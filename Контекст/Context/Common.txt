на работе планируют архитектура инф. системы.
руководство хочет такую архитектуру, в которой будет:
+ микросервисы на event-southing, общение через Kafka
+ процессы, реализованные на процессном движке типа camunda
+ озеро эталонных данных (не только справочники, а клиентские) как источник истины
+ интеграционная подсистема (для 30+ интеграций с гос.службами) с API, которое полностью закрывает на себя общение с внешним миром (т.е. от система просто говорит какие данные нужны, а API само определяет какие интеграции запускать, получает данные с ожиданием по временным лагам, парсит и отдает только чистые данные в нормализованном виде)

Есть : 
+ 3 ЦОДа в  1 городе, 
+ задержка (RTT) между ЦОДами - неизвестна
+ Используем Kubernetes
+ ожидается огромный объем данных (терабайты)
+ нагрузка неизвестна (говорят быть готовыми к высокой, но без каких-то аргументов и замеров)
+ Система должна работать без сбоев (24/7 не обсуждалось, но ожидания что работу будет беспрерывной)
