Мне нужно описать способ развертывания ПО для ИТ-ландшафта перед начало разработки.

+ Считаем, что уже есть:
    + 1 ЦОД
    + Система виртуализации (умеем создавать VM)
    + Про сеть не знаю ничего, это пока за рамками задачи
    + Список развертываемого ПО см. в папке \sample\ 

+ Требования к развертыванию:
    + На Dev должен быть такой же способ развертывания, что и на Prod для возможности воспроизвести ошибку. например:
        + Ошибка из-за вида инсталляции (на Prod все в кубере, а на Dev - на 1 VM по квикстарту)
            + Типа при накате обнновления что-то может отработать по-разному и т.д.
        + Ошибка из-за параллельной работы 2 под/нод (на Prod N-нод на разных нодах, а на Dev вообще нода с 1 инстансом)
        + Т.е. если на Prod - K8s-кластер из N-под на M-нодах, то на Dev тоже должнен быть именно K8s-кластер из 2 под на 2 нодах (просто берем минимум инстансев, чтобы просто была балансеровка нужного типа)
    + Отсюда требование: 
        + сначала спроектировать Prod-инсталляцию
        + потом Dev-инсталляцию, как упрощенный вариант
    + На Prod считать систему высоконагруженной с большим объемом данных (терабайты):
        + Нужно использовать все заложенные производителем возможности для маштабирования
    + Приоритет способа развертывания элементов подсистем:
        + Для stateless компанентов и небольших хранилищь (БД под настройки, сессии пользователей и т.д.)
            + K8s - по умолчанию
            + VM+Docker - если не поддерживается K8s
            + другой механизм виртуализации, если не поддерживается ни K8s, ни Docker
            + VM - если не поддерживается K8s
        + Для statefull компанентов или больших хранилищь (БД для хранения логов,метрик,аналитики,файлов,...)
            + Prod - физический сервер
            + Dev - виртуальный сервер

+ Что ожидаю на выходе:
    + К каждому файлу в папке \sample\ добавлено 2 инструкции:
        + Для Prod - контура
        + Для Dev - контура
    + Каждая инструкция содержит:
        + Схему инстансов икомпанентов в mermaid 
            + Пример: C:\_ii_\WORK-platform_companents\Out\Платформенная инфра\Kubernetes\Kubernetes.md
            + Схема также должна быть цветной.
            + У схемы должна быть такая же легенда для компанентов (прям точь-в-точь, только пояснение к цвету. Не нужно в легенде описывать назначение каждого элемента и т.д.)
            + На схеме должны быть выделнеы отдельные инстансы и указаны их аттрибуты:
                + Что это: 
                    + Пода: 
                        + K8s / Docker / - ? 
                        + На какой ноде поднят этот под?
                    + Нода:
                        + На какая нода? 
                        + Какая OS (Linux / МОС ОС / Ubuntu / ...)
            + На схеме не должно быть потоков, как в примере.
        + Комментарии к схеме
            + Какой функционал располагается на инстансе
            + Критически важные детали развертывания инстанса
