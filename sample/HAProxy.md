
Ресурсы:
+ Одна выделенная Linux-машина (amd64 или arm64) в закрытой сети; для отказоустойчивости нужны два независимых HAProxy в каждом ЦОДе, а VIP переносит отдельное ПО Keepalived/VRRP. [Официальный образ](https://hub.docker.com/_/haproxy), [модель отказоустойчивости](https://docs.haproxy.org/3.4/intro.html)
+ ПО: **HAProxy Community 3.4.3** (линия 3.4 LTS до Q2 2031) и Docker Engine актуальной поддерживаемой версии; минимальную версию Docker документация HAProxy не фиксирует. Не использовать `latest`. [Релизы HAProxy](https://www.haproxy.org/), [официальный образ и quickstart](https://hub.docker.com/_/haproxy)
+ ОС: Linux; для штатного мягкого reload нужно ядро **≥ 3.9**, а для запуска официального образа не от root на портах ниже 1024 — ядро **≥ 4.11** и соответствующий sysctl. [Management Guide](https://docs.haproxy.org/3.4/management.html), [официальный образ](https://hub.docker.com/_/haproxy)
+ Официальных минимумов RAM и HDD нет. Ориентир для небольшого закрытого стенда без нагрузки: **1 vCPU, 1 ГБ RAM, 5 ГБ локального диска** под конфигурацию и ротируемые журналы; вендор отмечает, что одного ядра хватает более чем 99% установок, но боевые CPU/RAM и `maxconn` определяются только нагрузочным тестом. Swap не использовать. [Sizing и ограничения](https://docs.haproxy.org/3.4/intro.html)
+ Заводских обязательных портов нет: HAProxy слушает только заданные в `bind`. Для платформы освободить **80/TCP** и **443/TCP** для HTTP(S), при проксировании Kubernetes API — **6443/TCP** только из административной сети; выбранный порт stats (например, **8404/TCP**) и выбранный порт `peers` доступны только внутри закрытой сети/между узлами пары. Нужен исходящий доступ к портам backend-сервисов; runtime API предпочтительно оставить Unix-сокетом без TCP-порта. [Конфигурация `bind`, stats и peers](https://docs.haproxy.org/3.4/configuration.html), [Runtime API](https://docs.haproxy.org/3.4/management.html)

Установка:
+ Использовать официальный quickstart контейнера: подготовить собственный `haproxy.cfg`, проверить его через `haproxy -c` и запустить фиксированный образ `haproxy:3.4.3` с конфигурацией, смонтированной только для чтения. Пошаговые команды и готовый боевой конфиг здесь намеренно не приводятся. [Официальный quickstart образа](https://hub.docker.com/_/haproxy), [проверка конфигурации и reload](https://docs.haproxy.org/3.4/management.html)
+ Один контейнер подходит только для учебного стенда: он не подтверждает отказоустойчивость, производительность TLS или переключение ЦОДа. [Архитектура и sizing](https://docs.haproxy.org/3.4/intro.html)

Подключение:
+ Клиенты обращаются к адресу/VIP HAProxy на настроенном frontend; HAProxy выбирает живой сервер из backend по health check. Для Kubernetes API используется TCP-вход **6443**, для веб-трафика — настроенные **80/443**. [Frontend, backend и health checks](https://docs.haproxy.org/3.4/configuration.html)
+ Встроенная stats-страница не имеет заводского порта и пароля: адрес и `stats auth` задаются в конфигурации; страницу и runtime API нельзя публиковать в интернет. [Stats page и аутентификация](https://docs.haproxy.org/3.4/configuration.html#4-stats%20auth), [Runtime API](https://docs.haproxy.org/3.4/management.html)
