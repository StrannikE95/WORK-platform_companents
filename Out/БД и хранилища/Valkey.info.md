# Valkey 9.1.1 — термины и сокращения

Словарь к файлу `Valkey.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в операционной системе: у неё есть память и открытые файлы. В Valkey это один серверный процесс на узел.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. RDB и AOF — снимок и журнал, не «вторая Cassandra». Рабочий набор ключей живёт в оперативной памяти.

**RAM** — оперативная память. Терабайты озера в Valkey не помещаются: влезает то, что в RAM всех primary, плюс запас на фрагментацию, буферы replica и `fork()` при снимке.

**TCP-порт** — номер, по которому другие программы находят этот процесс в сети. Клиенты и миграция ключей Cluster — **6379**; Cluster bus — **16379**; Sentinel — **26379**.

**ЦОД** — отдельная площадка с серверами (своё питание, своя сеть). Три ЦОДа в тексте — три независимые зоны отказа.

**RTT** — время туда-обратно по сети. Порога миллисекунд у проекта нет. Есть `cluster-node-timeout` (пример учебника кластера **5000** мс) и `down-after-milliseconds` Sentinel (в примере **60000**). Это не «можно 80 мс».

**TLS** — шифрование байтов в сети. В доке Valkey при включённом TLS по умолчанию **mTLS** клиентов. В Helm `tls.requireClientCertificate` дефолт **false** — ослабление относительно доки сервера.

**mTLS** — TLS, где проверяют сертификат и сервера, и клиента.

**fsync** — вызов ОС «запиши буфер на диск сейчас». Политика AOF `appendfsync` как раз про частоту этого сброса.

**fork()** — создание дочернего процесса для снимка. Persistence-дока: на больших снимках может задержать клиентов на миллисекунды–секунды. Запас RAM на primary часто считают как 2× на fork и фрагментацию.

**HA** — способность пережить отказ машины или процесса без ручного подъёма с нуля. Helm replication = копии, не смена primary при падении writer.

**RPO** — сколько уже подтверждённых данных готовы потерять. **RTO** — за сколько снова принимать запросы. Даже `WAIT` не даёт строгую консистентность.

**SoT (source of truth)** — место, которое считают правдой сущности. Эталон клиентов остаётся в озере/БД. Valkey — слой ускорения и координации, не слой истины.

**Под (Pod)** — единица запуска в Kubernetes. IP меняется; клиент не должен хардкодить DNS primary навсегда.

**StatefulSet** — объект Kubernetes с постоянным именем и диском на реплику.

**PVC** — заявка на том. **CSI** — плагин тома. Нужен **RWO** (том на одну ноду). **WaitForFirstConsumer** — том создаётся в зоне пода; replica не «переедет» в другой ЦОД со своим диском.

**emptyDir** — том, который гибнет вместе с подом. `replica.enabled` + emptyDir — сценарий «пустой primary после рестарта съел флот».

**cgroup** — лимит памяти/CPU контейнера. `maxmemory` ставят **ниже** лимита, с запасом на буферы replica, AOF rewrite и фрагментацию.

**OOMKill** — Kubernetes/ядро убило процесс из-за лимита памяти. Без потолка `maxmemory` запись интеграционного API встанет иначе: через OOM.

**NetworkPolicy** — кто может открыть TCP на 6379 / 16379 / 26379. Cluster bus без изоляции или mTLS: чужой узел может перехватить слоты.

**Anti-affinity / topology spread** — не класть primary и его replica (и все Sentinel) в одну зону. Иначе один ЦОД убивает шард насовсем.

**PDB (PodDisruptionBudget)** — сколько подов можно снять при drain (`maxUnavailable: 1` / `minAvailable`). Не защищает от падения ЦОДа.

**Helm / чарт** — шаблон манифестов. Официальный **`valkey-io/valkey-helm`**, чарт `valkey` **0.11.0**, `appVersion` **9.1.1**: standalone или primary + replicas. **Не** Cluster. **Не** Sentinel.

**PKI** — сертификаты для TLS клиентов, `tls-cluster` и `tls-replication`.

**CVE** — запись об ошибке безопасности. В 9.1.1 закрыты CVE-2026-56684 (RCE через TLS / `CLIENT KILL` у уже аутентифицированного клиента) и CVE-2026-63639 (RCE через повреждённый stream в RDB). Ставить 9.1.0 нельзя. Urgency релиза — **SECURITY**.

**RCE** — удалённый запуск кода в процессе сервера.

**ПДн / 152-ФЗ** — персональные данные и срок хранения. TTL не отменяет закон. Шифрование тома, ACL, сеть.

**ГОСТ / СКЗИ** — штатный TLS Valkey не является криптографией КИИ.

**LoadBalancer** — внешний адрес Kubernetes. 6379 в интернет без ACL — открытая память контура.

**Image tag `latest` / 9.1.0** — не пин. Прод: `valkey/valkey:9.1.1` (digest), свой registry.

**In-memory** — рабочий набор живёт в RAM. Диск (RDB/AOF) — снимок и журнал.

**Primary (ранее master)** — узел, который принимает записи. В репликации он один на набор данных.

**Replica** — копия primary. Читать можно, если готовы к отставанию. Писать на replica в штатной схеме нельзя. Service `valkey-read` в Helm — не writer.

**Асинхронная репликация** — primary отвечает клиенту OK, а потом досылает запись replica. Падение primary до досылки = потеря уже подтверждённой записи. Это модель, не баг.

**`WAIT`** — команда «подожди, пока N replica подтвердят». Снижает шанс потери, не даёт строгую консистентность (прямо сказано в cluster tutorial).

**Sentinel** — отдельные процессы: следят за primary/replica, выбирают новый primary, говорят клиентам новый адрес. Нужны, когда нет Cluster. Порт **26379**. В официальный Helm-чарт `valkey` **не входит** — ставят отдельными манифестами по `sentinel.conf` из дистрибутива.

**Кворум Sentinel** — сколько Sentinel должны согласиться, что primary мёртв, чтобы начать failover. Чтобы **выполнить** failover, нужна ещё **majority** всех Sentinel. Два Sentinel вендор показывает как *DON'T DO THIS*. Для 3 узлов quorum в `sentinel monitor` обычно **2**.

**`SENTINEL CKQUORUM`** — проверка, что кворум Sentinel ещё способен провести failover. Кладут в мониторинг.

**`sentinel.conf`** — конфиг Sentinel. Файл должен быть writable, иначе процесс не стартует.

**`down-after-milliseconds`** — таймаут «primary мёртв» у Sentinel. Пример 60 с терпимее к короткой тряске, чем 5000 мс Cluster, но это не «можно любой RTT».

**Valkey Cluster** — шардирование: данные режутся на **16384 hash slot** по нескольким primary. HA шарда = replica этого primary. Sentinel с Cluster не сочетают. Минимум **три** primary. Для прода вендор настоятельно рекомендует **шесть** узлов (3 primary + 3 replica). Cluster из двух primary нет.

**Hash slot** — корзина ключа: `CRC16(key) mod 16384`. Ключ живёт на одном primary. Порядок величины масштаба в spec — ~1000 узлов.

**Hash tag `{…}`** — кусок ключа в фигурных скобках: `user:{123}:a` и `user:{123}:b` попадут в один слот. Нужно для MULTI/Lua на нескольких ключах.

**MULTI / Lua** — пачка команд или скрипт на нескольких ключах. В Cluster — только внутри одного слота.

**Cluster bus** — внутренний канал нода↔нода. Порт по умолчанию клиентский + 10000 (6379 → **16379**). Клиентам туда нельзя. По умолчанию **без** прикладной аутентификации: кто дотянулся до порта, тому кластер верит. Закрывают сетью или `tls-cluster yes`.

**`cluster-node-timeout`** — сколько миллисекунд нода может не отвечать, прежде чем её сочтут мёртвой. Дефолт в учебнике кластера: **5000**. Primary, который не видит majority других primary столько же времени, перестаёт принимать запросы.

**`cluster-require-full-coverage`** — по умолчанию **yes**: если часть слотов никому не принадлежит, кластер не принимает записи. `no` — пусть лучше дырявый кэш (компромисс доступности).

**RDB** — снимок всего датасета в файл. Быстрый рестарт, удобный бэкап. Между снимками можно потерять минуты (зависит от `save`).

**AOF** — журнал каждой записи. Политика `everysec` (дефолт смысла AOF): потерять можно около 1 секунды. `always` — очень медленно. Вендор для важных данных советует **оба** (AOF+RDB); AOF-only не советует. В минимальном примере Cluster — `appendonly yes`.

**`appendfsync`** — как часто AOF сбрасывать на диск: `always` / `everysec` / `no`.

**Persistence off** — чистый кэш без диска. Репликация без persistence на primary + авторестарт = классический способ обнулить и primary, и все replica. Вендор это отдельно запрещает. Sentinel эту гонку не лечит, если primary успевает подняться раньше детекта. На Kubernetes kubelet почти всегда рестартит под — «кэш без диска» конфликтует с безопасностью репликации.

**`maxmemory` / `maxmemory-policy`** — потолок RAM и что выкидывать, когда он достигнут. Дефолт политики: **`noeviction`** (новые записи начинают получать ошибку). Для кэша обычно `allkeys-lru` и т.п. — это решение, не дефолт. С `noeviction` при заполнении встанет запись интеграционного API.

**`volatile-*`** — политики вытеснения только ключей с TTL. Для замков/сессий, которые нельзя вытеснить: отдельный инстанс или только такие ключи.

**ACL** — пользователи и права на команды/ключи. `requirepass` — совместимость со старым Redis; с `aclfile` / `ACL LOAD` он **игнорируется**. Helm + `auth.enabled`: обязателен пользователь `default` в ACL, иначе (цитата чарта) зайти можно без учётных данных.

**`requirepass`** — старый один пароль. Не мешать с `aclfile`.

**Protected mode** — если у `default` нет пароля — слушать только localhost. В Docker/K8s его часто выключают, подставив bind 0.0.0.0 — тогда без ACL инстанс открыт всей сети пода. В `valkey.conf`: `bind 127.0.0.1 -::1`, `protected-mode yes`.

**`min-replicas-to-write` / `min-replicas-max-lag`** — primary перестаёт писать, если живых replica с лагом ≤ порога меньше N. Дефолт **0** (выкл.). Это не гарантия, что replica запись приняла, а сужение окна потери. Пример Helm/conf: `min-replicas-to-write 1`, `min-replicas-max-lag 10`. Дефолт Helm 0.11.0: `minReplicasToWrite: 0`.

**Failover** — смена primary. Пока идёт — записи (и иногда чтения шарда) коротко падают. Клиент должен уметь retry и обновлять топологию / слот-карту.

**Split-brain / minority** — клиент остался с меньшинством узлов и ещё пишет в «старый» primary, пока majority не выберет нового. Потом эти записи выбрасываются. Окно ≈ `cluster-node-timeout` (Cluster) или `down-after-milliseconds` (Sentinel).

**IO threads (`io-threads`)** — часть сетевой работы не на одном ядре. Команды по-прежнему в основном на главном потоке. Больше CPU ≠ линейный QPS без замера.

**QPS** — запросов в секунду. Официального «N ядер на интеграционный сервис» нет.

**Stretch** — один логический Cluster/Sentinel-набор, узлы физически в разных ЦОДах. Общаются по 6379/16379/26379.

**Standalone** — один процесс. Запись только вертикаль RAM/CPU. Автоfailover нет. Цель теста, не трёх ЦОДов.

**Replication (1 primary + N replica)** — копия данных и чтение с replica. Запись не горизонталится. Автосмены primary нет, пока нет Sentinel (или ручного `REPLICAOF` / Cluster).

**`REPLICAOF`** — команда «стань копией этого primary». Ручной failover, не HA.

**TTL** — срок жизни ключа. В Valkey кладут TTL-данные, которые можно пересчитать, не «всех клиентов навсегда».

**FLUSHALL / CONFIG** — команды стереть датасет / сменить конфиг. Опаснее, чем «просто кэш». `rename-command` может спрятать их — это hardening, не замена ACL. Один админский ACL на все поды CI — способ стереть прод.

**Cluster-aware клиент / `valkey-cli -c`** — клиент, который понимает слоты. Обычный TCP на один Service не переживает смену primary и не попадает в нужный слот.

**NAT / Docker port-mapping** — Cluster: *does not support NATted environments*; для Docker — `--net=host`. Sentinel: remap портов ломает discovery. В Kubernetes — ClusterIP/headless на Pod IP / announce, не NodePort «как у веб-приложения».

**`valkey-operator`** — официальный оператор Cluster (`valkey-io/valkey-operator`, релизы до v0.5.0). README: in active development and **not ready for production use**, API `v1alpha1` может сломаться. На нём платформу не строят.

**Bitnami и сторонние чарты Cluster** — не проект Valkey; в файле не целевой путь.

**BSD-3** — лицензия форка под Linux Foundation. Это не Redis Stack / Redis Enterprise и не смена лицензии Redis Ltd. 2024 года.

**oliver006/redis_exporter** — экспортёр метрик Prometheus в официальном Helm. К Valkey ходит с auth, не анонимный 6379 «для scrape».

**Pub/Sub в Cluster** — идёт через bus. Это не Kafka: нет долгого лога, порядка и replay как у топика.

**Camunda / BPMN** — процессный движок. Valkey может держать кэш/лок рядом, не исполнять процесс.

**NTP / часы** — лаг replica считается по ping/ack. Часы должны быть относительно нормальные.

**`cluster_state`** — жив ли Cluster (принимает ли запросы). Сигнал мониторинга вместе с `used_memory`, evicted keys, `connected_replicas`, replication offset/lag, очередью клиентов, latency `INFO`.

**`--cluster-replicas 1`** — старт Cluster на 6 узлах по tutorial: у каждого primary одна replica.

**`tls-cluster` / `tls-replication`** — TLS на bus и на канале primary→replica. Sentinel наследует сеть.

**replication-user** — отдельный ACL для репликации. Минимум из Helm README: `+psync +replconf +ping`. Приложениям не дают `+@all` у `default`.

**Service `valkey` в Helm** — writer (primary). После появления replica запись на read-сервис будет ошибкой.

**Helm 0.11.0 по умолчанию** — нет persistence на standalone, replica выключены, `minReplicasToWrite: 0`, auth выкл., TLS выкл. Это стенд, не capacity plan. Persistence в режиме replication **обязательна**.

**`initSysctl`** — правка sysctl из чарта. Для Valkey в файле не нужен (это не Elasticsearch).

**Mesh 16379** — полная связность нод Cluster. Оба порта Cluster обязательны, иначе кластер «не работает как ожидается» (цитата tutorial).

**Бэкап** — RDB на сторону (S3/лента), отдельный процесс. Replica ≠ backup: `FLUSHALL`, кривой ACL, пустой primary после рестарта replica повторит.

**DR** — восстановление с снимка на другой площадке. Три независимых Valkey в трёх Kubernetes без общего кворума = три кэша и три правды сессий.

**Vault / Secret** — ACL и пароли. Не Git.

**Jump / контролируемый вход** — люди в прод не ходят общим `default`.

**hostNetwork / announce** — объявить стабильный адрес пода, если overlay врёт. Не Docker NAT.

**QPS / нагрузка** — неизвестны; цифры «N GiB `maxmemory`» в файле нет.

**Fragmentation** — дырки в куче аллокатора: занятая RAM больше размера ключей. Запас к `maxmemory` учитывает и это.

**Evicted keys** — счётчик вытесненных ключей. Для кэша норма при LRU; для замков — инцидент.

**Rate-limit / distributed lock / идемпотентность** — типичные ключи: лимит вызовов, короткий замок, ключ «этот запрос уже делали». Если ключ должен пережить падение ЦОДа без потери — его место в БД/озере.

Источники формулировок: глоссарий и тело `Valkey.md`. Новых порогов RTT и размеров RAM здесь нет.
