# OpenStack Swift 2.37.3 — термины и сокращения

Словарь к файлу `OpenStack Swift.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа. У Swift это proxy, object/container/account server и фоновые replicator, updater, auditor (для erasure coding — ещё reconstructor).

**Файл / каталог на диске** — объект на object-server лежит файлом; метаданные — в расширенных атрибутах ФС. Точки монтирования `/srv/node/…` от root (`root:root 755`), иначе при размонтировании диска rsync может писать в корневой том.

**TCP-порт** — вход в сети. Proxy (Swift API и при включении S3) — **8080**; object server — **6200**; container — **6201**; account — **6202**; rsync — **873**; Memcached — **11211**. Клиентам открывают только proxy (лучше 443 на LB → 8080).

**ЦОД** — площадка с независимым питанием, сетью, зданием. Три зала с общим UPS — не три домена отказа.

**RTT** — время туда-обратно. Порога миллисекунд у проекта нет. Default задуман как один region с высокой полосой и низкой задержкой. Мерить PUT/GET и rsync на 6200–6202, не ping ICMP.

**TLS** — шифрование канала на входе proxy/LB. ГОСТ/СКЗИ vanilla Swift не закрывает. Имя бакета во virtual-host — отдельный SAN/wildcard в сертификате.

**HA** — несколько копий в кольце плюс несколько stateless proxy за балансировщиком плюс фон replicator/auditor. SAIO на одной машине HA не является.

**RPO** — сколько данных готовы потерять. **RTO** — за сколько восстановиться. Успешный PUT при 2 из 3 дисков ≠ «файл уже в двух других ЦОДах», если включён write_affinity. Реплики Swift — не бэкап от `DELETE` контейнера и не бэкап `.builder`.

**SoT** — правда сущности. JSON-файлы клиентов в бакете SoT не являются: listing отстаёт, overwrite без транзакции, поиск по полям строите рядом.

**Под (Pod)** — единица Kubernetes. Кольцо содержит IP:порт/имя диска: смена IP пода без обновления кольца ломает кластер.

**DaemonSet / Deployment** — object/container/account: выделенные ноды, hostNetwork или стабильный IP в кольце, локальный диск. Proxy — Deployment/DaemonSet за Service/HAProxy: stateless, кольцо только читают.

**PVC / emptyDir / NFS** — том Kubernetes / одноразовый каталог / сетевая ФС. Диск object-server — локальный XFS, не emptyDir и не общий NFS.

**hostNetwork** — под слушает сеть хоста, чтобы IP в кольце не прыгал.

**NetworkPolicy / firewall** — proxy→storage, storage↔storage rsync, proxy→Keystone/memcached. 6200–6202 и 873 — внутренняя сеть. Выдать object-server в интернет = обойти auth proxy.

**Anti-affinity / PDB** — несколько proxy в каждом ЦОДе, не все в одной зоне.

**Helm / OpenStack-Helm** — чарт OpenStack, не ядро Swift. Матрица 2026.1: Kubernetes **≥ 1.33 и ≤ 1.35**. В платформе зафиксирован **Kubernetes 1.36.4** — не доказанная комбинация.

**Kolla-Ansible** — установщик OpenStack. Роль Swift **убрана с 2025.1**. Не планировать.

**PKI** — сертификаты входа. Root-секрет шифрования и S3-ключи не живут в git.

**CVE** — дыры S3 и proxy. 2.37.2 / 2.37.3 закрывают в том числе CVE-2026-71190 (DoS через `Accept`), CVE-2026-71191 / 71192 (копирование через S3-заголовки), CVE-2026-50221 (SSRF через container-update), CVE-2026-49017 (DoS aws-chunked). Не ставить Swift 2.29 с GeoData-инсталлятора как платформенный S3 без решения по патчам.

**SSRF** — сервер ходит по URL, который подсунул клиент. Здесь — через заголовки container-update.

**ПДн / 152-ФЗ / КИИ** — имена объектов at-rest middleware **не** шифрует. ПДн в ключе и в listing — вопрос ИБ.

**Apache 2.0** — лицензия исходников Swift. License-server нет. Следить за обвязкой (Keystone, образы дистрибутива).

**Объектное хранилище** — кладёте файл (объект) по имени в контейнер/бакет. Нет SQL, нет строк и индексов как в Postgres. Читаете и пишете целиком или кусками multipart.

**Account** — верхний уровень Swift API: пространство имён контейнеров. В связке с Keystone это обычно проект/tenant.

**Container** — пространство имён объектов внутри account (в S3 это bucket). Список объектов живёт отдельно от самих файлов (SQLite на container-серверах).

**Object** — сам блоб + метаданные. На диске — файл; метаданные — в **xattr**.

**Swift API** — родной REST: `/v1/{account}/{container}/{object}`. Это не S3.

**s3api** — middleware на proxy: принимает запросы «как Amazon S3» и переводит их во внутренности Swift. Эмуляция, не AWS. Включаете на том же proxy, не вторым кластером.

**s3token** — middleware: проверяет S3-подпись (access key / secret) через Keystone. Нужен, если S3 + Keystone. Зависит от версии Keystone (в 2.37.0 чинили >25.0.0).

**tempauth** — встроенная учётка в конфиге для лаборатории (SAIO). Пароли в `proxy-server.conf`. Для прода не identity.

**Keystone** — Identity OpenStack: пользователи, проекты, роли, каталог сервисов. Для прода S3 обычно берут EC2-credentials из Keystone. Умер Keystone — новые сессии и S3-подпись через s3token не пройти. Это SPOF доступа, не SPOF байт на диске.

**EC2-credentials** — пара access key / secret в модели S3, которую выдаёт Keystone.

**Proxy server** — единственная точка входа для клиентов. Смотрит в ring, куда послать запрос, стримит данные, не складывает объект целиком на диск proxy (не spool). Stateless: несколько proxy за балансировщиком — штатный HA. Падение всех proxy — кластер глухой, диски целы. На proxy pipeline: auth, s3api, encryption.

**Object / Container / Account server** — три внутренних сервиса хранения. Клиенту они не нужны; proxy ходит к ним сам. Object — файлы; container — listing и счётчики (SQLite); account — listing контейнеров.

**Ring (кольцо)** — словарь «имя сущности → на каких дисках лежат копии». Отдельные кольца: account, container, и по одному object-кольцу на storage policy. Без одинаковых `.ring.gz` на всех нодах кластер врёт: «пишу не туда» / 404 на живых данных. Кольца не масштабируются подами: меняются `rebalance` и выкладкой `.ring.gz` на все ноды.

**`.builder`** — исходник кольца. Его бэкапят. Потеряли builder — следующее изменение топологии станет лотереей. Ошибка кольца бьёт сильнее падения одной ноды. Пересобрали кольцо «с нуля» — карта уничтожена, файлы на дисках кластер не найдёт как раньше.

**Partition (в кольце)** — не раздел HDD. Виртуальный кусок пространства имён. Replica раскладываются по партициям. Рекомендация вендора: **≥ 100 партиций на диск**, число партиций = 2^part_power. part_power — от прогноза максимума дисков, не от «сейчас купили три HDD».

**Replica** — сколько копий каждой партиции. В Deployment Guide рекомендуется **3** — «это единственное значение, которое тестировали». 3 копии ≈ диск ×3 относительно одного экземпляра файла. Меньше 3 на проде = вы сами испытательный стенд проекта.

**Handoff** — запасной диск/узел из кольца, куда proxy отправит запись, если primary недоступен. Потом replicator догонит «правильное» место.

**Кворум записи proxy** — успех клиенту завязан на большинство успешных бэкенд-записей (`quorum_size` = replica//2+1, для 3 это **2**). Цифру 2 из 3 вендор в Deployment Guide отдельной главой не печает — печает «ставьте 3 replica». Это не Raft-лидер кольца.

**Region / Zone** — иерархия доменов отказа в кольце: region → zone → сервер → диск. Region — обычно площадка с другой задержкой; zone — изоляция внутри (зал, ряд, питание, сеть). Оба — положительные целые, смысл задаёте вы. «Минимум 5 zone» в гайде — оптимум тестов изоляции внутри region, не приказ нарезать 5 ЦОДов. При трёх ЦОДах: 3 zone = ЦОД (изоляция копии) + достаточно серверов/дисков внутри. Не жертвовать «1 копия = 1 ЦОД» ради цифры 5. Стойки — уровень server, либо дополнительные zone только после проверки dispersion.

**Storage policy** — именованный класс хранения контейнера (например «3 копии» и отдельно erasure coding). Политика задаётся при создании контейнера и на жизни контейнера не меняется.

**Erasure coding (EC)** — вместо N полных копий — кодирование с избыточностью (меньше места, больше CPU на proxy при encode/decode). Восстановление — **reconstructor**, не тот же путь, что rsync-репликатор. Вторая policy на новый контейнер, не ломая default 3×.

**Eventual consistency** — объект после успешного PUT обычно уже читается по имени. Список контейнера/аккаунта может отстать: обновление listing могло уйти в очередь updater.

**Last write wins** — конфликт версий объекта на диске решается временной меткой. Удаление — это тоже версия (tombstone, файл `.ts`).

**Replicator** — фоновый процесс: догоняет копии (часто через rsync для объектов), разносит tombstone. Ему нужны сеть репликации, I/O и время. rsync терабайтов по той же сети, что PUT клиентов, душит API.

**Updater** — догоняет отложенные обновления listing контейнера/аккаунта. Окно рассинхрона listing ≈ как часто он бегает и насколько бэкенд был занят.

**Auditor** — ползёт по локальным дискам, ищет битый файл (bit rot), кладёт в quarantine; replicator подтянет живую копию.

**SAIO** — Swift All In One: всё на одной машине, официальный путь разработки/теста, не прод. Несколько object/container/account на портах вроде 6210/6220 — лабораторная схема localhost.

**min_part_hours** — сколько часов нельзя повторно двигать одну и ту же партицию при rebalance. В гайде как ориентир — **24**. Пример создания: `create <part_power> 3 24`.

**Weight** — вес диска в кольце (доля партиций). Ориентир гайда: **100.0 × ТБ** ёмкости. «Все weight=1» на дисках разного размера = одни тома лопнут раньше.

**write_affinity / read_affinity** — «пиши/читай сначала рядом» (свой region/zone). Официальный механизм global cluster. Письмо локально ускоряет PUT, но сразу после записи копии могут ещё не лежать в чужом ЦОДе. Документация: имеет смысл, если не читаете объект сразу после записи в другом регионе; типичный пример — бэкапы. Если ingest быстрее вывоза — affinity выключают. По умолчанию выключен.

**SLO / DLO** — большие объекты кусками. По умолчанию один PUT ≤ **5 ГБ**; больше — сегменты + манифест. SLO не зависит от eventual listing; DLO — зависит. Для полной S3-совместимости multipart в pipeline должен быть **slo**.

**xattr** — расширенные атрибуты файла в ФС. Без них object-server не хранит метаданные штатно. Поэтому диск Swift — не любой NFS на скорую руку. Практический стандарт — **XFS**.

**Memcached** — кэш токенов и фактов «контейнер существует», не кэш тел объектов. Обычно на proxy; в `memcache_servers` перечисляют все инстансы. Для tempauth токен живёт в memcached: упал memcached — «не пускает». Для Keystone промах кэша = повторный поход в Keystone.

**Barbican / keymaster** — ключи шифрования at-rest: секрет в конфиге (`keymaster`) или внешний KMS (`kms_keymaster` / `kmip_keymaster`). Root-секрет keymaster: ≥ **44** символа base64, одинаковый на всех proxy. В проде — Barbican/KMIP, не `changeme` в git. Шифруется тело, ETag ненулевых объектов, значения пользовательских `X-Object-Meta-*`. Не шифруются имена account/container/object, имена метаданных, Content-Type, размер, системные метаданные. Это защита от унесённого диска, не от того, кто сел на внутреннюю сеть или украл root-секрет.

**swift-recon** — снятие телеметрии с нод: кольца, время репликации, quarantine, async pending.

**rsync** — копирование файлов между storage-нодами. Без него object-replicator не сходится штатным путём. Модули в `rsyncd.conf`.

**S3 bucket / path-style / virtual-hosted** — имя контейнера в пути или в Host. На первый контракт path-style (меньше сюрпризов с TLS). Virtual-hosted — только если сознательно настроили.

**Матрица `s3_compat`** — что из AWS S3 есть. Core PUT/GET/DELETE, multipart, ACL, versioning — да. Нет: bucket lifecycle, bucket policy, object tagging, notifications, website hosting, billing, inventory, accelerate. Срок жизни объектов — нативный object expiration Swift, не S3 Lifecycle API.

**`s3_acl` / `check_bucket_owner`** — совместимость ACL бакета. Дефолт `s3_acl` в проекте исторически `False`; часть CVE-2026-71191 завязана на этот дефолт. SAIO включает оба. Выбор проверить клиентами.

**Pipeline** — цепочка middleware на proxy. Для Keystone рекомендованный пример: `authtoken` → `s3api` → `s3token` → `keystoneauth`, у authtoken `delay_auth_decision = True` (иначе двойной поход в Keystone). Для заявленной S3-совместимости ещё **bulk** и **slo**. Порядок сверять с `proxy-server.conf-sample` той же 2.37.3. Типичный смысл прода: catch_errors / gatekeeper / healthcheck / cache / authtoken / s3api / s3token / keystoneauth / квоты / bulk / slo / (keymaster encryption) / proxy-server. `s3api` перед auth.

**Container sharding** — нарезка listing огромного контейнера. Отдельная операторская дисциплина при миллионах объектов в одном контейнере.

**Rebalance** — пересчёт кольца и движение партиций. Все изменения устройств — пакетом, потом один rebalance (гайд: меньше двигается данных). Не забивать диски вплотную — некуда двигать партиции. Не менять part_power «внезапно».

**Dispersion** — насколько кольцо реально разнесло копии по zone/серверам. Проверяют `swift-ring-builder`, не верят «нарезали zone по стойкам».

**`servers_per_port`** — свой порт object-server на диск, не все диски ноды на одном 6200.

**RAID** — вендор: RAID не требуется и не рекомендуется; паттерн I/O для RAID 5/6 — худший случай. Надёжность — replica в кольце + auditor. Диск умер — кольцо и replicator, не контроллер RAID.

**SPOF** — единственная точка отказа. Один proxy = SPOF API, даже если диски в трёх ЦОДах живы. Слабый Keystone = «хранилище живо, никто не входит».

**HAProxy / LB** — балансировщик перед несколькими proxy. TLS часто снимают на LB: SSL на proxy дороже CPU.

**QPS** — запросов API в секунду. Рост: больше proxy (CPU/сеть). Больше гигабайт — больше дисков в object-кольце, вес пропорционален ТБ, затем rebalance. Не «увеличить PVC одного пода». Нагрузки нет — нет цифры «N дисков и M ТБ».

**Global cluster** — несколько region с read_affinity/write_affinity. Официальный текст писался вокруг двух регионов с тремя zone в каждом. Три region — обобщение, не дословный пример.

**Container sync** — штатный мост между независимыми кластерами. Не «один бакет на три endpoint». Три кольца, другой RPO.

**Квоты (`account_quotas` / container quotas)** — потолок места. Без них озеро съест диски молча.

**Python 3 / 3.14 GIL enabled** — в 2.37.1 добавлена поддержка Python 3.14 (GIL enabled). Минимальную minor «навсегда» файл не фиксирует — смотреть пакет/дистрибутив 2.37.3.

**StatsD / Prometheus-exporter** — как снимете метрики. Labeled metrics API swift vs S3 есть в 2.37.0.

**GeoData Swift 2.29.2** — инсталлятор вендора GeoData, пример колец в одном region/zone. Склеивать с платформенным 2.37.3 без письма вендора нельзя.

**OpenStack 2026.1 (Gazpacho)** — серия; Swift **2.37.3** — последний номер линейки на дату документа. **2.38.x** в current/unreleased — не стабильная серия.

**Клиентское шифрование до PUT** — plaintext не светился на проводе до proxy. Единственный способ, который закрывает канал до входа.

**Least privilege S3** — отдельные EC2-keys на сервис; свой account/container; ротация. Нет общего ключа «на все микросервисы». Нет tempauth в проде.

**path PUT/GET vs listing** — успех по имени объекта не значит, что listing контейнера уже догнал. Контракт приложения: идемпотентный PUT, ключи объектов, что делать с listing, multipart для крупных тел.

**Вариант A/B/C/D** — один кластер, один region, три zone=ЦОД, replica=3; global cluster 3 region; три независимых кластера; мозг в одном ЦОДе. Пока RTT не измерен, A — гипотеза. Цель отказа: пережить 1 ЦОД, не 2 из 3 (при replica=3 и раскладке по ЦОДам два мёртвых ЦОДа оставляют одну копию).

Источники формулировок: глоссарий и тело `OpenStack Swift.md`. Новых порогов RTT и размеров диска здесь нет.
