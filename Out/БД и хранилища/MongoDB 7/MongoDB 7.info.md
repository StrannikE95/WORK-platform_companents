# MongoDB Community Server 7.0.40 — термины и сокращения

Словарь к файлу `MongoDB 7.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в ОС. «Нода» replica set или шард — это процесс `mongod`. Роутер шардов — процесс `mongos`.

**Файл / каталог на диске** — `dbPath`: файлы WiredTiger, журнал, логи. После рестарта данные поднимаются с этого каталога.

**TCP-порт** — номер входа в сети. Клиенты и члены обычного replica set / `mongos` — **27017**; дефолт члена шарда (`--shardsvr`) — **27018**; config server (`--configsvr`) — **27019**. UDP нет.

**ЦОД** — отдельная площадка с серверами. Три ЦОДа — три независимые зоны отказа, не три зала с общим питанием или SAN.

**RTT** — время туда-обратно по сети. Порога миллисекунд у MongoDB нет. Есть `electionTimeoutMillis` (дефолт **10000**) и heartbeat **2 с** (2000 мс). Это не «можно 80 мс».

**TLS** — шифрование канала клиент↔`mongod` и `mongod`↔`mongod`. В дефолте нет. Без TLS пароль SCRAM всё ещё едет по сети.

**HA** — пережить отказ машины/процесса без подъёма с нуля. Standalone вендор считает не архитектурой прода. Три пода — три копии одного primary, не масштаб записи.

**RPO** — сколько уже подтверждённых данных готовы потерять. **RTO** — за сколько снова принимать запросы. Живой primary и `w: majority` ≠ «ни один документ не потерян при dual-DC». Формального SLA в файле нет.

**SoT (source of truth)** — место правды сущности. Роль «озеро эталона» за Mongo в исходном ТЗ не закреплена. Если закрепят — бэкап, PII, шарды и запрет secondary как SoT-чтения обязательны.

**Под (Pod)** — единица запуска в Kubernetes. IP меняется; клиент ходит по replica set URI или списку `mongos`, не на один вечный IP primary.

**StatefulSet** — объект с постоянным именем и диском. Deployment с ephemeral диском для `mongod` не подходит.

**PVC / CSI** — заявка на том и плагин диска. RWO на каждый data-bearing `mongod`. `emptyDir` в проде = каждый рестарт как новая нода (initial sync) или потеря standalone.

**NFS** — сетевая ФС. Формально допустим, если POSIX; вендор предупреждает: обычно медленнее. Не строить прод на NFS «потому что PVC так проще».

**cgroup** — лимит памяти/CPU контейнера. В Kubernetes лимит пода ≠ RAM хоста.

**OOM** — убийство процесса из-за памяти. Без явного `cacheSizeGB` процесс считает RAM хоста и съедает лимит пода.

**NetworkPolicy** — кто может открыть 27017/27018/27019. Балансировщик «как у HTTP на все 27017» перед replica set ломает модель: клиент должен знать состав набора.

**Anti-affinity / topology spread** — voting members в разных зонах по схеме 1-1-1 или 2-2-1. Не два voting в одной зоне «случайно».

**PDB (PodDisruptionBudget)** — не эвакуировать 2 из 3 PSS одновременно (не снять majority).

**Helm / чарт** — шаблон манифестов. Совместимость конкретного Helm-тега с MCK 1.10.0 сверять; прогон на стенде обязателен.

**CR (Custom Resource)** — объект API Kubernetes вашего типа. **`MongoDBCommunity`** — CR Community: официально тип только `ReplicaSet`. Не шарды.

**Оператор Kubernetes** — контроллер, который приводит процессы к описанному виду. Актуальный: **MCK**. Старый Community Operator — EOL (best-effort до ноября 2025): не начинать с него.

**PKI** — сертификаты для TLS клиентов и кластера; для replica set ещё keyfile или X.509 между членами.

**CVE / Critical Advisories** — закрытые дыры линейки. Патчи младше 7.0.40, особенно 7.0.0–7.0.15, в прод не ставят. Пинить полный тег `7.0.40-ubi9-slim`, не `7.0` и не `latest`. Changelog 7.0.41 без Release Notes / образа — не ставить.

**EOL** — конец поддержки линии. 7.0 (on-prem / Enterprise Advanced и Atlas Dedicated): **31 августа 2027**.

**SSPL** — лицензия сервера (Server Side Public License). Это не BSD/Apache. Если отдаёте MongoDB как сервис третьим лицам, требования жёсткие; закрытый внутренний контур — решение юристов, не админа. Оператор MCK — Apache 2.0; лицензия сервера от этого не меняется.

**ПДн / 152-ФЗ / PII** — персональные данные. Индексы и бэкапы тоже ПДн. Community без native at-rest и без аудита — ИБ принимает компенсирующие меры явно.

**ГОСТ / СКЗИ** — штатный TLS OpenSSL/библиотека ОС, не криптография КИИ.

**Документ / коллекция / БД** — запись JSON-подобного BSON; набор таких записей; пространство имён. Не таблица SQL 1:1: схема гибкая, индексы проектируете сами.

**BSON** — бинарный формат документа. Лимит одного документа — **16 МБ**. Больше — GridFS или другое хранилище, не «увеличить лимит». `net.wireObjectCheck` (дефолт) проверяет, что BSON валидный.

**GridFS** — нарезка файла крупнее 16 МБ на несколько документов. Отдельный механизм, не снятие лимита документа.

**`mongod`** — процесс СУБД.

**`mongos`** — роутер шардированного кластера. Клиенты ходят сюда, не на шарды напрямую. Stateless: сам данные не хранит. В проде несколько экземпляров; если перед ними прокси — client affinity на соединение.

**Standalone** — один `mongod` без replica set. Для прода вендор считает это не архитектурой. Change streams на standalone нет.

**Replica set** — несколько `mongod` с одним набором данных: один primary (пишет), остальные secondary (копируют oplog). Это HA и копии, не горизонтальный масштаб записи. С 3.6 шард должен быть replica set.

**Primary / Secondary** — кто принимает запись / кто держит копию. Secondary может стать primary на выборах.

**Oplog** — журнал операций replica set (capped collection — коллекция с потолком размера, старое вытесняется). Secondary догоняет primary по oplog. Если отстал дальше окна oplog — только **initial sync**. Терабайты + маленький oplog = initial sync в худший момент.

**Выборы (election)** — secondary объявляет себя primary, если старый primary не отвечает дольше `electionTimeoutMillis`. Нужно большинство голосов. Ориентир вендора при дефолтах: медиана до нового primary обычно не больше ~12 с, плюс влияние вашей сети.

**Кворум / majority** — большинство голосующих членов. 3 члена → 2. Без majority нет primary → нет записи. Чтение с оставшегося secondary возможно, это уже не полноценный кластер.

**Arbiter** — голос без копии данных. Дешёвый кворум. В тройке PSA даёт известные проблемы с `w: majority`. Вендор: не ставить больше одного arbiter.

**PSA / PSS** — Primary–Secondary–Arbiter / Primary–Secondary–Secondary. Для прода с `w: majority` берут **PSS**, не PSA. Неявный default write concern для PSA (2 data + 1 arbiter) — `{ w: 1 }`, не majority.

**Голос / priority** — `votes` — участвует ли в кворуме. `priority` — насколько охотно станет primary. `priority: 0` — никогда не primary (скрытая копия, отчётность, другой ЦОД «только копия»). Не ставить чужим `priority: 0`, если они должны уметь стать primary.

**Hidden / delayed** — Hidden не светится клиентам как readable. Delayed отстаёт на N секунд — откат ошибочного `drop` во времени, не HA.

**Write concern (`w`)** — сколько копий должны подтвердить запись, прежде чем клиент получит OK. `{ w: 1 }` — только primary. `{ w: "majority" }` — большинство data-bearing voting. Дефолт majority, если нет arbiter-ловушки.

**`wtimeout`** — сколько ждать write concern. Без него клиент может ждать бесконечно, если majority недоступен. Дефолтом `wtimeout` не спасает.

**Read concern** — насколько «подтверждённую» копию читать. `"local"` — что есть на этом узле. `"majority"` — то, что уже на majority.

**Read preference** — на кого слать чтение: `primary` (дефолт), `secondary`, `secondaryPreferred`. Secondary может отстать. Вендор прямо: replica set не для того, чтобы сваливать чтение на secondary по умолчанию.

**Rollback** — после смены primary записи, которые не дошли до majority, на старом primary откатываются. `w: 1` это допускает.

**Journaling** — журнал на диск до применения (WAL: сначала факт изменения на диск, потом страницы данных). Включено по умолчанию. `w: "majority"` по умолчанию ждёт journal (`writeConcernMajorityJournalDefault: true`). Не выключать.

**WiredTiger** — единственный storage engine Community 7.0 (MMAPv1 давно убран). Данные на диске сжаты (дефолт коллекций — **snappy**), во внутреннем кэше — разжаты. zstd — лучше степень сжатия, другой CPU.

**WiredTiger cache** — RAM движка. Дефолт: большее из `50% × (RAM − 1 ГБ)` и **256 МБ**. В контейнере обязан быть задан явно (`storage.wiredTiger.engineConfig.cacheSizeGB` / `wiredTigerCacheSizeGB`) **ниже** лимита cgroup: иначе процесс считает RAM хоста. Не увеличивать выше дефолта без причины.

**Initial sync** — новая/отставшая нода копирует все данные с донора. Для терабайт — часы/сутки и нагрузка на донора. Это не рестарт пода.

**Шард / sharded cluster** — данные коллекции разрезаны по shard key на несколько replica set. Масштаб ёмкости и записи, если ключ удачный. Шардов для распределения вендор: минимум два. Community CR шарды не описывает.

**Shard key** — поле (или поля), по которому режут коллекцию. Плохой ключ = один горячий шард. Высокая cardinality, без монотонного hotspot — или hashed. Проектировать до терабайт данных на коллекции.

**`reshardCollection`** — смена shard key с 5.0. Тяжёлая операция, не «поменяли конфиг».

**Chunk** — кусок диапазона shard key на одном шарде. Балансировщик двигает chunk'и. Горячий документ живёт на одном чанке — шард его не спасёт.

**CSRS (config servers)** — replica set с метаданными шардов (кто какой chunk держит). В проде — **3** члена. Упал CSRS кворум — кластер не маршрутизирует нормально. Вендор рекомендует раскладывать CSRS и каждый шард минимум на 3 ЦОДа.

**Hashed sharding** — режут по хешу поля. Ровнее пишет (хорошо для монотонного `_id`/времени), хуже диапазонные запросы (часто scatter-gather: запрос уходит на все шарды).

**Change stream** — подписка на изменения коллекции/БД. Нужен replica set или sharded cluster. Это не Kafka: нет долгого retention как у топика, семантика другая.

**SCRAM** — пароль + challenge (дефолтная аутентификация Community).

**X.509** — аутентификация сертификатом (клиенты и/или члены replica set).

**Keyfile** — общий секрет между членами replica set / шардами («мы свои»). Без внутренней аутентификации чужой `mongod` можно добавить в набор, если дотянулся до порта.

**RBAC** — роли: кому какие действия на каких БД. Дефолт: authorization выключен. Сначала user administrator, потом остальные; приложению не дают `userAdminAnyDatabase` / `dropDatabase` / `root`.

**Authorization / access control** — проверка ролей. Localhost exception — только процедура создания первого пользователя, не постоянный режим. `bindIp` на внутренний интерфейс, не интернет. Нативный пакет слушает localhost; образы/Helm часто шире «чтобы завелось».

**Encryption at rest (WiredTiger native)** — шифрование файлов движком, часто с KMIP. Это **Enterprise**, не Community. Community: LUKS / CSI encryption / dm-crypt, права на `dbPath`.

**KMIP** — протокол к внешнему хранилищу ключей. Native связка — Enterprise.

**Аудит** — журнал «кто что сделал» на сервере. Это **Enterprise**. Community: логи подключений + аудит в приложении / SIEM снаружи.

**LDAP / Kerberos** — корпоративный вход. Это **Enterprise / Atlas**, не Community 7.0.

**In-Memory storage engine** — движок «только RAM». Enterprise, не Community.

**MCK** — MongoDB Controllers for Kubernetes — актуальный оператор (слияние Community Operator и Enterprise Operator). Релиз **1.10.0** (30 июля 2026). В CR Community пинить `spec.version` полной строкой (`7.0.40`). sidecar `mongodb-agent` — отдельный потребитель CPU/RAM в смете пода.

**Stretch** — один replica set / sharded cluster, члены физически в разных ЦОДах. Ходят друг к другу по 27017 (и служебным портам шардов). Hostname, не голый IP: с 5.0 узел только с IP в конфиге replica set не стартует. Полный mesh.

**PSS-3 1-1-1** — три data-bearing члена, по одному в ЦОД. Падение любого одного ЦОДа — оставшиеся двое выбирают primary. `w: majority` ждёт вторую площадку — латентность = RTT.

**PSS-5 2-2-1** — пять членов на 3 ЦОДа, majority=3. Падение любого одного ЦОДа оставляет ≥3 голосов. Два члена в ЦОДе primary могут закрыть `w: majority` внутри площадки. Цена: пять полных копий данных.

**Fault tolerance (голоса)** — 3 члена → пережить 1; 5 → 2. Четыре члена не дают tolerance 2. Replica set: до **50** членов, из них голосующих до **7**. Официальный прод-стандарт — **3**.

**`rs.stepDown()`** — контролируемая сдача роли primary. Без прогона нет HA, есть надежда. Drain primary без stepDown = простой записи.

**`replSetGetStatus`** — команда статуса набора: кто primary, лаг, здоровье.

**URI `replicaSet=` / SRV** — строка подключения со всеми членами (или DNS SRV). Драйвер с retryable writes/reads — норма 7.0. «Подключились к одному IP 27017 навсегда» переживает только standalone.

**Retryable writes/reads** — драйвер сам повторяет часть операций после смены primary.

**`mongosh`** — консольный клиент. **Database Tools** — `mongodump` / `mongorestore` / `mongostat`. Compass — UI-клиент, не кластер.

**`mongodump --oplog`** — логический дамп. Вендор считает инструментом **небольших** деплоев; на терабайтах impact неприемлем → снимок тома/CSI с journal, предпочтительно со hidden secondary.

**PITR** — восстановление на момент времени «из коробки». Ops Manager / Cloud Manager / Atlas, не Community. Community: снимки ФС/CSI и `mongodump`.

**Ops Manager / Cloud Manager / Atlas** — коммерческие или облачные контуры, не Community Server. Percona Server for MongoDB и 8.x в этот файл не входят.

**XFS** — файловая система. Для data-bearing с WiredTiger настоятельно рекомендуется. EXT4 + WiredTiger — риск деградации.

**THP (Transparent Huge Pages)** — выключить на хосте. Иначе хвосты latency.

**NUMA / `numactl --interleave=all`** — память по сокетам CPU; для `mongod` вендор просит interleave.

**`vm.swappiness`** — насколько ядро уводит страницы в swap. Production notes: 0 или 1.

**Readahead** — сколько диска ядро читает вперёд. Том: **8–32**.

**NTP** — синхронизация часов, особенно шарды.

**RAID-10** — зеркало+страйп. Production notes: RAID 10, не 5/6, если аппаратный RAID. SSD; локальный быстрый том.

**Индекс** — структура на диске и в RAM для запросов. Запрос без индекса на терабайтах = collection scan. Индекс ест RAM и диск. Не «на все поля».

**Collection scan** — чтение всей коллекции. Первый такой в проде — инцидент, если индексы не спроектировали на тесте.

**Aggregation / multi-document transaction** — законная фича 7.0 и законный способ уложить primary. Не обещать «как Redis SET» на транзакции через три ЦОДа.

**TTL-индекс** — автоудаление документов по времени. Истёкший TTL уедет и на secondary — реплика не бэкап.

**`slowms` / профилировщик** — лог медленных операций. Сам профилировщик стоит: включать осторожно.

**`--noscripting`** — выключить server-side JS (`$where`, `$function`, `mapReduce`, `$accumulator`), если нет явной нужды.

**QPS / write-QPS / IOPS** — запросов и операций диска в секунду. Нагрузки нет — нет цифры «N шардов и M гигабайт cache».

**Working set** — горячие страницы, которые должны влезать в cache. Thrash — cache постоянно вытесняет нужное.

**Connection / keepalive 120** — TCP-сессии клиентов; production notes про keepalive. Тысячи соединений — часть сметы RAM.

**LoadBalancer** — не замена replica set URI. Antipattern перед primary.

**Image `mongodb/mongodb-community-server:7.0.40-ubi9-slim`** — официальный образ. Не устаревший `library/mongo` как единственный ориентир. Публиковать `-p 27017:27017` на все интерфейсы рабочей станции нельзя.

**Mongosync** — отдельное ПО переноса/копии кластера. Для read-heavy вендор предлагает отдельный кластер — это уже не Community Server «из коробки».

**Outbox / change stream → Kafka** — публикация факта «документ изменился». Шина всё равно Kafka.

**Антивирус / EDR** — исключить `dbPath` и лог: сканер может испортить файлы и уронить процесс.

**Vault / Secret** — пароли и keyfile не в Git.

**Jump host** — люди в прод-Mongo не общей учёткой приложения. Community не становится LDAP-сервером.

**Mesh** — полный обмен между всеми членами replica set на их портах, не «клиент ходит только на primary». Нет pod-to-pod между ЦОДами → это не один набор.

**Overlay / jitter** — сеть подов с плавающей задержкой. Если хуже VM — члены иногда лучше вне overlay. Решение по замерам.

**Бэкап** — снимок вне набора и прогнанный restore. Secondary спасает от падения ноды. Не спасает от `dropDatabase`, кривого обновления, ransomware на StorageClass.

**DR** — ручной restore или reconfigure voting при недоступных членах. Вендор описывает это как процедуру аварии, не автоfailover. Вариант «мозг в одном ЦОДе»: падение ЦОД-1 = нет записи ни у кого.

**Cache pressure (PSA)** — если data-bearing нода лежит, `w: majority` в PSA не выполняется, majority commit point отстаёт, WiredTiger копит историю, растут I/O и cache, oplog может разрастаться выше лимита. Смягчение: временно `{ votes: 0, priority: 0 }` на больной ноде — костыль.

**1-1-1 vs «мозг в одном ЦОДе» vs независимые наборы** — stretch один URI; кворум только в ЦОД-1 плюс скрытые копии; три SoT без склейки приложением или Kafka.

Источники формулировок: глоссарий и тело `MongoDB 7.md`. Новых порогов RTT и размеров диска/cache здесь нет.
