# Redis Community Edition 7.4.11 — термины и сокращения

Словарь к файлу `Redis 7.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в операционной системе: у неё есть память и открытые файлы. В Redis это один `redis-server` на ноду.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. У Redis на диске живут снимок и журнал записей, а рабочий набор ключей — в оперативной памяти.

**RAM** — оперативная память процесса. Данные Redis держатся здесь; диск нужен, чтобы пережить рестарт, не чтобы хранить терабайты как СУБД.

**TCP-порт** — номер, по которому другие программы находят этот процесс в сети. У Redis клиенты ходят на **6379**; внутренняя сеть Cluster — **16379**; Sentinel — **26379**. UDP нет.

**ЦОД** — отдельная площадка с серверами (своё питание, своя сеть). «Три ЦОДа» в тексте — три такие площадки.

**RTT** — время туда-обратно по сети между двумя машинами. Чем оно больше, тем дольше операция, которая ждёт подтверждения с другой площадки. Порога миллисекунд у Redis Community **нет**.

**TLS** — шифрование байтов в сети. В дефолтном `redis.conf` выключен (`tls-port` закомментирован). Без него команда AUTH и значения ключей идут открытым текстом.

**fsync** — вызов ОС «запиши буфер на диск сейчас». Политика AOF `always` / `everysec` / `no` как раз про то, как часто это делать.

**fork()** — системный вызов: процесс создаёт дочерний. Снимок и сжатие журнала Redis делает дочерний процесс после `fork()`. На большом наборе ключей это даёт паузу задержки; copy-on-write после fork увеличивает пик RAM.

**HA (high availability)** — способность пережить отказ машины или процесса без ручного «поднять сервер заново с нуля». Конкретные цифры времени в файле не обещаны.

**RPO** — сколько уже подтверждённых данных готовы потерять при аварии. **RTO** — за сколько времени снова начать принимать запросы. Успешный `PING` и живая копия ≠ «ни один ключ не потерян при смене master».

**SoT (source of truth)** — место, откуда система считает текущее состояние сущности правдой. Для карточки клиента в этом файле это не Redis, а озеро/СУБД.

**Под (Pod)** — минимальная единица запуска в Kubernetes: один или несколько контейнеров, которые живут и умирают вместе. IP пода меняется.

**StatefulSet** — объект Kubernetes для процессов с постоянным именем и диском. Redis с persistence ставят так, не Deployment с одноразовым IP как у единственного клиента без Sentinel/Cluster.

**PVC** — заявка Kubernetes «дай том такого размера». **CSI** — плагин, который этот том создаёт. Для RDB/AOF нужен локальный быстрый диск (SSD), не единственный NFS.

**NFS** — сетевая файловая система. Латентность fsync при сжатии AOF опасна, если это единственный диск ноды.

**emptyDir** — том, который исчезает при рестарте пода. Для AOF/RDB в проде это холодный старт или пустой master (опасный паттерн репликации).

**cgroup** — лимит памяти и CPU, который Kubernetes ставит на контейнер. `maxmemory` должен быть **ниже** этого лимита.

**OOM** — процесс убит, потому что кончилась память cgroup или машины. Часто в момент снимка, не в `PING`.

**NetworkPolicy** — правила Kubernetes, кто в кластере может открыть TCP на 6379 / 16379 / 26379. Это не ACL Redis.

**Anti-affinity / topology spread** — правило планировщика: не класть два пода Redis (или все Sentinel) на одну машину или в одну зону.

**PDB (PodDisruptionBudget)** — лимит, сколько подов можно снять одновременно при плановом обслуживании ноды. Не защищает от падения ЦОДа. Нельзя снять сразу majority Sentinel или два master Cluster.

**Helm / чарт** — шаблон установки набора манифестов. Готовые чарты Bitnami проверяют на лицензию образов и тег; не `latest`.

**PKI** — выпуск и проверка сертификатов. Нужен, если включаете TLS между ЦОДами.

**CVE** — опубликованная запись об ошибке безопасности. Линия 7.4 регулярно закрывает RCE в Lua; 7.4.11 — SECURITY-патч.

**RCE** — удалённый запуск кода в процессе сервера (здесь — через Lua). Боевым учёткам `EVAL`/`SCRIPT` лучше запретить ACL, если Lua не нужен.

**ПДн** — персональные данные. Компрометация Redis с сессиями или кэшем ответов госслужб = компрометация ПДн. **152-ФЗ** задаёт срок хранения: TTL и запрет класть полный паспорт «на всякий случай».

**ГОСТ / СКЗИ** — требования к криптографии контура КИИ. Штатный TLS OpenSSL сборки Redis их не закрывает.

**LoadBalancer** — сервис Kubernetes, который выдаёт адрес снаружи кластера. 6379 в интернет без ACL — открытая память контура.

**Image tag `latest` / `redis:7`** — ярлык, который завтра укажет на другой патч. В проде пинят `redis:7.4.11` (лучше digest).

**Инстанс / нода** — один процесс `redis-server`. Данные в RAM; диск — чтобы пережить рестарт.

**Ключ / значение** — запись вида `session:abc → …`. Структуры разные: строка, hash, list, set, zset, stream, bitmap.

**TTL** — срок жизни ключа. Истёк — Redis удалит. Для кэша это норма; для единственной копии клиента — нет.

**Master (primary)** — нода, которая принимает запись (`SET`/`DEL` и остальные команды изменения). Реплики копируют с неё.

**Replica (historically slave)** — копия master. По умолчанию только чтение (`replica-read-only yes`). Реплика не увеличивает объём записи и не является бэкапом.

**Асинхронная репликация** — master не ждёт реплику, отвечая клиенту «записано». Реплика может отстать. Это дефолт Redis. Если master умер до досылки — клиент уже получил OK, а на копии этой записи нет.

**Failover** — аварийная смена master (старый умер). Сама репликация failover не делает: нужен Sentinel или Redis Cluster. Клиент обязан уметь узнать новый адрес.

**Split / разъезд датасетов** — старый master ещё принял записи, которых нет на новом (репликация async). Это потеря строк, не «потом автоматически смержим».

**Лаг реплики** — насколько копия отстала от master (offset репликации или время). Читатель с replica может не видеть только что записанный ключ.

**WAIT** — команда клиента: подожди, пока N реплик подтвердят запись. Уменьшает окно потери, не делает Redis системой с сильной согласованностью (как quorum-write в etcd).

**WAITAOF** — то же для сброса AOF на диск (`fsync`). Есть с Redis **7.2**. Тоже не сильная согласованность.

**Сильная согласованность / CP** — гарантия «клиент получил OK — запись уже на большинстве копий и не откатится». Спека Cluster прямо описывает окна потери acknowledged writes; `WAIT` это не закрывает.

**Sentinel** — отдельные процессы, которые следят за одним master и репликами (не Cluster), голосуют, что master мёртв, и переключают реплику в master. Клиенты спрашивают Sentinel: «кто сейчас master?». Порт **26379**.

**Кворум Sentinel (детект)** — сколько Sentinel должны согласиться, что master недоступен. Сам failover стартует только если есть **большинство процессов Sentinel**. Два Sentinel официально «DON'T DO THIS». Минимум — **3**, в независимых зонах отказа.

**SDOWN / ODOWN** — Subjectively down (один Sentinel так думает) / Objectively down (кворум согласился). Failover — от ODOWN.

**`down-after-milliseconds`** — через сколько миллисекунд Sentinel считает master недоступным. Пример из доки `60000` — учебный, не ваш SLA. Ставить меньше нормального блеска сети опасно ложным failover.

**Redis Cluster** — режим шардирования: ключи раскиданы по **16384 слотам**. Несколько master, у каждого свои слоты и обычно свои реплики. Sentinel на тот же датасет **не** ставят.

**Hash slot** — корзина ключа: `CRC16(key) mod 16384`. Клиент ходит на master, которому слот принадлежит. Рекомендуемый максимум нод порядка ~1000, не 16384 master.

**Hash tag `{...}`** — кусок ключа в фигурных скобках: `{user:1}:profile` и `{user:1}:cart` попадут в один слот. Без этого мультиключ (`MGET`, транзакция на два ключа) в Cluster часто даёт **CROSSSLOT**.

**CROSSSLOT** — ошибка Cluster: команда затронула ключи из разных слотов. `MULTI` на два ключа без hash tag так и ломается.

**MOVED / ASK** — ответы Cluster-протокола клиенту: «этот слот на другом master» / «временно иди сюда». Клиент без поддержки протокола за балансировщиком «как у HTTP на все 6379» ломает модель.

**Cluster-aware клиент** — библиотека, которая держит карту слотов и ходит напрямую на нужный master (или умеет Sentinel). «Подключились к одному IP 6379 навсегда» переживает только standalone.

**Cluster bus** — внутренняя сеть нода↔нода (gossip, failover). Порт по умолчанию командный + 10000, то есть **16379**, если клиентам **6379**. Клиенты сюда не ходят.

**Gossip** — ноды периодически рассказывают друг другу, кто жив. На этом держится детект отказа Cluster. Нужен полный mesh 16379 между всеми нодами.

**NODE_TIMEOUT (`cluster-node-timeout`)** — сколько миллисекунд нода должна быть недостижима, чтобы её посчитали мёртвой. Дефолт в `redis.conf` **15000**. Должен быть заметно больше RTT. Слишком маленький = ложные PFAIL/FAIL и лишние failover.

**PFAIL / FAIL** — пометка Cluster: нода субъективно / объективно мертва. От FAIL идёт failover слотов.

**Большинство master** — failover в Cluster: реплика должна получить голоса большинства master. 3 master → нужно 2. Падение двух ЦОДов из трёх при одном master на ЦОД = кворума нет, запись останавливается.

**`cluster-require-full-coverage`** — дефолт **yes**: если часть слотов никому не принадлежит, кластер отказывается писать (и часто читать покрытые слоты тоже в error state). `no` — обслуживаем что осталось. Для кэша часто ставят `no`; для единственной копии сессии — нет.

**Replica migration** — если у master не осталось реплик, Cluster может переселить лишнюю реплику с другого master. Барьер: `cluster-migration-barrier`. На ровно одной реплике на master переселять почти не из чего.

**`nodes.conf` / `cluster-config-file`** — файл карты Cluster на PVC. Без постоянного файла после рестарта пода Cluster «забывает себя».

**`redis-cli --cluster`** — утилита создать/добавить ноды Cluster (`create`, `add-node`, `reshard`). Новые ноды без reshard стоят пустые.

**Reshard** — плановая перекладка слотов на другой master. Не автоматическое масштабирование «добавили под — данные сами переехали».

**RDB** — снимок всего датасета на диск. Быстрый рестарт, компактный файл для бэкапа. Между снимками данные можно потерять (минуты — типичный save point). Дефолтные точки в комментариях конфига: `3600 1`, `300 100`, `60 10000`.

**AOF** — журнал записей. С Redis **7.0** — multi-part AOF (base + incremental). В дефолте выключен (`appendonly no`).

**`appendfsync`** — как часто сбрасывать AOF на диск: `always` / `everysec` (дефолт смысла AOF) / `no`. **`appendfsync everysec`**: официально можно потерять около 1 секунды записей при аварии. `no` — в руках ядра, до ~30 с по формулировке доки.

**BGSAVE / rewrite** — снимок или сжатие AOF делает дочерний процесс после `fork()`. Ещё одна причина не класть терабайты в Redis.

**Persistence** — запись RDB и/или AOF на диск. Реплики не заменяют снимок. `FLUSHALL`, ошибка приложения, истёкший TTL, шифровальщик на PVC — реплицируются тоже. Master без persistence с авторестартом: реплики синхронизируются с пустым master и стирают свои данные.

**`maxmemory`** — потолок RAM инстанса. В дефолтном `redis.conf` не задан — процесс будет есть память, пока его не убьёт OOM. В проде задают всегда, ниже лимита cgroup, с запасом на буфер реплики и fork.

**`maxmemory-policy`** — что делать, когда потолок достигнут. Дефолт **`noeviction`**: запись получает ошибку, ключи сами не выкидываются. Для кэша обычно `allkeys-lru` / `allkeys-lfu`. Смешать на одном инстансе «кэш можно дропнуть» и «лок нельзя» — слабое место; лучше два инстанса.

**Eviction** — вытеснение ключей по политике, когда `maxmemory` достигнут.

**ACL** — именованные пользователи и права на команды и ключи (с Redis 6). Рекомендуемый способ вместо одного `requirepass` на всех. Default user в 7.x лучше выключить или оставить без опасных команд.

**`requirepass`** — старый «один пароль на инстанс». С `aclfile` несовместим. Пароль в конфиге открытым текстом.

**Protected mode** — если слушаем все интерфейсы и нет пароля/ACL — с 3.2 Redis отвечает только loopback и ругается остальным. Это страховка, не костыль прода. `protected-mode no` + bind `*` + без пароля = инцидент.

**AUTH** — команда проверки пароля. Без TLS не защищает от сниффера: идёт как остальные команды.

**`bind`** — на каких сетевых интерфейсах слушать. Образы часто слушают `*` и отключают protected mode «чтобы завелось».

**`io-threads`** — с Redis 6: доп. потоки на сеть, не на исполнение команд. Команды по-прежнему в основном на одном потоке. В `redis.conf` пример `4`, выключено комментарием. Масштаб записи одного ключа ≠ «добавить тред».

**LOGICAL DB (`SELECT`)** — на standalone по умолчанию **16** логических баз (0…15). В Redis Cluster работает только DB 0. Не проектируйте «db=1 для кэша, db=2 для сессий», если цель — Cluster.

**Stretch** — один логический Sentinel-набор или один Cluster, ноды физически в нескольких ЦОДах. Общаются по 6379/16379/26379. Пока RTT не измерен — гипотеза.

**Active-Active (CRDT)** — мультимастер запись в нескольких регионах. Это Redis Software / Redis Cloud, не Community 7.4. Community Cluster = один writer на слот.

**Valkey** — форк Linux Foundation от Redis 7.2 (BSD). Не этот документ. Имеет смысл, если юристы запретят RSALv2/SSPL.

**RSALv2 / SSPLv1** — лицензии линии **7.4.x** (это уже не BSD). Линия **7.2 и старше** — BSD-3-Clause. Линия **8.x** в этот файл не подменяют. Без решения юристов установка 7.4 в контур может быть запрещена.

**Redis Software / Enterprise / Cloud** — коммерческие продукты Redis Ltd. Официальный Kubernetes-оператор Redis Ltd — Enterprise. Community-оператора у Redis Ltd нет.

**Redis Stack / модули (`.so`)** — RedisJSON, RediSearch и т.п. В ванильном образе `redis:7.4.11` этих модулей нет, пока сами не загрузите (и не примете их лицензию).

**Pub/Sub** — публикация подписчикам без долгого лога. Подписчик перезапустился — сообщения нет. Это не Kafka.

**Streams** — структура журнала в Redis. Другая семантика и ops, чем у топика Kafka; в файле не замена шины.

**`FLUSHALL` / `DEL` / `KEYS` / `DEBUG` / `CONFIG` / `MODULE`** — опасные команды. `CONFIG` умеет сменить каталог и имя dump (класс атак на запись файла). Приложению кэша их не дают ACL.

**`rename-command`** — старый способ спрятать команду. Deprecated; путь — ACL.

**`min-replicas-to-write` / `min-replicas-max-lag`** — master отказывается писать, если живых реплик с допустимым лагом меньше N. Дефолт в конфиге — не требовать реплик. Это снижает доступность при падении реплик/ЦОДа.

**`tls-port` / `tls-replication` / `tls-cluster`** — отдельные ручки TLS для клиента, репликации и cluster bus. Между ЦОДами без TLS ключи сессий идут по городской сети; gossip и failover-команды — открытым текстом.

**Transparent Huge Pages (THP)** — режим ядра Linux, который даёт хвосты задержки у Redis. Выключают на хосте, не флажком в ConfigMap.

**`vm.overcommit_memory=1`** — настройка ядра, чтобы `fork` для BGSAVE не отказывался.

**QPS** — запросов в секунду. Нагрузки в исходном контексте нет, поэтому в файле нет сметы ядер и гигабайт.

**Mesh** — полная связность нода↔нода (для Cluster — все 16379). Нет pod-to-pod между ЦОДами → это не один Cluster, а несколько инстансов.

**NAT / Docker port-mapping** — подмена портов на входе контейнера. Sentinel официально ломает autodiscovery; Cluster не рассчитан на NAT.

**`READONLY`** — в Cluster чтение с replica после этой команды. Читатель видит отставание.

**Hot key / big key** — один горячий или огромный ключ. Cluster его не шардирует; огромный hash убивает задержку BGSAVE и сеть репликации. Ловят `redis-cli --bigkeys` / `--memkeys` / `--keystats` (7.4).

**`INFO` / `CLUSTER INFO` / `SENTINEL masters`** — команды телеметрии: память, репликация, слоты, кто master. Сигналы: `used_memory`, eviction, `rejected_connections`, лаг, `blocked_clients`, `master_link_status`, CPU `commandstats`.

**`CLUSTER FAILOVER`** — команда на replica отдать ей слоты. Контролируемый failover для учения; rolling upgrade без failover = простой записи.

**Утилиты** — `redis-cli`, `redis-benchmark`, `redis-check-aof`, `redis-check-rdb`. Операционка, не runtime.

**redis-exporter** — отдельный процесс метрик Prometheus. Его HA проектируется отдельно.

**OT-CONTAINER-KIT** — сторонний community-оператор Kubernetes (заявляет Redis ≥ 6). Совместимость конкретного релиза с 7.4.11 прогонять на стенде; сертификата «как Strimzi ↔ Kafka» нет.

**DR (disaster recovery)** — заранее прогнанный restore RDB/AOF на другой площадке или холодная replica вне кворума. Это ручное восстановление, не автоfailover.

**Vault / Secret** — место для ACL-файла и паролей, не Git.

**Jump host** — контролируемый вход людей в прод-Redis. Community не становится OIDC-сервером; людей не пускают «логином как в UI».

**Least privilege** — приложению только нужные команды и ключи; кэш-сервис не делает `FLUSHALL`.

**WAF** — фильтр HTTP-атак. Redis его не содержит: модель — доверенные клиенты в доверенной сети.

**hostNetwork** — под слушает порты хоста. Иногда берут, если overlay между ЦОДами хуже VM-сети; решение по замерам.

**Rolling upgrade / drain** — плановая смена подов. Drain без failover = простой записи.

**Loopback** — адрес 127.0.0.1 той же машины. На тесте пароль можно не ставить только на loopback / изолированной сети.

**Идемпотентность** — повтор того же запроса не удваивает внешний вызов. В Redis — ключ вроде `idem:req-id` с TTL. Для денег Redis-лок не консенсус: сеть моргнула — можно получить два лока.

**Rate-limit / circuit** — ограничение частоты вызовов и обрыв больного контура. Типичная роль Redis перед интеграционным API, не шина событий.

**Object storage / S3** — хранилище объектов. RDB удобнее увозить туда, чем сырой AOF. Это не диск Redis.

**Бэкап** — копия, с которой можно поднять данные независимо от живых процессов. Реплика им не является. Нужно проверять restore, не только наличие файла.

Источники формулировок: глоссарий и тело `Redis 7.md`. Новых порогов RTT и размеров RAM здесь нет.
