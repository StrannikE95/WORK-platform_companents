# PostgreSQL 18.6 — термины и сокращения

Словарь к файлу `PostgreSQL.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в операционной системе: у неё есть память и открытые файлы. PostgreSQL на одну клиентскую сессию обычно поднимает отдельный такой процесс.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. Каталог данных PostgreSQL называют `PGDATA`: там таблицы, индексы и журнал изменений.

**TCP-порт** — номер, по которому другие программы находят этот процесс в сети. У PostgreSQL клиенты и копии ходят на **5432**.

**ЦОД** — отдельная площадка с серверами (своё питание, своя сеть). «Три ЦОДа» в тексте — три такие площадки, не три папки в одном шкафу.

**RTT** — время туда-обратно по сети между двумя машинами (запрос ушёл, ответ пришёл). Чем оно больше, тем дольше операция, которая ждёт подтверждения с другой площадки.

**TLS** — шифрование байтов в сети. В конфиге PostgreSQL параметр всё ещё называется `ssl`, но речь про TLS. Без него пароль и строки таблиц идут по сети открытым текстом (SCRAM закрывает только обмен паролем, не SELECT).

**CVE** — опубликованная запись об ошибке безопасности в конкретном ПО. Номер вроде CVE-2026-… — идентификатор этой записи, не «балл опасности».

**CVSS** — числовая оценка тяжести такой ошибки (часто до 10). В тексте «CVSS 8.8» значит «очень тяжёлая», не отдельный продукт.

**EOL** — дата, после которой авторы линейки больше не выпускают исправления. PostgreSQL 14 в файле: 12 ноября 2026.

**OLTP** — профиль работы: много коротких изменений «одна карточка / один COMMIT», не тяжёлые отчёты по миллионам строк.

**SoT (source of truth)** — место, откуда система считает текущее состояние сущности правдой. Для карточки клиента в этом файле это PostgreSQL, не кэш и не лог Kafka.

**Инстанс PostgreSQL** — один запущенный `postgres` (главный процесс плюс рабочие) с одним каталогом `PGDATA`.

**Кластер PostgreSQL** — не Kubernetes. Это набор баз внутри одного `PGDATA` (`postgres`, `template1`, ваши базы). Один primary = один такой набор.

**База (`CREATE DATABASE`)** — логический контейнер схем и таблиц внутри инстанса. Не путать с «сервером» и с «кластером PostgreSQL».

**Схема** — пространство имён таблиц внутри одной базы (`public` и ваши). Права часто выдают на схему, не «на весь инстанс».

**Primary** — единственный инстанс, который принимает запись (`INSERT`/`UPDATE`/`DELETE`/`DDL`). Community PostgreSQL не пишет сразу в несколько primary.

**Standby / replica / hot standby** — второй инстанс, который копирует изменения с primary. Hot standby можно читать через `SELECT`. Штатно писать в него нельзя: сервер отвергнет изменение.

**WAL (Write Ahead Log)** — файлы на диске, куда PostgreSQL **сначала** пишет факт изменения, и только потом обновляет страницы таблиц. Репликация и восстановление после падения процесса читают именно эти файлы. Если сегмент WAL удалили раньше, чем копия его прочитала — копию нельзя «догнать», её клонируют заново.

**fsync** — вызов ОС «запиши буфер на диск сейчас». Выключить `fsync` в PostgreSQL значит: после краха ОС можно потерять уже отвеченный клиенту `COMMIT`.

**Streaming replication** — копия непрерывно забирает WAL по сети с primary. Это побайтовая копия всего инстанса, не «одной таблицы».

**Синхронная репликация** — `COMMIT` на primary не возвращает OK клиенту, пока указанное число копий не подтвердили запись WAL. По умолчанию в PostgreSQL синхронных копий нет.

**`synchronous_commit`** — насколько глубоко ждать. `on` плюс непустой список sync-копий: ждать запись WAL на копии. `remote_apply` — ещё и чтобы `SELECT` на копии уже видел строку (медленнее). `local` / `off` — копию не ждать.

**`synchronous_standby_names`** — кого считать sync. `ANY n (...)` — любые n из списка. `FIRST n (...)` — первые n живых по порядку списка.

**Асинхронная репликация** — primary отвечает клиенту «закоммичено», копия догоняет позже. Если primary умер до досылки — клиент уже получил OK, а на оставшейся копии этой записи нет.

**Failover** — аварийная смена primary (старый умер). **Switchover** — плановая смена. В самом PostgreSQL автосмены нет: нужен CloudNativePG или Patroni.

**Split-brain** — два инстанса оба принимают запись. Потом одну ветку выбрасывают. Это потеря строк, не «потом автоматически смержим».

**Лаг реплики** — насколько копия отстала от primary (в байтах WAL или во времени). Читатель с копии может не видеть только что закоммиченную строку.

**Replication slot** — пометка на primary: «эти сегменты WAL ещё нужны такой-то копии, не удаляй». Без слота primary имеет право стереть непрочитанный WAL.

**Логическая репликация** — копирование выбранных таблиц (публикация/подписка), не всего диска. Не замена отказоустойчивости. DDL, последовательности, большие объекты — с ограничениями.

**`pg_hba.conf`** — файл правил: с какого адреса, в какую базу, каким методом пускать. Это список на стороне PostgreSQL, не сетевой firewall кластера.

**SCRAM-SHA-256** — способ хранить и проверять пароль (хеш, не открытый текст в каталоге). MD5 в 18 помечен как устаревший.

**`host` / `hostssl` / `hostnossl`** — типы строк в `pg_hba`: любой TCP / только с TLS / только без TLS.

**`ssl` (параметр сервера)** — включить TLS на 5432. Дефолт community: выкл.

**Суперпользователь (`postgres`)** — роль, которой можно всё, включая `COPY ... PROGRAM` (запуск программы ОС из сессии) и чтение файлов сервера. Учётке приложения её не дают.

**Роль** — учётка внутри PostgreSQL. **GRANT** — выдача прав на объекты. Приложению: `CONNECT` к своей базе и права на свои таблицы, без `CREATEDB` и без суперпользователя.

**RLS (Row Level Security)** — правила «этой роли видны только такие строки». Это не веб-фильтр и не замена отдельной базы на контур.

**`shared_buffers`** — кэш страниц таблиц **внутри** процесса PostgreSQL. Дефолт часто около 128 МБ. Остальная RAM машины идёт в кэш файлов ОС. Это не «вся память пода».

**`max_connections`** — потолок одновременных сессий. Каждая сессия — отдельный процесс. Дефолт часто около 100. Тысячи сессий съедают RAM раньше, чем вырастет число запросов в секунду.

**Сессия** — одно TCP-подключение клиента к PostgreSQL на время работы.

**PgBouncer** — отдельный процесс перед PostgreSQL: много клиентских подключений делят мало реальных сессий к базе. Режим `session` — одно клиентское соединение = одна сессия до отключения. Режим `transaction` — сессия отдаётся другому клиенту после `COMMIT` (ломает часть вещей, завязанных на всю сессию: часть prepared statements, `LISTEN/NOTIFY`, временные таблицы).

**MVCC** — способ хранения строк: `UPDATE` не затирает старую версию сразу, а пишет новую; старая видна транзакциям, которые начали раньше. Отсюда «мёртвые» версии, которые надо убирать.

**Autovacuum** — фоновый процесс, который убирает мёртвые версии строк. Без него файлы таблиц растут. Крайний случай: кончатся номера транзакций (wraparound) — сервер может остановить запись, чтобы не смешать старые и новые версии.

**Партиции** — нарезка одной большой таблицы на куски (часто по дате). Помогает удалять старое и пылесосить кусками. Второй процесс, который принимает запись, от партиций не появляется.

**PITR (Point-in-Time Recovery)** — восстановление на выбранный момент: берёте снимок диска/базовый бэкап и накатываете архив WAL до нужной секунды. Без архива WAL есть только «как было в момент снимка».

**RPO** — сколько уже подтверждённых данных готовы потерять при аварии (ноль, секунды, часы). **RTO** — за сколько времени снова начать принимать запросы. Копия на другом сервере не заменяет бэкап: `DROP TABLE` уедет и на копию.

**Бэкап** — копия, с которой можно поднять данные независимо от живых процессов. Реплика им не является.

**CloudNativePG (CNPG)** — программа в Kubernetes, которая по описанию в API поднимает primary и копии, меняет primary при падении, выпускает сертификаты, создаёт DNS-имена сервисов. Сама таблицы не хранит.

**Оператор Kubernetes** — контроллер, который смотрит объекты API и приводит фактические процессы к описанному виду. CNPG — такой оператор для PostgreSQL.

**CR (Custom Resource)** — объект в API Kubernetes вашего типа (`Cluster`, `Pooler`). Не файл на диске приложения, а запись «хочу такой PostgreSQL».

**`instances` (CNPG)** — сколько подов PostgreSQL в одном `Cluster`. Число копий = это число минус один.

**Под (Pod)** — минимальная единица запуска в Kubernetes: один или несколько контейнеров, которые живут и умирают вместе. IP пода меняется; клиент должен ходить в стабильное DNS-имя сервиса.

**Сервисы `-rw` / `-ro` / `-r`** — DNS-имена CNPG. `-rw` — текущий primary (запись). `-ro` — только копии (чтение с лагом). `-r` — любой инстанс; писать сюда нельзя. Порт 5432.

**`dataDurability`** — ручка CNPG у синхронной репликации. `required`: нет живой sync-копии — запись останавливается. `preferred`: если копии нет, синхронность временно снимают, запись идёт, появляется окно потери.

**Replica cluster (CNPG)** — другой объект `Cluster` (часто в другом Kubernetes), который догоняет источник по сети или из архива WAL. Автоматической смены primary между двумя Kubernetes оператор не делает.

**Stretch** — один логический набор (один primary), процессы физически в нескольких ЦОДах. В ваших инструкциях так не делают: сеть между площадками для ожидания WAL слишком медленная/нестабильная.

**Patroni** — агент на виртуалках, который выбирает primary через отдельное хранилище ключей (etcd/consul). На Kubernetes в этом файле его роль закрывает CNPG. Patroni и CNPG на одни и те же файлы данных вместе не ставят.

**Citus** — отдельный продукт: нарезка данных по серверам (шарды). В community PostgreSQL этого нет.

**FDW (Foreign Data Wrapper)** — таблица, которая на самом деле живёт на другом сервере PostgreSQL. Не HA.

**Горизонтальное масштабирование записи** — добавить ещё один процесс, который принимает `INSERT` тех же данных. У community PostgreSQL этого нет: запись упирается в один primary.

**Вертикальное масштабирование** — дать этому primary больше CPU, RAM, диска.

**DDL** — команды смены структуры (`CREATE TABLE`, `ALTER`). **DML** — изменение строк (`INSERT`/`UPDATE`/`DELETE`).

**`libpq` / JDBC** — клиентские библиотеки: C и Java. Приложение открывает ими TCP на 5432.

**Расширение (`CREATE EXTENSION`)** — загружаемый модуль внутри того же инстанса (`pg_stat_statements`, `pgcrypto`, PostGIS). Это не отдельный сервер. Обновление и дыры безопасности — у этого же процесса.

**PostGIS** — расширение с типами геометрии и индексами для карт. GeoServer может читать такие таблицы.

**`psql`** — консольный клиент. **`pg_dump` / `pg_restore`** — выгрузка и загрузка логического дампа. **`pg_basebackup`** — физическая копия каталога данных. **`pg_rewind`** — подтянуть старый primary к новой ветке WAL после смены роли. **`pg_upgrade`** — смена мажорной версии на месте.

**Pooler (CNPG)** — объект, который поднимает PgBouncer перед `-rw` или `-ro`.

**Barman Cloud** — выгрузка бэкапов и WAL в object storage (S3-совместимое хранилище). Встроенная в оператор реализация помечена как устаревающая; в файле для прода — плагин CNPG-I, не код внутри старого оператора.

**Object storage** — хранилище объектов (файл + ключ), не диск PostgreSQL. WAL-архив кладут туда, чтобы PITR не зависел от живого primary.

**CSI** — плагин Kubernetes, который создаёт диск для пода. **PVC** — заявка «дай том такого размера». Для PostgreSQL том должен быть локальным быстрым диском, не единственный NFS как `PGDATA`.

**NFS** — сетевая файловая система. Латентность `fsync` и поведение при обрыве сети для журнала WAL опасны, если это единственный диск primary.

**Anti-affinity** — правило планировщика: не класть два пода PostgreSQL на одну машину.

**PDB (PodDisruptionBudget)** — лимит, сколько подов можно снять одновременно при плановом обслуживании ноды. Не защищает от падения ЦОДа.

**NetworkPolicy** — правила Kubernetes, кто в кластере может открыть TCP на 5432. Это не `pg_hba`.

**Helm / чарт** — шаблон установки набора манифестов. Bitnami-подчарт Postgres в чужом чарте (Camunda, Superset) — не ваш SoT.

**`initdb`** — первичное создание каталога `PGDATA` пустым.

**`COMMIT`** — конец транзакции: изменения становятся видны другим сессиям (с оговорками изоляции) и при sync ждут WAL.

**Outbox** — таблица в той же базе, куда в одной транзакции с карточкой пишут «надо опубликовать в Kafka». Иначе база уже закоммитила, а сообщение в шину не ушло (или наоборот).

**HA (high availability)** — способность пережить отказ машины/процесса без ручного «поднять сервер заново с нуля». Конкретные цифры времени в файле не обещаны.

**QPS / TPS** — запросов/транзакций в секунду. В исходном контексте нагрузки нет, поэтому в файле нет сметы ядер.

**OOM** — процесс убит, потому что кончилась память cgroup/машины. Часто в VACUUM или тяжёлом отчёте, не в простом `SELECT 1`.

**cgroup** — лимит памяти/CPU, который Kubernetes ставит на контейнер.

**`listen_addresses`** — на каких сетевых интерфейсах слушать. В контейнере обычно все; доступ режут `pg_hba` и NetworkPolicy.

**`sslmode=verify-full`** — клиент проверяет сертификат сервера и имя хоста. `disable` — TLS нет.

**MD5 (пароль)** — старый метод аутентификации. В 18 deprecated.

**Unix-сокет** — подключение без TCP, файл на той же машине. Из соседнего пода приложения почти всегда ходят в TCP.

**Image tag `latest`** — ярлык, который завтра укажет на другой патч. В проде пинят `18.6`.

**Регрессия** — исправление, которое сломало другое поведение. Из-за этого линейка 18 пропустила 18.5.

**PGDG** — группа, которая выпускает community PostgreSQL (даты EOL линии 18).

**Postgres Pro / EDB** — другие продукты на базе PostgreSQL. Правила HA и лицензия другие; в файле их нет.

Источники формулировок: глоссарий и тело `PostgreSQL.md`. Новых порогов RTT и размеров диска здесь нет.
