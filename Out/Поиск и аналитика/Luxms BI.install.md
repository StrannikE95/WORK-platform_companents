# Luxms BI 12.x — установка и конфигурирование

Связанный документ (глоссарий, Patroni, NATS, лицензии, почему так): `Luxms BI.md`.

Этот файл — **как поставить и настроить**. Не копируйте Dev-значения в прод. Stretch одного кворума Consul/Patroni/NATS/синхронного Postgres на несколько ЦОДов **не делаем**: порога RTT в публичных docs Luxms нет.

Версии: линейка **12.x**. Notes вендора — **12.0.2**; портал документации помечен **12.1.0**. Точную сборку пакетов фиксируют **договором и персональным репозиторием**, не Docker Hub. Ниже — правила 12.x и стека из текущей «Технической информации».

Это **коммерческое** ПО (реестр российского ПО, рег. № **3366**). Без лицензии и репозитория вендора «скачать как Grafana OSS» нельзя. Публичного оператора Kubernetes в docs 12.x **нет**. Штатный путь — **пакеты Linux** (dnf/apt/zypper) + Ansible вендора после согласования схемы.

---

## Допущения этой инструкции

1. **Stretch запрещён.** Кворум Consul, Patroni (один primary), кластер NATS и KeyDB **ядра** — **внутри одного ЦОДа** (мозг в 1 ЦОДе; второй ЦОД — DR). Web-узлы в чужом ЦОДе без согласованных сессий/KeyDB дают «то залогинен, то нет».
2. Новый контур без требования «только ФСТЭК» — **12.x** (pin из репозитория). Сертификат ФСТЭК № 5055 — сборка **11.0.x**, не «12.x с тем же сертификатом».
3. ОС из матрицы вендора: Astra SE 1.7/1.8, РЕД ОС 7.3/8.0, Альт СП 10, Rocky 9, MosOS Arbat 15.5 — не «любой Ubuntu с Compose».
4. Ядро БД: PostgreSQL **15 или 17** (или Postgres Pro 15/17 и др. из tech-info) + обязательные расширения **из пакетов вендора** (`plv8`, `pgsql-http`, redis/keydb fdw, pubsub). Пакеты PG **13** вендор прекратил с 01.12.2025.
5. Dev — одна VM, изолированная сеть. **Не** выдумывать docker-compose «как у Grafana».
6. Нагрузки нет — ориентир вендора 8 ядер / 24 ГиБ / 500 ГиБ на сервер и 16/32/1 ТиБ на **100** одновременных — не ваша смета. UL: потолок **1000** сессий в описании лицензии.
7. Для 2 ЦОДов: мозг в ЦОД-1, cold/DR в ЦОД-2. Для 3 ЦОДов: то же; лицензия Enterprise Cluster в tech-info — формулировка **2** промышленных сервера — три площадки согласовать отдельно.
8. Luxms **не** ходит в госслужбы. Витрины — озеро/ClickHouse, которые наполнил интеграционный контур.
9. Importer 9.2 для новых внедрений **не** берём (Data Boring + datagate). ИИ-модуль 12.x в первом проде выкл.

## Dev: 1 ЦОД, без нагрузки

**Цель:** свой дэшборд по витрине (или демо-атлас), роли Viewer/Creator. **Не** цель: отказ ЦОДа и 1000 сессий.

### Предпосылки

- Доступ к **персональному** репозиторию (логин вендора).
- Одна VM на ОС из матрицы 12.x, NTP, jump-хост. 5432/443 не с мира.
- Лицензия DEVL / тест, если так оформлено в договоре.

### Установка (пакеты на одну VM — основной путь Dev)

Порядок из вашего **sysadm-guide той сборки**, что в договоре (имена пакетов могли сдвинуться; порты Java ниже — сверка с 12.x, исторический каркас есть в гайде 9.2):

1. ОС + NTP + разделы диска (не NFS как `$PGDATA`).
2. PostgreSQL 15/17 + расширения вендора.
3. KeyDB (один узел), NATS (кластерный блок **не** включать).
4. `luxmsbi-appserver-mono` (тест; для нагрузки источники выносят в datagate).
5. `luxmsbi-web`, `luxmsbi-bins`.
6. При необходимости Data Boring. Демо-атлас: пакет вида `bi-pg-ds-demo174` / `bi-pg-demo174` — только если репозиторий это даёт.

Вход с jump-хоста на web, не LoadBalancer в интернет. Пароли **не** `bi`/`bi` из примеров Lua гайда 9.2.

Appliance VM вендора — путь B «ещё быстрее понять продукт»; состав — в **текущем** гайде поставки, не в PDF 7.0 (там CentOS 7).

На Kubernetes: публичного Helm 12.0.2 нет. Самодельный Compose/чарт без runbook вендора = вы сами support. На тесте это не цель.

### Конфигурирование Dev

| Параметр | Значение | Зачем |
|---|---|---|
| Patroni / Consul | выкл | Нет цели пережить VM |
| NATS cluster | один узел | Нет трёх ЦОДов |
| MPP ClickHouse | выкл, если витрина маленькая | Не цель терабайты |
| SSO | локальные учётки, не `bi`/`bi` | Сначала контур данных |
| ИИ 12.x | выкл | Лицензия и ИБ |
| ФСТЭК 11.0.x | не обязательна | Если тест не аттестационный |

Чего **не** упрощать: ОС и мажор Postgres из матрицы; обязательные расширения; хотя бы один датасет с **вашими** полями (или честно демо); web и 5432 не с мира.

### Проверка Dev

1. UI открывается, дэшборд не пустой.
2. Снесли VM — атласы пропали: состояние на одном диске. Это ожидаемо.
3. Не включать `no_tls` / `no_auth_user` из appendix NATS 12.x как «норму».

### Сильные / слабые стороны Dev

| Сильное | Слабое |
|---|---|
| Совпадает с официальным «один сервер / DEVL» | Нет Patroni, нет пула HAProxy, нет SSO |
| Показывает, есть ли витрина, которую BI прожуёт | Успех на VM ≠ FDW не убьёт SoT в проде |
| | Привычка plaintext и `bi`/`bi` уедет в бой |

Препрод: Patroni на 2–3 VM **в одном ЦОДе**, два web, HAProxy, свои секреты, NATS с TLS — даже без боевых пользователей.

## Prod: 2 или 3 ЦОДа, без stretch, нагрузка возможна

**Цель:** пережить отказ **машины внутри ЦОДа** (второй web, Patroni switchover, NATS/KeyDB не single). Отказ **ЦОДа с primary** = нет записи и, скорее всего, UI, пока DR promote + DNS VIP. Терабайты фактов — ClickHouse/озеро, **не** единственный Postgres ядра.

### Почему не stretch

Consul gossip, Patroni, NATS **6222**, репликация Postgres. Городской firewall режет UDP/TCP — кластер не соберётся. Потеря кворума Consul = Patroni не знает лидера → запись BI встаёт. Лицензия «2 сервера» может не покрывать три площадки + MPP.

### Топология

**Внутри активного ЦОДа (ЦОД-1)** — мозг:

- Consul **3** (кворум 2) **в этом ЦОДе**;
- Patroni: 3 узла Postgres 15/17 + расширения вендора; клиенты **только** через VIP/HAProxy, не hostname лидера;
- NATS cluster: уникальный `server_name`, JetStream на диск (`/opt/nats` в гайде — старт **10 ГиБ**), **не** `no_tls: true` и не `no_auth_user` из примера 12.x;
- KeyDB: пароль/ACL, репликация, **не** `protected-mode no` из гайда 9.2 без firewall;
- ≥2 `luxmsbi-web`, ≥2 appserver (или mono, если вендор так согласует); HAProxy HTTPS снаружи;
- в гайде 9.2 nginx `hash $upstream_cookie consistent` на appserver — **липкость к appserver желательна**;
- datagate / Data Boring не на тех же CPU, что web;
- TLS к Postgres — **включить**, пока ИБ не подписала исключение; рекомендация вендора «plaintext внутри для нагрузки» для контура с ПДн слабая;
- pin пакетов из репозитория (12.0.2 vs 12.1.0 — как в договоре).

**Между ЦОДами:**

| Площадок | Что где | Отказ ЦОД-1 |
|---|---|---|
| **2 ЦОДа** | ЦОД-1: весь мозг + web. ЦОД-2: реплика Postgres (async) / бэкап + холодные пакеты; **не** член кворума Consul ЦОД-1 | UI/запись стоят, пока promote + переключение VIP. RTO замерить. Реплика Patroni **не** заменяет backup ядра (DROP повторится) |
| **3 ЦОДа** | ЦОД-3: второй DR или только бэкапы | То же; не три независимых атласа «для HA» |

MPP ClickHouse — **отдельный** HA (`ClickHouse.install.md`). «Поставили Luxms Cluster» ≠ «витрина переживает ЦОД».

### Предпосылки прода

- Согласованная с вендором схема и **их** Ansible/runbook.
- Зеркало репозитория пакетов в контуре.
- Vault: пароли `bi`, KeyDB, NATS, JDBC озера, Keycloak client secret. Нет примеров `bi`/`bi`.
- HAProxy уже есть на платформе (`HAProxy.install.md`, если есть).
- SSO Keycloak/AD. Admin — break-glass.
- NTP на всех узлах.

### Установка (ЦОД-1, пакеты)

Порядок (этапы, не замена sysadm-guide 12.x):

1. ОС из матрицы, sysctl/диски, NTP.
2. Consul кворум → Patroni → `patronictl list` → HAProxy к лидеру.
3. NATS с TLS/учётками → KeyDB с паролем.
4. appserver → web за HAProxy.
5. Закрыть дефолты: антибрут (`max_login_attempts = 0` в 9.2 — **выкл**, включить), `rpmlimit`, bind KeyDB.
6. Витрина озера JDBC/FDW, **не** госAPI. Один боевой атлас. RLS.
7. SSO + АРМ ИБ + журнал в SIEM/Wazuh.
8. Бэкап **ядра** Postgres (метаданные, права, дэшборды). Вендор в 9.2 намекал «WAL для аналитики не копить» — для **ядра BI** это слабо: витрины можно пересчитать, атласы — нет.

Если вендор в договоре дал контейнеры/чарты — следуйте **им**. Иначе честный план: Luxms на VM, в K8s только Ingress.

### Конфигурирование прода

| Слой | Правило |
|---|---|
| Сеть | 443 с SSO-сети; 5432/6379/4222/6222/Consul/1880 — не с пользовательского VLAN |
| Datagate исходящие | Только озеро/витрины, не подсеть интеграционного API |
| Выгрузки Excel | Запрет бесконтрольного на ПДн |
| Плагины/bi-magic | Ревью как свой код |
| SELinux/Mandat на Astra | Не выключать «чтобы встало» без ИБ |

Порты Java/web (8080, 8200, 8888, …): **сверить** с guide вашей 12.x — в 9.2 и 12.x NATS websocket пример делит номер **8888** с историческим BINS.

### Масштабирование (когда появятся цифры)

1. Люди → CPU web+БД, пул HAProxy, потолок лицензии сессий.
2. Тяжёлый JDBC → datagate и **источник**, не «ещё nginx».
3. Терабайты → MPP/озеро. На одном хосте вендор «обычно до **100 активных**» — репер, не BOM.

### Проверка прода (пока это не пройдено — это не прод)

1. `patronictl list`, NATS cluster без demo `no_tls`, KeyDB с ACL.
2. Убить один web: LB жив. Switchover Patroni: клиенты через VIP.
3. Restore ядра на стенде.
4. Учение «ЦОД-1 выключен»: promote в ЦОД-2 по runbook. Учение «озеро недоступно»: UI жив, дэши пустые — ожидаемо.
5. Нет `bi`/`bi`, нет NATS example-паролей `"x"`/`"y"`.

### Сильные / слабые стороны прод-схемы (мозг в одном ЦОДе + DR)

| Сильное | Слабое |
|---|---|
| Кворум Consul/Postgres предсказуем | Падение ЦОДа мозга = нет BI для всех |
| Реестр РФ, пакетный путь вендора | 12.x ≠ сертифицированная таблица 11.0.x |
| Короткий путь Nginx→БД | Ядро = Postgres: дыра в SQL = дыра во всём BI |
| | Нет публичного Helm; самописный чарт — ваш split-brain |

**Не готов к проду**, если: один хост «как тест» на три ЦОДа; три web без Patroni; `bi`/`bi` или NATS `no_tls`; 12.x там, где обязали ФСТЭК 11.0.x; BI ходит в госAPI; эталон клиентов только в датасете Luxms; Consul растянут на 3 ЦОДа; restore ядра не делали; лицензия «2 сервера» а узлов пять; ждут замену Kafka/Camunda/Grafana; выдуманный docker-compose как «официальный прод».
