# OpenSearch 3.8.0 — термины и сокращения

Словарь к файлу `OpenSearch.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа: память и открытые файлы. Нода OpenSearch — один процесс JVM. Несколько процессов с одним `cluster.name` считают себя одной системой.

**Файл / каталог на диске** — то, что остаётся после рестарта. Шарды индекса лежат на диске data-ноды. Официально: **не сетевая ФС** как хранилище ноды в проде. Snapshot — во внешнем репозитории (S3 / shared FS), не на PVC одной ноды.

**TCP-порт** — номер в сети. REST/HTTP **9200**, transport нода↔нода **9300**, Dashboards **5601**, Performance Analyzer **9600**. UDP нет. Порт 443 в таблице вендора относится к Amazon OpenSearch Service, не к self-hosted.

**ЦОД** — отдельная площадка. Stretch = один кластер, процессы в нескольких ЦОДах, общаются по **9300**.

**RTT** — время туда-обратно. Порога в мс нет. Cluster state и копирование шардов ходят по 9300. Мерить 9300, не ICMP ping.

**TLS** — шифрование байтов в сети. Transport TLS на 9300 для Security plugin **обязателен**. HTTP TLS на 9200 в настройках plugin **по умолчанию выключен** (`plugins.security.ssl.http.enabled`, default `false`) — в проде включают явно. JDK TLS, не ГОСТ/СКЗИ.

**Под (Pod)** — контейнер(ы) Kubernetes. Data и cluster manager — отдельные node pool, PVC RWO на каждую ноду.

**PVC / RWO** — том только одному поду. Data-нода без него теряет индекс при рестарте.

**emptyDir** — диск «пока жив под». Для data-нод в проде это потеря данных. У оператора при emptyDir для upgrade требуют `general.drainDataNodes: true`.

**NFS** — вендор против NFS как *диска ноды*. Snapshot-репозиторий типа `fs` — другой случай: путь, доступный **всем** нодам.

**Helm / оператор** — OpenSearch Kubernetes Operator (целевой путь прода) и Helm-чарты `opensearch` / `opensearch-dashboards` (appVersion 3.8.0). Оператор: rolling upgrade, TLS, расширение томов.

**Кластер** — несколько процессов OpenSearch: общее имя, общее состояние, общие индексы.

**Нода (node)** — один процесс OpenSearch. Роли можно разделять или совмещать.

**Cluster manager** — нода, которая ведёт *состояние кластера*: кто жив, какие индексы есть, где лежат шарды. Раньше это называли master. Выбирается голосованием eligible-нод. На неё внешний клиентский трафик не посылают.

**Cluster-manager-eligible** — нода, которая *может* стать cluster manager. Не все eligible обязаны быть dedicated. Dedicated: `node.roles: [ cluster_manager ]`, боевые индексы на них не кладут.

**Кворум** — большинство eligible-нод. Для 3 cluster manager большинство = 2. Если живых меньше — кластер **не выбирает** manager: создание индексов, аллокация шардов, стабильная запись под вопросом. Формулировка вендора «never loses quorum» = при потере **одной** зоны из трёх, не двух.

**Data-нода** — хранит шарды на диске, индексирует и ищет. Основной диск/RAM. Роли на старте часто `[ data, ingest ]`.

**Ingest-нода** — гоняет документ через pipeline *до* записи в индекс (разбор JSON, grok, enrich). Можно совмещать с data.

**Coordinating-нода** — принимает запрос клиента, раздаёт его по шардам, склеивает ответ. У каждой ноды эта роль есть по умолчанию; *dedicated* — когда `node.roles: []`. Клиентов направляют: ingest → coordinating → data.

**Индекс** — именованный набор документов. Схема гибче таблицы СУБД; это не PostgreSQL.

**Документ** — одна JSON-запись в индексе.

**Шард (shard)** — кусок индекса на диске. Параллелизм хранения и поиска = шарды.

**Primary shard** — «главный» кусок. Число primary задаётся **при создании** индекса; потом только re-index в новый индекс. Дефолт OSS: **1** primary.

**Replica shard** — копия primary на другой ноде. Число replica можно менять позже. Дефолт: **1** replica (две копии, не три). На три ЦОДа «по копии в каждый» нужно **2 replica** (итого 3 копии). На single-node replica ставят 0: копию некуда положить.

**Green / yellow / red** — здоровье кластера. Green — все primary и replica на месте. Yellow — все primary есть, части replica нет (поиск ещё идёт). Red — не хватает primary: часть данных недоступна.

**Zone / shard allocation awareness** — OpenSearch старается не класть primary и replica одного шарда в одну зону (`node.attr.zone` + `cluster.routing.allocation.awareness.attributes: zone`).

**Forced awareness** — replica **никогда** не поселяется в ту же зону, что primary. Если зона умерла, кластер остаётся yellow и **не** перекладывает копии в оставшиеся зоны (чтобы не убить их диском).

**Discovery / seed hosts** — список адресов, куда нода стучится при старте, чтобы найти cluster manager. Без него мультинодовый кластер не соберётся.

**cluster.initial_cluster_manager_nodes** — список имён нод для **первого** bootstrap кластера. Нужен один раз, одинаковый на всех eligible. Ошибка = два кластера с разными UUID. После bootstrap новые manager присоединяются, а не бутстрапят второй.

**`discovery.type=single-node`** — обходит нормальный discovery. Только dev/test.

**Transport** — внутренний протокол нода↔нода. Порт **9300**. Балансировщик «как один VIP на 9300 всех нод» ломает модель. Балансировщик HTTP перед 9200 допустим.

**REST / HTTP** — API для клиентов. Порт **9200**.

**Security plugin** — встроенный модуль: TLS, пользователи, роли, аудит. В дистрибутиве OpenSearch он есть.

**Demo certificates** — комплект самоподписанных сертификатов «чтобы завелось». Документация: для прода **небезопасны**, общеизвестны. `plugins.security.allow_unsafe_democertificates: true` помечен как unsafe.

**OPENSEARCH_INITIAL_ADMIN_PASSWORD** — с версии **2.12** при demo-конфиге нужен свой пароль `admin`. Слабый пароль → процесс **не стартует**.

**securityadmin.sh** — утилита, которой заливают/снимают конфиг Security plugin (роли, внутренние пользователи). Ходит на **HTTPS 9200**, нужен admin-сертификат из `plugins.security.authcz.admin_dn`. Правка `roles.yml` на одной ноде сама не разъедется, если выключен `allow_default_init_securityindex`.

**ISM** — Index State Management: через N дней сжать / перенести / удалить индекс. Без этого диск съедят данные сами.

**Hot-warm** — `node.attr.temp` + ISM: горячий индекс на одних нодах, остывший на других. Включать после понимания, какие индексы остывают.

**Snapshot / repository** — бэкап индексов во внешнее хранилище (S3-совместимое, shared FS, HDFS). Реплики шардов **не** заменяют snapshot: не спасают от `DELETE index` и от гибели всех копий. В **3.8.0** дефолт `server_side_encryption_type` сменился на **AES256**; если MinIO отвергает заголовок — явно `bucket_default`.

**CCR (cross-cluster replication)** — плагин: follower-кластер **тянет** индекс с leader по 9300. Follower **read-only**. Это два кластера, не один stretch. Промоушен follower в leader — отдельная процедура. Плагин на обоих кластерах; Security plugin — либо включён на обоих, либо выключен на обоих.

**OpenSearch Dashboards** — веб-UI. Порт **5601**. Stateless относительно данных кластера. Отдельный документ.

**Data Prepper** — отдельная программа проекта: принимает логи/трейсы, ковертирует, пишет в кластер. **Не** плагин и **не** входит в пакет «поставил OpenSearch».

**Performance Analyzer** — плагин метрик ноды, порт **9600**. Это не Prometheus из коробки.

**JVM heap (`-Xms` / `-Xmx`)** — куча Java-процесса. Официально: примерно **половина RAM** машины/пода, `Xms = Xmx`. Остальная RAM — кэш файлов ОС (Lucene читает сегменты с диска через mmap). Дефолт процесса **1g/1g**. Процентные `-XX:MaxRAMPercentage` **перебиваются** этим дефолтом. Лимит Kubernetes должен быть **выше** кучи.

**vm.max_map_count** — лимит ядра Linux на число mmap. Официально **≥ 262144**, иначе нода падает. Даже в Docker значение ставится **на хосте**. Ещё: swap лучше выключить; `bootstrap.memory_lock=true` + `memlock` unlimited; `nofile ≥ 65536`.

**Stretch-кластер** — один логический кластер, ноды физически в нескольких ЦОДах.

**RPO / RTO** — сколько данных готовы потерять / как быстро восстановиться.

**Java** — линия 3.6.1+: совместимы **21, 25, 26**; в бандле на момент таблицы — **25.0.4+7**. Свой JDK — `OPENSEARCH_JAVA_HOME` / `JAVA_HOME`.

**DISABLE_SECURITY_PLUGIN** — в docker-примерах для лаборатории. В проде plugin включают.

**DISABLE_INSTALL_DEMO_CONFIG** — в проде `true`.

**Dual-mode SSL** (`plugins.security_config.ssl_dual_mode_enabled`) — только на время миграции.

**`enforce_hostname_verification`** — проверка имени в сертификате на 9300. Выключать «чтобы завелось» нельзя считать продом.

**disk watermark** — порог заполнения диска, после которого аллокация шардов останавливается. Сигнал в файле, не смета PVC.

**bulk** — пакетная запись многих документов одним HTTP-запросом. Не мелкие одиночные POST.

**Index template** — шаблон shards, replica, mapping, refresh **до** первого документа. Primary потом дешево не поменять.

**`_id`** — идентификатор документа. Явный `_id` даёт идемпотентность ingest из Kafka.

**Wazuh indexer** — отдельный OpenSearch-совместимый кластер SIEM. Склеивать с бизнес-поиском в одном RBAC нельзя.

**Amazon OpenSearch Service** — облако AWS, другие манифесты. Не этот файл.

**SoT** — OpenSearch не источник истины клиентов. Near-real-time, нет ACID как в PostgreSQL. Копия для поиска ≠ SoT.

**Image tag `latest`** — не брать. Прод: **3.8.0** на нодах и Dashboards, major не смешивать.

**PDB** — не снять сразу два manager или слишком много data одной зоны.

**Rolling upgrade оператора** — ждёт **green** после каждой ноды. Жёлтый кластер из-за forced awareness во время аварии зоны **остановит** выкат.

**G↔Gi** — не менять unit диска без бэкапа: оператор может пересоздать VolumeClaimTemplates.

**Apache 2.0** — лицензия OSS. License-server нет.

Источники формулировок: глоссарий и тело `OpenSearch.md`. Новых порогов RTT и размеров диска здесь нет.
