# Docker Engine 24.0.9 — установка и конфигурирование

Связанный документ (глоссарий, Swarm vs Kubernetes, сокет = root, почему так): `Docker 24.md`.

Этот файл — **как поставить и настроить**. Не копируйте Dev-значения в прод. Stretch одного Swarm на несколько ЦОДов **не делаем**: межЦОДовый RTT для Raft manager'ов неприемлем, и Swarm **не** является прод-путём этой платформы.

Версия: **Docker Engine 24.0.9** (последний патч линии 24.0, релиз 31 января 2024).  
Линия **unmaintained**: security-поддержка 24.0 закончилась **8 июня 2024**; после 24.0.9 патчей нет. BuildKit CVE, о которых вендор писал в релиз-нотах 24.0.9, **этой сборкой не закрыты** (фикс — Engine 25.0.2+).  
Документация линии: https://docs.docker.com/engine/release-notes/24.0/

**Честно:** 24.0.9 — не безопасный runtime прод-кластера в 2026 году. Dev — локальный Compose. Прод Kubernetes использует **containerd**, не `dockerd` как CRI. Если линию всё же ставят — только на **builder-VM**, не на worker'ы.

---

## Допущения этой инструкции

Их не было в исходном контексте платформы; без них нельзя дать конкретные команды.

1. **Stretch запрещён.** Один Swarm на 2–3 ЦОДа не поднимаем. Overlay/Raft между площадками не обещаем.
2. Прод-оркестратор — **vanilla Kubernetes 1.36.x + kubeadm** в каждом ЦОДе отдельно (`Kubernetes.install.md`). CRI — **containerd**. Engine 24 **не** ставится на worker'ы.
3. Если 24.0.9 всё же фиксируют письменно — роль: стенд разработчика и **сборочные VM**. Не Kafka, не Camunda, не озеро.
4. Dev — изолированная сеть; пароль в примере не секрет.
5. Нагрузки нет — нет числа builder-VM и размера `/var/lib/docker`.
6. Пакеты Docker Inc. того времени (`docker-ce` 24.0.9), не `docker.io` дистрибутива «какой apt назвал docker», не Docker Desktop, не static tarball в прод.
7. Для 2 ЦОДов: builder хотя бы в двух площадках. Для 3 — лучше по одному в каждом. Общего Raft между ними нет и не нужно.

## Dev: 1 ЦОД, без нагрузки

**Цель:** `docker build`, Compose (Postgres/Redis рядом с сервисом), отладка Dockerfile. **Не** цель: HA, Swarm, эмуляция Kubernetes.

### Предпосылки

- Linux 64-bit (или Dev-машина с Docker Engine, не путать с Desktop как «тем же продом»).
- Порты стенда не торчат в интернет.
- Ядро с overlay, cgroup; диск под `/var/lib/docker` **локальный**, не NFS.
- Свободен Unix-сокет; **2375 не слушать**.

### Установка

Пакеты линии **24.0.9** (репозиторий Docker Inc. того времени / зеркало). Static tarball вендор **не** рекомендует в прод — и на Dev лучше пакеты, чтобы зависимости (containerd/runc) были явными. После установки:

```bash
docker version
# Client/Server: 24.0.9  — не «24.0 какой скачается»
# API демона линии 24.0 = 1.43; в бандле 24.0.9: runc 1.1.12, containerd часто 1.7.13 — сверять docker info
```

`daemon.json` (`/etc/docker/daemon.json`) — смысл из соседнего файла, не «весь мануал»:

```json
{
  "live-restore": true,
  "storage-driver": "overlay2",
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "icc": false,
  "no-new-privileges": true
}
```

Затем `systemctl restart docker`. Swarm **не** включать: `live-restore` со Swarm несовместим.

Проверка Compose (плагин той же поставки CE):

```bash
docker compose version
docker run --rm --network none hello-world
```

Привязка опубликованных портов — к `127.0.0.1`, не `-p 5432:5432` на все интерфейсы.

### Конфигурирование Dev

| Параметр | Значение | Зачем |
|---|---|---|
| Один `dockerd` | да | Некому строить кворум |
| Swarm | нет | Иначе нельзя live-restore; это не прод-путь |
| API | только Unix-сокет | 2375 = удалённый root |
| `icc: false` | да | Default bridge без лишней связности; Compose сам сделает user-defined сеть |
| Ротация `json-file` | 10m × 3 | У драйвера **нет** max-size по умолчанию |
| Experimental containerd store | **нет** | В 24.0 это experiment |
| `--privileged` / проброс сокета в сервисы | запрещены | Привычка уедет в CI |

Чего **не** упрощать в Dockerfile/Compose: `USER` не root; лимиты памяти; секреты не в Git; тег образа ≠ `:latest`.

### Проверка Dev

1. `docker version` = 24.0.9 с обеих сторон.
2. Compose поднимает сервис; рестарт `dockerd` при `live-restore` не убивает долгоживущий контейнер.
3. `ss`/`netstat`: нет слушателя `0.0.0.0:2375`.
4. Образ, который потом уедет в Kubernetes, собирается здесь и пушится в **staging-реестр**, не только «на ноутбуке есть».

### Сильные / слабые стороны Dev

| Сильное | Слабое |
|---|---|
| Часы, официальный Compose | Падение VM = простой стенда |
| Те же OCI-образы, что потом в Kubernetes | Не ловит CRI, CNI, Swarm Raft, 2376 |
| | Успешный Compose **не** доказывает прод |
| | 24.0.9 приучает CI к линии без патчей |

Препрод-сборка: отдельный хост с **тем же** `daemon.json`, что у builder'ов, push в тот же класс реестра.

## Prod: 2 или 3 ЦОДа, без stretch, нагрузка возможна

**Цель:** собирать образы и пушить в реестр, переживая отказ **одной builder-машины / одного ЦОДа со сборкой**. Runtime приложений — Kubernetes + containerd. Цифр «ядер под сборку» нет — ниже минимум независимости хостов, не смета.

### Почему не stretch и почему не Swarm

Swarm Raft на manager'ах — тот же класс риска, что etcd. Порога RTT в документации Docker **нет**. Платформа уже выбрала Kubernetes. Второй оркестратор (вариант D соседнего файла) и `dockerd` как CRI через cri-dockerd (вариант E) **не берём**: лишний hop, root-демон на каждой ноде, EOL Engine под kubelet 1.36.

Целевой макророль соседнего файла — **вариант C**: Engine только на CI/builder.

### Топология

На **нодах Kubernetes** Engine **нет**. CRI = containerd (`Kubernetes.install.md`).

**Builder-хосты** — независимые `dockerd`, без общего кворума:

| Площадок | Что где | Отказ ЦОД-1 |
|---|---|---|
| **2 ЦОДа** | ЦОД-1 и ЦОД-2: ≥1 builder каждый; общий **реестр** (HA реестра — другой продукт) | Сборка уходит на живую площадку. Выкат приложений зависит от Kubernetes и реестра, не от Docker |
| **3 ЦОДа** | По builder'у в каждом (минимум два из трёх живы) | То же |

Не склеивать builder'ы Swarm «чтобы было HA»: для сборки это лишние 2377/7946/4789 между ЦОДами.

Если 24.0.9 на builder всё же ставят — понимать: **vendor-security линии нет**. Компенсации (минимум пакетов, нет 2375, свой реестр, сканер образов) **не заменяют** патчи. ИБ может запретить 24 — и будет права. Письменно: исключение с датой вывода **или** уход на поддерживаемый Engine (на дату соседнего файла живая линия — 29.x). Смена линии **не отменяет** правило «не dockerd как CRI».

### Предпосылки прода

- Kubernetes в каждом ЦОДе; на worker'ах **нет** `dockerd`.
- Реестр организации; с прод-сети Docker Hub запрещён.
- Локальный SSD/NVMe под `/var/lib/docker`. **Не NFS.**
- NTP/chrony. `daemon.json` из git, одинаковый на всех builder'ах.
- Секреты сборки — не в демоне «как получится»; сокет не в CI-подах.

### Установка (каждый builder)

1. Пакеты **24.0.9** (если линия зафиксирована) или поддерживаемый Engine — по письменному решению из шага 0.
2. Тот же `daemon.json`, что на Dev, плюс явно: **нет** `-H tcp://0.0.0.0:2375`. Удалённо — только SSH (`DOCKER_HOST=ssh://…`) или mTLS **2376**, если удальное управление доказано необходимым.
3. `live-restore: true` — если на хосте есть долгоживущие helper-контейнеры. Чистый ephemeral-builder может без него.
4. Группа `docker` — поимённо, не «все разработчики».
5. Мониторинг заполнения `/var/lib/docker` и inode. Prune — по политике, не слепой `docker system prune -a` по cron.

Не ставить Engine рядом с kubelet на той же ноде: iptables Docker vs CNI.

Безопасность каждого builder (без этого хост дырявый):

1. Зафиксировать письменно: 24.0.9 — исключение с датой вывода **или** уход на поддерживаемый Engine. Без пункта 1 vendor-security **нет**.
2. API только Unix-сокет. Группа `docker` поимённо.
3. Не монтировать `/var/run/docker.sock` в job-поды. DinD — изолированная VM, не сокет хоста.
4. Не `unconfined` seccomp, не `--privileged` без тикета. `no-new-privileges` уже в `daemon.json`.
5. Исходящий pull — только реестр организации. BuildKit CVE 2024 на 24.0.9 **не закрыты** — это цитата релиз-нотов, не гипотеза.

### Конфигурирование builder (смысл, не полный unit)

| Параметр | Прод | Зачем |
|---|---|---|
| `storage-driver` | overlay2 | Дефолт 24.x на Linux; containerd store в 24.0 — experiment |
| `log-opts` max-size | обязательны | Иначе диск убивает хост |
| 2375 | никогда | Удалённый root |
| Сокет в контейнерах CI | нет | DinD/socket = побег на хост |
| `--privileged` сборок | нет на общем пуле | Исключение с тикетом |
| seccomp / AppArmor | не `unconfined` | «Чтобы завелось» — дыра |
| Content Trust | если ИБ требует | Не замена сканера CVE |
| Данные озера/Kafka | не в writable layer | Слой — для кода |

`userland-proxy`: дефолт true. На хосте с кучей `-p` часто ставят `false` — только поняв nft/iptables **этого** хоста.

### Масштабирование (когда появятся цифры)

1. Сборка упирается в CPU, диск слоёв, сеть до реестра. Горизонталь = **ещё независимые builder'ы**, не «один docker на 128 ядер» как единственная стратегия.
2. Лимиты памяти на контейнеры сборки: без них job съест хост.
3. Параллелизм CI ограничивать очередью, не надеждой на 24.0.
4. Кэш слоёв важнее «одного огромного Docker»; HA — у реестра.

### Проверка прода (пока это не пройдено — это не прод)

1. На worker Kubernetes: `crictl`/`containerd`, **нет** `dockerd` как CRI.
2. `docker version` на builder = зафиксированная версия.
3. Нет слушателя 2375. Попытка pull с Hub из прод-сети — отказ.
4. Убить один builder: очередь CI берёт другой; приложения в Kubernetes живы.
5. Алерт на заполнение `/var/lib/docker` срабатывает на стенде до боя.
6. Сокет не смонтирован в пайплайн-поды.

### Сильные / слабые стороны (builders only, без Swarm)

| Сильное | Слабое |
|---|---|
| Не спорит с Kubernetes и с etcd | Сам Engine не даёт HA приложений — и не должен |
| Падение builder'а не роняет бизнес-поды | Нужен живой реестр |
| Можно снять 24.0.9, не трогая кластер | Линия без патчей; BuildKit CVE 24.0.9 не закрыты |
| Нет Raft между ЦОДами | N копий `daemon.json` разъедутся без git |

**Не готов к проду**, если: 24.0.9 на worker'ах Kubernetes, открыт 2375, группа `docker` у отдела, сокет в CI-подах, Swarm и kubelet на одних нодах, Swarm «на 2–3 ЦОДа», `latest` с Hub, NFS как `/var/lib/docker`, нет ротации логов, cri-dockerd «потому что привыкли к docker ps».
