# Kubernetes 1.36.4 — термины и сокращения

Словарь к файлу `Kubernetes.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в ОС: память, открытые файлы, сетевые сокеты. На ноде Kubernetes прикладной код почти всегда бежит внутри контейнера, а не как «голый» systemd-сервис.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. Состояние кластера Kubernetes лежит не в файлах приложения, а в etcd. Данные Kafka/БД лежат в томах CSI, не в etcd.

**TCP-порт** — номер, по которому другие процессы находят этот в сети. kube-apiserver слушает **6443** (TLS). Health check балансировщика перед HA control plane — TCP до 6443.

**ЦОД** — отдельная площадка с серверами (своё питание, своя сеть). «Три ЦОДа» в тексте — три такие площадки. Три зала с общим UPS — ложные «три ЦОДа».

**RTT** — время туда-обратно по сети (запрос ушёл, ответ пришёл). Запись в etcd не быстрее репликации на большинство членов. Порога RTT в документации проекта Kubernetes нет.

**TLS** — шифрование байтов в сети. kubeadm включает TLS для API и etcd. Выключить проверку сертификатов «чтобы завелось» в проде нельзя.

**PKI** — набор сертификатов и ключей: CA кластера, apiserver, etcd, kubelet. kubeadm генерирует этот набор. По умолчанию сертификаты kubeadm живут **1 год**.

**CA** — удостоверяющий центр кластера: им подписывают сертификаты компонентов. Не корпоративный IdP.

**CVE** — опубликованная запись об ошибке безопасности в конкретном ПО.

**EOL** — дата, после которой авторы линейки не выпускают исправления. Ориентир линий Kubernetes: https://kubernetes.io/releases/.

**GA** — общедоступный релиз. **RC** — кандидат в релиз. В прод не берут RC. На дату файла тега v1.37.0 ещё нет (`v1.37.0-rc.1`).

**SIG Release** — группа проекта, которая ведёт календарь релизов. 1.37.0 в календаре стоит на 26 августа 2026.

**ОС** — в этой архитектуре Linux на нодах. Windows-ноды не закладывают.

**CRI (Container Runtime Interface)** — API, по которому kubelet говорит рантайму «создай/убей контейнер». Docker-shim убран. Нужен containerd или CRI-O. CRI должен работать **до** `kubeadm init`.

**containerd / CRI-O** — реализации CRI. В допущениях файла CRI — containerd. CRI-O допустим; на правила HA это не влияет.

**OCI-образ** — неизменяемый шаблон файловой системы + метаданные для контейнера. Ноды тянут его из реестра.

**Контейнер** — изолированный процесс из OCI-образа (namespaces + cgroups). Сам Kubernetes контейнеры не запускает — это делает runtime.

**cgroup** — лимит памяти/CPU, который ядро (и Kubernetes) ставит на контейнер.

**OOM** — процесс убит, потому что кончилась память cgroup/машины.

**Нода (node)** — машина (физическая или VM), на которой крутится kubelet. Бывает control-plane и worker.

**kubelet** — агент на каждой ноде: следит, чтобы назначенные поды реально бежали. kubelet **нельзя** новее apiserver; можно отстать до **3** minor.

**Кластер** — набор машин, которыми управляет один control plane. «Один Kubernetes» = один кластер. Три независимых Kubernetes — **три** кластера.

**Control plane** — API, планировщик, контроллеры, etcd. Без него уже запущенные поды обычно продолжают работать, но нельзя деплоить, масштабировать и переносить упавшие поды.

**kube-apiserver** — единственная точка входа в API кластера. Всё управление идёт через его HTTP API (обычно порт 6443, TLS). Клиенты ходят на ControlPlaneEndpoint, не на «первый master».

**etcd** — распределённое key-value хранилище **состояния кластера** (какие Deployment есть, какие поды должны быть, Secrets). Это не озеро данных и не Kafka. Линия kubeadm 1.36 использует etcd **3.6.x**; точный патч образа — `kubeadm config images list`.

**Ключ-значение (key-value)** — хранение записей «имя → байты». etcd так держит объекты API.

**Raft** — протокол согласия, на котором etcd выбирает лидера и реплицирует запись. Каждая успешная запись должна быть подтверждена большинством. Дефолты etcd: heartbeat **100 ms**, election timeout **1000 ms**; election timeout должен быть **не меньше 10× RTT**.

**Heartbeat / election timeout** — интервалы Raft: «лидер ещё жив» и «пора выбирать нового лидера». Если RTT «плавает» или пакеты теряются, начинаются выборы лидера, API таймаутится.

**Кворум (quorum)** — большинство голосов etcd. Для 3 членов большинство = 2. Если живых меньше большинства, etcd **перестаёт принимать запись**. Чтобы пережить N одновременных отказов членов, нужно 2N+1. Три etcd → одного члена. Пять → двоих. Потеря двух ЦОДов при трёх членах etcd кворум, как правило, убивает.

**Лидер etcd** — член, который принимает запись. Остальные подтверждают по Raft.

**Stacked etcd** — etcd живёт **на тех же** машинах, что и API-сервер. Дефолт kubeadm. Падение ноды бьёт сразу по API и по голосу etcd. Документированный минимум HA: stacked 3.

**External etcd** — etcd на **отдельных** машинах. Минимум ещё 3 хоста. Отказ API-сервера не снимает голос etcd. Сеть CP↔etcd тоже критична.

**kube-scheduler** — решает, на какую ноду положить новый под (ресурсы, зоны, taint/toleration, affinity).

**kube-controller-manager** — набор контроллеров: «хотели 3 реплики — сейчас 2 — создать ещё одну».

**Контроллер / оператор** — процесс, который смотрит объекты API и приводит фактические процессы к описанному виду.

**Желаемое состояние** — то, что записано в API («5 реплик»). Контроллер догоняет факт.

**kubectl** — CLI к apiserver. Ставится отдельно, на машины администраторов.

**kubeadm** — официальный путь проекта для HA-установки. Запрещает skip minor даже на одном apiserver. Порядок апгрейда: apiserver → controller-manager/scheduler → kubelet (с drain).

**kubeconfig** — файл с адресом API, сертификатами/токеном. `admin.conf` с cluster-admin — не рабочий процесс на 50 человек.

**kube-proxy** — реализует Service на ноде (обычно iptables/ipvs). Иногда его заменяет CNI вроде Cilium.

**Под (Pod)** — минимальная единица запуска: один или несколько контейнеров с общим network namespace. Поды смертны: Kubernetes имеет право их убить и создать заново на другой ноде. IP пода меняется.

**Network namespace** — изоляция сетевого стека: у пода свой IP, свои интерфейсы. Контейнеры одного пода его делят.

**Реплика** — ещё один под того же контроллера. Число реплик само по себе не создаёт репликацию данных на диске.

**Deployment** — контроллер для stateless-подов: заданное число реплик, rolling update.

**StatefulSet** — контроллер для подов с стабильным именем и PVC на реплику (`volumeClaimTemplates`).

**DaemonSet** — по одному поду на подходящую ноду (агенты).

**Job (Kubernetes)** — набор подов, который должен завершиться успешно заданное число раз. Не джоб GitLab CI.

**ConfigMap** — объект API с несекретной конфигурацией. Огромные ConfigMap раздувают etcd.

**Secret** — объект API с секретом. Без `--encryption-provider-config` API-сервер кладёт ресурсы в etcd **открытым текстом**. В API Secret выглядит как base64; в etcd по умолчанию plaintext. TLS к API от этого не спасает.

**Service** — стабильный виртуальный IP/DNS на набор подов. Поды умирают и меняют IP — Service остаётся.

**ClusterIP / NodePort / LoadBalancer** — типы Service: внутренний VIP / порт на нодах / внешний IP. На железе в ЦОДе «просто LoadBalancer» не появится без MetalLB, BGP или внешнего ADC.

**MetalLB** — реализация LoadBalancer на железе (часто BGP к маршрутизаторам).

**BGP** — протокол анонса маршрутов. Нужен, чтобы VIP сервиса стал достижим в сети ЦОДа.

**ADC** — внешний балансировщик площадки (отдельное ПО).

**DNS кластера** — в типичной установке kubeadm это **CoreDNS** (аддон, не ядро API). Без DNS сервисы по имени не резолвятся.

**Ingress / Gateway API** — объекты API для входа HTTP(S) снаружи. Не часть ядра исполнения: нужен отдельный контроллер. Gateway API — более новый стандарт, Ingress — старый, всё ещё живой.

**CNI (Container Network Interface)** — плагин сети подов. Без него кластер после kubeadm **не умеет** нормально запускать поды. Kubernetes сеть «из коробки» не даёт.

**Cilium / Calico** — примеры CNI. Конкретный продукт — решение сети/ИБ. CNI **обязан** реализовывать NetworkPolicy, иначе объекты политики ничего не режут.

**Overlay (VXLAN / Geneve)** — инкапсуляция пакетов подов в UDP поверх L3. Между ЦОДами добавляет латентность и проблемы MTU. Для прямых соединений брокер–брокер Kafka плохая подложка.

**MTU** — максимальный размер пакета без фрагментации. Overlay его уменьшает.

**CIDR** — диапазон IP (pod CIDR, service CIDR). Не «чуть подкрутить CIDR», если неверна топология ЦОДов.

**CSI (Container Storage Interface)** — плагин дисков. Kubernetes только **заказывает** том. Репликация диска — задача СХД/CSI, не kube-scheduler.

**PersistentVolume (PV)** — объект «вот диск такого размера/класса». **PVC** — заявка пода «дай том». PV/PVC переживают перезапуск пода. **Не** переживают потерю ноды, если том локальный и репликации нет.

**StorageClass** — «какой диск дать»: локальный NVMe, сетевой, с репликацией, в какой зоне.

**WaitForFirstConsumer** — диск создаётся **после** выбора ноды. Нужен, чтобы том не оказался в ЦОДе A, а под — в ЦОДе B.

**RWO** — том монтируется на запись одним подом. Типичный режим для etcd и БД.

**NFS** — сетевая файловая система. Для диска etcd **нельзя**: etcd пишет в Raft-лог каждый коммит; медленный fsync = ложные выборы лидера.

**fsync** — вызов ОС «запиши буфер на диск сейчас». Для etcd нужен локальный SSD/NVMe, низкий хвост fsync. Ориентир документации etcd для нагруженных контуров: **500 sequential IOPS**. Типичная память члена **8 ГиБ** (тяжелее — 16–64). Это отправная точка, не замер вашего кластера.

**emptyDir / hostPath / local-path-provisioner** — локальные тома для теста. emptyDir умирает вместе с подом.

**Квота etcd** — размер БД метаданных. Дефолт **2 ГиБ**, рекомендуемый максимум для обычных сред — **8 ГиБ** (выше — предупреждение при старте). Это не озеро. Компакция и дефрагментация — регулярная операция.

**Namespace** — логическая папка в одном кластере (права, квоты, NetworkPolicy). Это **не** изоляция уровня ЦОДа и не отдельный Kubernetes.

**RBAC** — кто какие API-вызовы может делать (`get pods`, `create secrets`, …). Сервисный аккаунт приложения — не человек. Приложениям не дают `cluster-admin`.

**least privilege** — выдавать только те API-глаголы и ресурсы, без которых процесс не работает.

**ServiceAccount** — учётка пода для обращения к API. Токен монтируется в под.

**Pod Security Admission (PSA)** — встроенный фильтр: какие поды вообще можно создать. Три профиля: **Privileged** / **Baseline** / **Restricted**. Для прикладных namespace — `restricted` или как минимум `baseline`; `privileged` только kube-system и оговорённым операторам (CSI, CNI).

**PSP (PodSecurityPolicy)** — старый внешний механизм. Давно убрали; PSA его заменяет.

**NetworkPolicy** — firewall между подами. **Работает только если CNI это умеет.** Объект в API без поддержки CNI — декорация. В проде: default-deny в namespace, затем DNS, свои зависимости.

**Taint / Toleration** — «на эту ноду обычные поды не пускать» / «этому поду можно». Control plane по умолчанию tainted.

**Affinity / topologySpreadConstraints** — правила «положи рядом» / «размажь по зонам». Без них все реплики могут сесть в один ЦОД.

**Anti-affinity** — не класть два указанных пода на одну машину.

**topology.kubernetes.io/zone** — стандартный ярлык зоны (в файле — id ЦОДа). Scheduler и CSI на него опираются. Без ярлыка scheduler не знает ЦОДы.

**PDB (PodDisruptionBudget)** — «не убивай сразу две реплики при drain». Защита от **добровольных** снятий (обновление ноды), не от падения ЦОДа.

**drain** — штатно выселить поды с ноды перед обслуживанием. Drain нод по одной зоне/ЦОДу, не параллельно все три.

**eviction** — снятие пода планировщиком/kubelet (диск, память, PDB).

**HPA (Horizontal Pod Autoscaler)** — больше/меньше подов по метрикам. Нужен источник метрик. Для Kafka/БД «просто добавь под» не увеличивает партиции и не создаёт реплики данных.

**Metrics Server** — аддон, отдающий CPU/RAM подов для HPA. **Не** часть kubeadm.

**Prometheus Adapter** — адаптер своих метрик Prometheus в API HPA. Отдельное ПО.

**Cluster Autoscaler / Cluster API** — добавление **нод**, не подов. Отдельные проекты. Без возможности заказать VM «из воздуха» autoscaler бесполезен.

**requests / limits** — заявка и потолок CPU/RAM пода. Без requests под — BestEffort, его выкинут первыми. `resources.requests` на тесте не упрощают.

**BestEffort / Burstable / Guaranteed** — QoS-классы по наличию requests/limits.

**ControlPlaneEndpoint** — DNS/IP балансировщика **перед** несколькими kube-apiserver. Без него HA control plane по kubeadm не собирают. Один VIP в одном ЦОДе = скрытый SPOF.

**SPOF** — единственная точка, отказ которой роняет функцию (часто не etcd, а один HAProxy в одном шкафу).

**Skew (version skew)** — насколько версии компонентов могут отличаться. kubelet нельзя новее apiserver; отставание kubelet — до 3 minor. Skip minor для kube-apiserver проект **запрещает**.

**Stretch-кластер** — один Kubernetes, ноды физически в нескольких ЦОДах, **один** etcd-кворум растянут между ними. Документация etcd: члены по возможности в одном ЦОДе. Stretch — гипотеза, пока RTT и потери не измерены.

**Partition (сеть)** — разрыв связности. «1 ЦОД vs 2» изолирует меньшинство: локальный API в меньшинстве не запишет в etcd.

**RPO** — сколько данных готовы потерять при аварии. **RTO** — за сколько времени снова начать принимать запросы. Для etcd это состояние кластера; данные Kafka/БД — **другой** RPO. Формального SLA / RPO / RTO в контексте нет.

**HA (high availability)** — пережить отказ машины/процесса без ручного «поднять сервер с нуля». Конкретные цифры времени файл не обещает.

**Failover / switchover** — аварийная / плановая смена роли. В самом etcd смена лидера — часть Raft; смены «кластера на другой Kubernetes» оператор не делает.

**Бэкап etcd** — снимок, с которого можно поднять состояние API независимо от живых членов. Без проверки восстановления отказ кворума = сбор кластера заново.

**Encryption at rest / EncryptionConfiguration** — шифрование объектов в etcd. Включать **до** боевых секретов, затем `replace` существующих Secret, чтобы перешифровать.

**KMSv2** — провайдер шифрования через внешний KMS/HSM/Vault-plugin. Рекомендация Kubernetes 1.36. Если KMS недоступен, API может не расшифровать.

**KMSv1** — старый провайдер. Deprecated с 1.28, disabled by default с 1.29. Не использовать.

**aesgcm** — локальный ключ на диске control plane. Нет KMS на старте. Ключ не в Git; нужна ротация.

**identity** — провайдер «не шифровать». Дефолт. В проде нельзя.

**Audit log** — журнал apiserver: кто читал Secret и менял RBAC.

**OIDC** — вход людей через корпоративный IdP (токен, не общий `admin.conf`).

**IdP** — сервер учётных записей (Keycloak, Entra, …).

**Anonymous** — запросы без учётки. Не оставлять «мир может list'ить».

**admission-webhook (OPA / Kyverno)** — внешний фильтр создания объектов. Отдельное ПО и свой HA. Не входит в ядро.

**hostNetwork** — под использует сеть ноды. Без нужды запрещать.

**privileged** — почти все ограничения контейнера сняты. На тесте уже не оставлять без нужды.

**Image tag `latest`** — ярлык, который завтра укажет на другой патч. В проде пинят digest/патч. Образы — свой registry; `registry.k8s.io` из закрытого контура может быть недоступен.

**Harbor / Quay** — корпоративный реестр образов. Не часть Kubernetes.

**GitOps (Argo CD / Flux)** — синхронизация манифестов из Git в кластер(а). Сам Kubernetes не синхронизирует три control plane.

**Helm / чарт** — шаблон установки набора манифестов.

**swap** — выгрузка страниц на диск. Выключить или корректно настроить по текущим требованиям kubeadm/kubelet.

**NTP / chrony** — синхронизация часов. Рассинхрон ломает TLS и путает таймауты Raft.

**QPS** — запросов в секунду (к apiserver). Нагрузки в контексте нет — нет числа worker-нод «хватит для прода».

**page cache** — кэш файлов в RAM ноды. Лимиты подов должны оставлять память kubelet и page cache (для Kafka разобрано в его файле).

**ГОСТ TLS / СКЗИ** — сертифицированная криптография. В Kubernetes не входит. Если требование ИБ — отдельный контур.

**152-ФЗ / КИИ** — требования к персональным данным и критической инфраструктуре. Меняют PKI, допустимость Docker Hub, KMS/HSM, аудит.

**vanilla Kubernetes** — «чистый» проект + kubeadm, не RKE2/Talos/OpenShift. Дистрибутивы не отменяют кворум etcd, зоны и RBAC.

**kind / k3d / minikube** — однокластерные стенды для разработки. Успешный тест на kind не доказывает готовность прода.

**Препрод** — маленькая копия прод-топологии control plane (3 stacked или 3+3 external) даже без боевой нагрузки.

**Вариант A (stretch)** — один кластер, ноды во всех трёх ЦОДах, etcd 1+1+1 (или 2+2+1). Пока RTT не измерен, честно выбрать нельзя.

**Вариант B** — три независимых кластера (по одному в ЦОДе). etcd каждого не растянут. Консервативный прод при неизвестной сети.

**blast radius** — какая доля системы падает от одной ошибки/апгрейда. В stretch один баг control plane бьёт все три ЦОДа.

**Пул нод** — taint + dedicated: `control-plane`, `platform` (Kafka, тяжёлые БД), `general`, при необходимости `ingress` / `integration-dmz`.

**SoT (source of truth)** — место, откуда система считает текущее состояние правдой. Kubernetes не SoT клиентских данных: в etcd только «как должна выглядеть система».

Источники формулировок: глоссарий и тело `Kubernetes.md`. Новых порогов RTT и размеров диска здесь нет.
