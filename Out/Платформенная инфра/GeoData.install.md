# GeoData 4.0.1 / workflow 4.0.2 — установка и конфигурирование

Связанный документ (глоссарий, ОПО/ППО, пересечение с Camunda/Kafka, почему так): `GeoData.md`.

Этот файл — **как поставить и настроить**. Не копируйте Dev-значения в прод. Stretch кластера GeoData на несколько ЦОДов **не делаем** и **не выдумываем**: публичный инсталлятор — один логический `dc0`; глава «Аварийные ситуации» / «Среда развертывания ППО» с портала **не была загружена**. Пока вендор не подписал мульти-DC схему — честный прод = **один ЦОД + backup/restore**.

Продукт: on-premise платформа ООО «АйТи Гео». Модули **4.0.1**, **workflow 4.0.2** (руководство администратора на docs.datageo.ru). Публичного changelog «август 2026» нет — пиним **опубликованное руководство**.  
Документация: https://docs.datageo.ru/ · продукт: https://datageo.ru/

Поставка ППО: **`docker load` tar.gz → реестр (Nexus 3.49.0 в таблице ОПО) → `kubectl apply`**. Официального Helm «GeoData на любой Kubernetes» нет.

## Допущения этой инструкции

Их не было в исходном контексте платформы; без них нельзя дать конкретные команды.

1. **Stretch запрещён.** Cassandra/Kafka/ZK/ES/Swift из инсталлятора не размазываем по ЦОДам. SimpleStrategy RF=2 и `region 1 zone 1` — схема **одной площадки**, не «пережили ЦОД».
2. On-premise дистрибутив, не SaaS datageo.ru.
3. Платформенный Kubernetes — **1.36.x** (`Kubernetes.install.md`). В доке GeoData — **Kubernetes 1.24.1**. Совместимость манифестов **не заявлена** — это **критический пробел**, не «наверное заведётся». До письма вендора: отдельный кластер поддерживаемой версии **или** поставка стопорится.
4. Платформенные Kafka 4.3.1, Camunda 8.9, Swift/object storage — **соседние** продукты. Не подставлять их молча вместо ОПО GeoData (Kafka **3.4.0 + ZooKeeper**, Elasticsearch **8.6.2**, Swift **2.29.2**), пока вендор письменно не разрешит замену.
5. Роль: **А** (гео-ETL) или **Б** (процессы + госинтеграции), не оба сразу с Camunda и своим Integration API.
6. Dev — изолированная сеть. Нагрузки нет.
7. Keycloak: в главе установки дерево **`keycloak-21.1.2`**; строка «3.4» в сводной таблице — расхождение доки, закрывать с вендором.
8. Для 2 ЦОДов: актив в ЦОД-1, ЦОД-2 — restore по методике вендора. Для 3 — то же + вторая копия бэкапа. Третий `dc` в Cassandra **не** добавляем сами.

## Dev: 1 ЦОД, без нагрузки

**Цель:** аналитик собирает процесс, понятен язык платформы, коннекторы. **Не** цель: отказ ЦОДа и терабайты PostGIS.

### Предпосылки

- Дистрибутив `Distr/Apps/` (tar.gz, yaml, `setup*.sh`). Публичного Docker Hub нет.
- Kubernetes, который **подтвердит вендор** для этой поставки (не считать 1.36 доказанным).
- DNS/FQDN, Ubuntu 22.04 в инструкции ОПО (Debian-подобные — с оговоркой вендора).
- Браузер с WebGL 1.0 (Chrome ≥ 81 / Яндекс ≥ 76 / …).

### Установка

Порядок вендора **не переставлять**:

1. ОПО по руководству (Cassandra → Elasticsearch → … → Redis). Версии таблицы: Cassandra **4.1.0**, Kafka **3.4.0** + ZK, ES **8.6.2**, PostgreSQL **15.2** + PostGIS **3.3**, Redis **7.0.8**, Swift **2.29.2**, Nexus **3.49.0**. Пропуск шага — только если тот же продукт той же мажорной линии уже есть **и** вендор разрешил.
2. Keycloak: реалм, клиент `oauth.clientid` (в примере `workflowprod`).
3. Nexus (или согласованный registry): 

```bash
docker load -i <модуль>.tar.gz
docker tag … <registry>/…:4.0.1   # workflow: 4.0.2
docker push …
```

4. Namespace, Service/LB, манифесты из дистрибутива: `kubectl apply -f …`
5. На тесте реплики ППО **1**, не копировать `<replicas>/3`. Модули: `clientui`, `adminui`, `workflow` (**4.0.2**), `geometry`, `bpmncryptopro`, `timejobexecutor`, `timeeventhandler`, `statistic` (**4.0.1**).
6. Критерий вендора «система жива»: стартовая страница **модуля аналитика** после логина.

Служебные топики Kafka инсталлятора (это **не** ваши `client.updated`): `jobtimeeventtopicprod`, `timeeventtopicprod`, `tokentoexecute`, `workflowlogs`, `workflowtokenstatus`, `statistictopic`, `filestorageactiontopic`, `audittopics`. В инструкции RF=2, 50 партиций; `offsets.topic.replication.factor=3`. На одноброкерном стенде — только RF=1 и пометка «песочница».

Сжать ОПО относительно прода можно, но не в самодельный compose «всего», если вендор такого профиля не дал. Cassandra: 3 узла лучше 1 (иначе не видно RF=2); 1 узел и RF=1 — только с пометкой «песочница, не кластер».

Пример вендора `protected-mode no` и `xpack.security.enabled: false` — **только** изолированный стенд; лучше сразу пароль Redis/ES, чтобы привычка не уехала.

### Конфигурирование Dev

| Параметр | Значение | Зачем |
|---|---|---|
| Реплики ППО | 1 | Нет HA |
| RF Cassandra/Kafka | 1 на крошечном стенде | Некому реплицировать |
| КриптоПро | заглушка/тест УЦ, если юристы разрешат | Иначе стенд встанет на СКЗИ |
| СМЭВ | тестовый контур или мок | Промконтур на тесте часто запрещён |
| AI Network | выкл | Утечка датасетов в LLM |
| Свой Kafka 4.3 / OpenSearch | не подменять ОПО | Нет протокола совместимости |

Чего **не** упрощать: имена внутренних топиков и keyspace `workflow_schema`; OIDC через Keycloak; отдельный Postgres для PostGIS; экспорт/импорт процессов zip по методике вендора (папка **без** вложенных папок).

Секреты из текста инструкции и `docker commit` properties **не** переносить как норму — даже на тесте лучше Secret, если yaml это переживёт; иначе зафиксировать долг.

### Проверка Dev

1. adminui открывается, логин через Keycloak. Модули 4.0.1 / workflow 4.0.2.
2. Один процесс доходит до шага; geometry ходит в PostGIS, не в Cassandra.
3. Успешный ETL **не** доказывает RF=2, 50 партиций и падение Keycloak.

### Сильные / слабые стороны Dev

| Сильное | Слабое |
|---|---|
| Близко к реальной поставке (load → registry → apply) | Не ловит rebalance Kafka, split Cassandra, латентность PostGIS |
| Дешевле трёх ЦОДов; можно выбрать роль А/Б | ES без xpack с теста утащат копипастой |
| | Совместимость yaml 1.24 с платформой 1.36 **не** проверена |

Препрод: уменьшенная **односайтовая** копия инструкции (3 Cassandra, 3 Kafka, 3 ES, 3 реплики ППО, RF как в мануале) уже с TLS и секретами не в образе.

## Prod: 2 или 3 ЦОДа, без stretch, нагрузка возможна

**Цель:** поставить то, что вендор умеет описать: устойчивость **внутри одной площадки** (3 узла ОПО, 3 реплики ППО). Отказ ЦОДа — **DR по вендорскому backup/restore**, не самодельный NetworkTopologyStrategy «как в блогах Cassandra». Цифр RPO/RTO вендор в загруженных главах **не даёт** — мерить после runbook.

### Почему не stretch и почему не выдумываем HA

Инсталлятор: Cassandra `dc0`, keyspace **SimpleStrategy RF=2**; Kafka без rack, топики RF=2; Swift пример — 3 IP в одном region/zone; Redis и PostgreSQL и Keycloak — **по одному** хосту. «3 реплики Deployment» ≠ 3 ЦОДа. Доработка RF/DC/Sentinel без письма вендора = серая схема, этот файл её не собирает.

Вариант P2 соседнего файла (stretch ОПО) **не выбран**.

### Топология

**Активный ЦОД-1** — следование инсталлятору, ужесточение дыр примера:

- ППО: реплики **≥ 3** как в инструкции, anti-affinity **внутри** ЦОДа, PDB, не `emptyDir` для состояния;
- ОПО: минимумы вендора (Cassandra ≥ 3 узлов **на этот** ЦОД; Kafka 3 + ZK; ES 3 master+data; Swift RF=3 на узлах **этой** зоны);
- Redis / Postgres+PostGIS / Keycloak — в инструкции одиночки. Для прода **даже в одном ЦОДе** одиночка Postgres для geometry — SPOF: поднять HA **внутри ЦОДа** только если вендор подтвердит клиентский URL (сейчас `geodatapostgresX`). Пока нет письма — принять SPOF и компенсировать бэкапом, не молча подставить CNPG 18.6 вместо 15.2;
- HAProxy 2.4 + Keepalived 2.2.4 в матрице ОПО; линейка 2.4 старше актуального LTS вашего `HAProxy.install.md` — что ставить, решает совместимость yaml GeoData.

**Между ЦОДами — только DR:**

| Площадок | Что где | Отказ ЦОД-1 |
|---|---|---|
| **2 ЦОДа** | ЦОД-1: полный ОПО+ППО. ЦОД-2: копии бэкапов Cassandra / Postgres / Swift (+ ES snapshot) и процедура вендора; ППО не член того же Raft/кольца | Простой до restore. RPO > 0 |
| **3 ЦОДа** | Вторая копия бэкапа в ЦОД-3 или холодный контур | То же; не три `dc` в одном keyspace |

Не дублировать слепо:

| Уже есть на платформе | У GeoData своё | Правило |
|---|---|---|
| Kafka 4.3.1 KRaft | Kafka 3.4.0 + ZooKeeper, свои топики (`tokentoexecute`, …) | Отдельный кластер, пока нет письма |
| Camunda 8.9 | свой `workflow` BPMN | Один контур заявок, не два движка «на всякий случай» |
| Object storage / Swift платформы | Swift 2.29.2 в инсталляторе | Не NFS «вместо»; не подмена MinIO без вендора |
| OpenSearch 3.8 | Elasticsearch 8.6.2 | Не смешивать с поиском платформы и Wazuh |
| PostgreSQL 18.6 | 15.2 + PostGIS 3.3 | Версия ОПО — из таблицы GeoData, пока вендор не скажет иначе |

### Предпосылки прода

- Письмо вендора **до** договора: Kubernetes (1.24 vs **1.36**); типовая схема на 2–3 ЦОДа (RF/DC names, Redis, Postgres); можно ли заменить ES→OpenSearch, Kafka 3.4→4.3 KRaft, Swift→MinIO, Nexus→Harbor; как класть секреты без `docker commit`; обязательность КриптоПро; RPO/RTO и глава «Аварийные ситуации»; кто закрывает CVE ОПО между релизами GeoData; как лицензируется Elasticsearch 8.6.2. Пока ответов нет — честная формулировка для руководства: отказоустойчивость «как у трёх ЦОДов» из публичной доки **не следует**.
- Пока совместимость 1.36 не подтверждена — **нельзя** честно накатить yaml Distr на платформенный кластер.
- SMTP, исходящий контур только к согласованным ведомствам/API.
- Роль А или Б зафиксирована. Вариант «и Camunda, и workflow, и Integration API» — запрещён по умолчанию.

### Установка (ЦОД-1)

1. Закрыть пробел Kubernetes письмом. Не начинать прод на 1.36 «на глаз».
2. ОПО строго по руководству, версии пинить. **Включить** то, что в примере выключено: ES security; Redis bind/protected-mode; TLS к Cassandra/Kafka/ES/Postgres/Keycloak/Swift/Ingress.
3. Nexus с нормальным TLS, не `storepass password` из примера.
4. `docker load` → tag **4.0.1 / 4.0.2** → push → `kubectl apply`.
5. Properties: пароли **не** из мануала и по возможности **не** в слое образа (`docker commit` — слабое место поставки; цель — Secret, если вендор поддержит).
6. Проверка: логин аналитика. Затем zip-перенос процессов по методике.

Restore в ЦОД-2 — **тот же** порядок ОПО+ППО на холодном контуре, данные из вендорского бэкапа. Без прогона на препроде нет RTO.

### Конфигурирование

| Параметр | Прод | Зачем |
|---|---|---|
| SimpleStrategy RF=2 на 3 ЦОДа | не расширять самим | Нет инструкции |
| Внутренние топики на Kafka 4.3 | нет | Другой протокол/операционка |
| `xpack.security.enabled: false` | запрещён | Индекс задач открыт |
| `mail.smtp.ssl.trust=*` | нет | Любой сертификат SMTP |
| Секреты в образе | долг/запрет | Ротация = пересборка |
| NetworkPolicy | UI→workflow/Keycloak; workflow→ОПО; egress — список | Иначе СМЭВ «гуляет» |
| AI Network | не в минимальном контуре | GPU/промпты — отдельный проект |

ЭП: КриптоПро — отдельный контур ИБ, не чинит plaintext ОПО.

### Масштабирование (когда появятся цифры)

1. UI — горизонталь подов, упирается в `workflow` и Keycloak.
2. `geometry` — CPU подов **и** PostGIS, не «ещё clientui».
3. Объём файлов — Swift, не PVC пода. Терабайты контуров — диск PostGIS.
4. Минимумы ОПО (8 ГиБ / 100 ГБ на узел Cassandra и т.д.) — «чтобы кластер считался кластером», не смета нагрузки.

### Проверка прода (пока это не пройдено — это не прод)

1. Модули 4.0.1 / workflow 4.0.2; ОПО тех версий, что в таблице.
2. Убить 1 под `workflow` внутри ЦОД-1 — UI жив, **если** состояние в Cassandra/Redis.
3. Restore Cassandra+Postgres+Swift на стенде ЦОД-2 по вендору (дочитать главу аварий, когда загрузится). Самодельный failover «переключили DNS» без этого — не прод.
4. ES с аутентификацией; Redis не `protected-mode no`; нет паролей мануала в registry.
5. Архитектура: нет второго BPMN-контура на те же заявки без решения.
6. Манифесты 1.24 на 1.36 либо сертифицированы письмом, либо крутятся на отдельном кластере.

### Сильные / слабые стороны (один ЦОД + вендорский DR)

| Сильное | Слабое |
|---|---|
| Совпадает с публичным инсталлятором | Потеря ЦОД-1 = простой до restore |
| Не выдумываем мульти-DC RF | Redis/Postgres/Keycloak в мануале — SPOF |
| Реестр отечественного ПО | Стек ОПО (K8s 1.24, Kafka 3.4+ZK, ES 8.6.2) рядом с платформой 2026 = два мира патчей |
| | Совместимость с Kubernetes 1.36 **не заявлена** |
| | Dual-run с Camunda/своим API размоет истину заявки |

**Не готов к проду**, если: yaml 1.24 накатили на 1.36 без письма; stretch Cassandra/Kafka «потому что три ЦОДа»; внутренние топики на платформенном Kafka 4.3; второй workflow рядом с Camunda на те же госуслуги; ES без security; секреты в образе как единственный путь; нет прогнанного restore; нет решения роли А vs Б.
