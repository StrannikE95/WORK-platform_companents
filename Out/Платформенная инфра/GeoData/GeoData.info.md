# GeoData — термины и сокращения

Словарь к файлу `GeoData.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа. Экземпляр GeoData — набор контейнеров ППО плюс процессы ОПО (Cassandra, Kafka, Elasticsearch, PostgreSQL, Redis, Swift, Keycloak). Интерпретатор платформы выполняет команды аналитика пошагово: если он упал — текущие шаги процесса не идут.

**Файл / каталог на диске** — состояние процессов в Cassandra (`workflow_schema`), геометрия в PostgreSQL/PostGIS, файлы/PDF в Swift. Не в `emptyDir` пода Kubernetes.

**TCP-порт / VIP** — вход UI через LB-сервисы (`adminui-lb`, `clientui-lb`, `workflow-lb`, `geometry-lb`, `bpmncryptopro-lb`). В матрице ОПО — HAProxy **2.4** и Keepalived **2.2.4**. Пример VIP 192.168.10.20x — из инструкции вендора, не ваш план адресации.

**ЦОД** — отдельная площадка. Инсталлятор GeoData написан вокруг **одного** `dc0`. «Упал один из трёх ЦОДов — GeoData жива» публичным текстом не доказано. Страница «Среда развертывания ППО» и глава «Аварийные ситуации» с портала **не были загружены** (таймаут).

**RTT** — время туда-обратно. Для stretch Cassandra/Kafka неизвестный RTT может убить латентность записи. Пока нет замера — stretch не обещать.

**TLS** — шифрование каналов ОПО. Пример вендора с plaintext JDBC / `http://` Keycloak — только лаборатория. Подпись документов КриптоПро ≠ шифрование канала Cassandra/Kafka/ES. ГОСТ TLS на всех каналах ОПО не заявлен.

**Low-code** — большую часть интеграций и процессов собирают в графическом редакторе. Код всё равно есть: «русскоязычные команды» встроенного интерпретатора.

**Интерпретатор** — программа, которая пошагово выполняет команды языка платформы.

**BPMN 2.0** — стандартная схема бизнес-процесса (блоки, стрелки, шлюзы). GeoData исполняет модели **своим** движком `workflow`, это **не** Camunda. Два BPMN-движка = два места правды по заявкам.

**Модель процесса / экземпляр** — модель — схема («как должно быть»). Экземпляр — один конкретный прогон (одна заявка, один ETL-запуск). Есть реестр моделей, версий и исполняемых экземпляров.

**ППО** — прикладное ПО самой GeoData: контейнеры `clientui`, `adminui`, `workflow` и остальные модули из дистрибутива. Образы публичного Docker Hub нет: `Distr/Apps/`, tar.gz, yaml, скрипты `setup*.sh`. Версии в руководстве: clientui / adminui / timejobexecutor / bpmncryptopro / timeeventhandler / geometry / statistic — **4.0.1**, workflow — **4.0.2**. Публичного changelog «последний релиз на август 2026» у вендора нет.

**ОПО** — общесистемное ПО, без которого ППО не стартует. Вендор фиксирует версии. ОС в инструкции: **Ubuntu 22.04 LTS** (Debian-подобные с оговоркой).

**Модуль аналитика (`adminui`)** — веб-UI, в котором проектируют процессы, источники, формы, права. nginx + JS. В примере вендора Deployment **3** реплики, Service/LB `adminui-lb`. Вендор определяет «система жива» так: в браузере открывается стартовая страница модуля аналитика после логина.

**Модуль исполнителя (`clientui`)** — веб-UI для тех, кто выполняет задачи процесса. То же масштабирование, `clientui-lb`.

**`workflow`** — сервер исполнения процессов. Образ **4.0.2**, `workflow-lb`. UI ходит в `workflow` и в Keycloak.

**`geometry`** — сервер пространственных операций (пересечения, буферы, контуры). JDBC в **PostgreSQL/PostGIS**. Тяжёлые пересечения полигонов не лечатся «ещё одним clientui».

**`bpmncryptopro`** — подпись электронных документов через **КриптоПро** (СКЗИ). Без лицензии/носителей ЭП это не «просто Java».

**`timejobexecutor` / `timeeventhandler`** — задачи по расписанию и постановка следующих шагов процесса во времени. Реплики есть, отдельный LB в таблице IP **не** указан.

**`statistic`** — сбор статистики исполнения (Kafka + Elasticsearch). Отдельный `setupstat.properties`. Продюсер в примере: `acks=all`.

**Датасет** — массив разнородных данных, который платформа загружает, валидирует, обогащает. В маркетинге и в патенте — центральная сущность.

**Источник данных** — подключение, которое аналитик заводит в UI: СУБД, очередь, API. Не путать с «озером эталона» вашей архитектуры. По руководству пользователя: PostgreSQL, MongoDB, Cassandra, MS SQL, Oracle, Elasticsearch; очереди Kafka и RabbitMQ. Готовые модули на сайте: ФИАС, Росреестр, СМЭВ 3.0, Яндекс, Почта РФ. В кейсах: PostGIS, geojson, PBF, XML, XLSX, REST, ЕГРН, DaData.

**СМЭВ 3.0** — система межведомственного электронного взаимодействия. Адаптер в GeoData — **клиент** к ней, не замена вашего интеграционного контура целиком, пока вы так не решите. HA GeoData не лечит ночь, когда ведомство не отвечает.

**ФИАС / ЕГРН / Росреестр** — федеральная адресная система / реестр недвижимости / ведомство. Вендор заявляет готовые модули.

**PostGIS** — расширение PostgreSQL для геометрии (точки, полигоны, пространственные индексы). «Таблица с контурами зданий» обычно живёт здесь. Версия в таблице вендора: **3.3**. PostgreSQL **15.2**. В инструкции один сервер; минимум 4 ГБ RAM / 2 ГБ диска — «чтобы поставилось», не терабайты геометрии.

**Cassandra** — распределённая СУБД без классических SQL-транзакций «как в Postgres». В GeoData — схема исполнения процессов (`workflow_schema`). Версия **4.1.0**. Вендор: минимум **3 узла на каждый ЦОД**, от 8 ГБ RAM и 100 ГБ диска на узел (100 ГБ — пол тестовый). Аутентификация (роль `dba` и т.д.) в проде не выключать.

**Фактор репликации (RF)** — сколько копий данных. RF=2 значит две копии. При трёх ЦОДах RF=2 **не раскладывает** по копии на каждый ЦОД. Служебные топики Kafka инсталлятор создаёт с RF=2, 50 партиций. `offsets.topic.replication.factor=3`. Swift в тексте — RF=3.

**SimpleStrategy / NetworkTopologyStrategy** — стратегии репликации Cassandra. SimpleStrategy **не знает** про ЦОДы. NetworkTopologyStrategy знает (`dc0: 3` = три копии в логическом ЦОДе `dc0`). Инсталлятор: `system_auth` через NetworkTopologyStrategy `dc0: 2`; рабочий keyspace **SimpleStrategy RF=2**. Для мульти-DC keyspace процессов **не оставлять** SimpleStrategy RF=2.

**ZooKeeper** — отдельный кворум для Kafka **3.x**. В Apache Kafka 4.x его уже нет (KRaft). Вендор GeoData ставит **Kafka 3.4.0 + ZooKeeper**. Минимум 3 узла; 4 ядра / 8 ГБ / 100 ГБ на узел (цифра вендора). Kafka без rack в инсталляторе. Платформенный Kafka 4.3.1 и Kafka 3.4.0 GeoData — **разные кластеры**, пока вендор письменно не подтвердит работу клиентов 4.0.x против вашего брокера.

**KRaft** — режим Kafka без ZooKeeper (ваша платформенная линия 4.x). Не backend GeoData из коробки.

**Служебные топики Kafka** — внутренность GeoData, не ваши `client.updated`: `jobtimeeventtopicprod`, `timeeventtopicprod`, `tokentoexecute`, `workflowlogs`, `workflowtokenstatus`, `statistictopic`, `filestorageactiontopic`, `audittopics` (в тексте инструкции строка команды на этом топике обрезана, имя указано). 50 партиций — запас параллелизма внутри GeoData.

**Elasticsearch 8.6.2** — поиск/индекс экземпляров (`jobinstance` в примере statistic). Рекомендуется 3 узла; 8 ГБ / 100 ГБ; имя кластера в примере `smartgeoelcluster`; роли `[data, master]`. Zone awareness в процитированном фрагменте **не задан**. В примере **`xpack.security.enabled: false`**. Не смешивать с вашим OpenSearch и с Wazuh indexer. ES 8.x — не Apache 2.0 как OpenSearch; EULA юристы смотрят до «поставим ES рядом». Снапшоты индекса — во внешнее хранилище; реплики шардов бэкапом не являются.

**Redis 7.0.8** (в главе установки — «Redis 7.0») — кэш/оперативные структуры. В примере конфига **один** хост. Минимум 4 ядра / 4 ГБ / 20 ГБ. Пример: `#bind 127.0.0.1` и `protected-mode no`. Sentinel/Cluster в инструкции нет = **SPOF**. Клиенты ППО сейчас понимают один `redis.host` — доработка вендора для кластера. Глубину деградации `workflow` при потере Redis вендор в загруженных главах не расписал.

**Swift (OpenStack Swift 2.29.2)** — объектное хранилище файлов, PDF, вложений. RF=3, «рекомендуется 5 узлов, RF не больше числа узлов»; пример колец добавляет **3** IP в одном region/zone. Не NFS вместо Swift, если вендор ждал Swift API.

**Keycloak** — сервер логинов (OAuth/OIDC). UI пускает по логину/паролю через него. В сводной таблице указано **3.4**; в главе установки каталог **`keycloak-21.1.2`**, Java **OpenJDK 11**, 2 ядра / 4 ГБ / 250 ГБ. Версии в двух главах не совпадают — закрывать с вендором. Допущение файла: 21.1.2 важнее строки «3.4». Клиент в примере `oauth.clientid` = `workflowprod`. Для прода — внешняя БД + реплики / infinispan, не один JVM.

**Nexus Repository 3.49.0** — реестр Docker-образов дистрибутива. Образы ППО пушат сюда, Kubernetes забирает отсюда. TLS-сертификат docker `certs.d`. Не `storepass password` из примера.

**HAProxy + Keepalived** — балансировщик HTTP/TCP + плавающий VIP. Версии в матрице ОПО: **2.4 / 2.2.4**. Линейка 2.4 у GeoData **старше**, чем актуальный LTS в отдельном документе HAProxy; что ставить — совместимость с yaml GeoData. Детальный текст установки в выгрузке «Операций» не попал.

**Replica (Kubernetes)** — сколько одинаковых подов модуля. В примерах вендора для ППО подставляют **3**. Три пода на одной ноде/в одном ЦОДе — это не три ЦОДа. На тесте — по 1 реплике, не копировать `<replicas>/3`.

**onCloud / onPremise** — облако вендора vs установка у вас. Для контура с гособменом обычно on-premise. Фраза «специальные действия по установке на стороне пользователя не требуются» — про **SaaS**, не про ваш Kubernetes.

**ЭП / СКЗИ / КриптоПро** — электронная подпись / средство криптозащиты / сертифицированный продукт. Модуль `bpmncryptopro` на этом стоит. Отключаемость модуля без вендора не подтверждаем.

**AI Network** — надстройка: локальные LLM, YandexGPT/GigaChat, RAG, MCP, Telegram-боты. В главе установки ОПО/ППО её нет. GPU, исходящие API, данные в промптах. В минимальный контур не входит.

**RPO / RTO** — сколько данных готовы потерять / как быстро восстановиться. Вендор в загруженных главах **цифр не даёт**. Вариант P1: RPO > 0, RTO измеряется часами, пока не отрепетируете.

**Stretch** — один логический кластер, железки в нескольких ЦОДах. Для Cassandra/Kafka свой набор правил.

**Kubernetes 1.24.1** — версия в доке вендора. Совместимость манифестов с вашим 1.36.x **не заявлена**. Дистрибутив: `docker load` tar.gz → Nexus → `kubectl apply` yaml. Официального Helm «GeoData на любой Kubernetes 1.36» нет.

**application-dit.properties** — конфиг ППО. В инструкции зашивают в файл и **вшивают в образ** (`docker cp` + `docker commit`) перед push в Nexus. Слой образа хранит секрет. Ротация пароля = пересборка образа.

**SPOF** — единственная точка отказа. В инструкции Redis, PostgreSQL (`geodatapostgresX`), Keycloak (`geodatakcX`) — по одному серверу.

**ISR** — in-sync replicas Kafka. Смотреть ISR < RF на внутренних топиках.

**acks=all** — продюсер ждёт подтверждения всех ISR (у statistic в примере уже есть).

**min.ISR** — минимум синхронных реплик. Для P2 цель файла (если вендор согласится): RF=3, min.ISR=2, rack=ЦОД.

**Message Bus** — логический компонент из патента **RU 2790038** (описание способа, не инсталлятор). Совпадает с тем, что продают: ядро управления данными, моделирование, BPM обработки, BPM документооборота, бизнес-аналитика, Message Bus.

**Реестр отечественного ПО № 17166** — запись от 03.04.2023. Свидетельство ЭВМ **№ 2023612186** от 31.01.2023. Вендор: ООО «АйТи Гео» (IT Geo), docs.datageo.ru.

**WebGL 1.0** — нужен браузеру клиента. Chrome ≥ 81, Яндекс.Браузер ≥ 76, Opera ≥ 12, Safari ≥ 13.

**SMTP** — уведомления. Пример `mail.smtp.ssl.trust=*` — доверять любому сертификату SMTP.

**RBAC прикладного уровня** — раздел «Безопасность» в UI: разрешения до папки процесса, задачи, формы; субъекты — пользователь, позиция, подразделение, атрибут. Не замена NetworkPolicy и TLS ОПО.

**NetworkPolicy / PDB / topologySpreadConstraints** — изоляция egress (СМЭВ, Почта РФ, Яндекс), не убить все `workflow` при drain, размазать реплики по `topology.kubernetes.io/zone`.

**Patroni** — HA PostgreSQL (не из коробки GeoData). Stretch sync на 3 ЦОДа без замера RTT нельзя.

**Вариант А (роль продукта)** — узкий: пространственный ETL + ГИС-слой. Озеро/сервисы отдают данные в GeoData; Kafka и интеграционный API остаются вашими.

**Вариант Б** — широкий: процесс + интеграции + гео. Camunda и «свой Integration API» тогда не дублируют тот же контур. В тексте прода файла заложен как гипотеза закупки.

**Вариант В** — запрещённый по умолчанию: и Camunda, и GeoData.workflow, и своё API, и озеро, и внутренние топики GeoData — четыре места правды заявки.

**P1** — один сайт активен, два других холодные/тёплые копии. Ближе к публичному инсталлятору. Пока вендор не подписал P2 — честный прод.

**P2** — stretch ОПО на 3 ЦОДа. Публичная инструкция этого **не собирает**. Cassandra NTS, по 3 узла на DC = уже **9** узлов; Kafka RF=3+rack; ES awareness; Swift разные zone=ЦОД; Redis Sentinel/Cluster; Postgres часто активен в одном ЦОДе с репликой; Keycloak не один JVM.

**Экспорт процессов** — zip по методике вендора: папка процессов **без** вложенных папок; связанные задачи/источники/файлы/формы попадают в архив по правилам. В экспорте уезжают источники и файлы — не «все могут экспортировать».

**OpenSearch 3.8 / MinIO / Harbor** — соседние продукты платформы. Замена ES→OS, Kafka 3.4→4.3 KRaft, Swift→MinIO, Nexus→Harbor **не обещана**. Замена без вендора = форк на вас.

**152-ФЗ / КИИ / ГОСТ / аттестованный контур** — персональные и кадастровые данные, ЭП, исходящие в коммерческие API (Яндекс, DaData). Меняет onCloud, логи ES без xpack, сегментацию.

Источники формулировок: глоссарий и тело `GeoData.md`. Новых порогов RTT и размеров диска здесь нет.
