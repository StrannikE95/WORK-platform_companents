# Docker Engine 24.0.9 — термины и сокращения

Словарь к файлу `Docker 24.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в ОС. На хосте с Docker главный процесс — демон `dockerd`; контейнеры — отдельные процессы ядра с namespaces и cgroups.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. У Engine данные хоста — `/var/lib/docker` и volumes **этого** хоста. Демон соседнего хоста их не знает.

**TCP-порт** — номер в сети. Демон по умолчанию слушает Unix-сокет, не TCP. **2375** — API без TLS (удалённый root). **2376** — API с TLS.

**ЦОД** — отдельная площадка с серверами. Три зала с общим питанием — ложные «три ЦОДа»; раскладка Swarm 1-1-1 тогда врёт так же, как etcd 1-1-1.

**RTT** — время туда-обратно по сети. Порога RTT для Swarm Raft в документации Docker нет. Stretch-swarm — гипотеза, пока сеть не замерена.

**TLS / mTLS** — шифрование канала; mTLS — оба конца показывают сертификат. Если удалённый API нужен — SSH (`DOCKER_HOST=ssh://…`) или mTLS на **2376**. Ключи 2376 = root-пароль.

**CVE** — запись об ошибке безопасности. В 24.0.9 runc поднят до **1.1.12** (в т.ч. CVE-2024-21626). Вендор явно пишет: известные CVE BuildKit **не закрыты**; фикс — Engine **25.0.2+**.

**EOL / Unmaintained** — линия больше не получает исправления. Ветка `24.0` в Moby помечена Unmaintained. На endoflife.date окончание security-поддержки 24.0 — **8 июня 2024**. После 24.0.9 патчей линии нет. Поддерживаемая линия Engine на дату файла — **29.x** (патч 29.7.2). Линия 25.0 с датой окончания **4 декабря 2026** — это **не** 24.0.

**ОС** — Linux 64-bit на серверах ЦОДа. Windows-контейнеры и Docker Desktop не рассматривают.

**Ядро Linux** — namespaces, cgroups, overlay, iptables/nft. Старый текст «ядро ≥ 3.10» относится к бинарной установке и не является сайзингом прода.

**namespaces / cgroups** — изоляция имён (PID, сеть, mount) и лимиты CPU/RAM. Контейнер — это они, плюс образ.

**OCI-образ (image)** — шаблон файловой системы + метаданные. Неизменяемый. Идентификатор — digest (sha256). Тег (`:latest`) — только ярлык.

**Digest** — хеш содержимого образа. В проде пинят digest или неизменяемый tag сборки, не `:latest`.

**Контейнер** — запущенный процесс из образа. Падение демона по умолчанию **убивает** контейнеры, если не включён live restore.

**Docker Engine (`dockerd`)** — демон на одной Linux-машине: принимает команды, тянет образы, запускает контейнеры. Это **не** кластер и не Kubernetes. Один `dockerd` = один хост.

**Docker CLI (`docker`)** — клиент. Ходит к демону через Unix-сокет (обычно `/var/run/docker.sock`) или по сети. Пакет `docker-ce-cli` в схеме Docker Inc.

**Engine API 1.43** — номер HTTP API демона линии 24.0, не «версия Docker».

**Unix-сокет** — файл-канал на той же машине. Кто может писать в `/var/run/docker.sock`, тот **управляет демоном**. Официально: это равносильно root на хосте (можно смонтировать `/` хоста в контейнер).

**Группа `docker`** — членство даёт доступ к сокету **без sudo**. Официальный post-install это включает и предупреждает: привилегированный доступ. Не раздавать всему отделу и не вешать AD-группу «все разработчики».

**`daemon.json`** — главный конфиг демона, на Linux обычно `/etc/docker/daemon.json`. Предпочтительнее флагов в unit-файле.

**data-root** — каталог данных демона (дефолт `/var/lib/docker`). Локальный SSD/NVMe. NFS как data-root — порча слоёв и зависания.

**Слой (layer) / overlay2** — драйвер хранения образов в 24.0: слои только для чтения + тонкий записываемый слой контейнера. Писать «в контейнер» как в постоянный диск нельзя; данные — в volume. Терабайты не кладут в writable layer overlay2.

**Volume** — каталог/диск, который Docker монтирует в контейнер и который переживает удаление контейнера. Это **не** репликация на другой хост. Падение хоста = потеря локального volume.

**Bind mount** — кусок ФС хоста внутрь контейнера. Контейнер видит (и может писать) то, что отдали.

**live restore** — контейнеры **не** убиваются, если упал/перезапустили `dockerd`. Только для **standalone**-контейнеров. Со **Swarm mode несовместим** (демон откажется инициализировать swarm). Не спасает от смерти машины и не всегда от `systemctl stop docker` с убийством cgroup.

**Swarm mode** — встроенный оркестратор Docker: сервисы, overlay-сеть, Raft у manager-нод. Включается `docker swarm init`. Это **конкурент Kubernetes**, не плагин к нему. В вашей схеме оркестратор уже Kubernetes.

**Manager / worker (Swarm)** — manager хранит состояние swarm (Raft) и планирует задачи. Worker только выполняет. Manager по умолчанию тоже может принимать задачи; в проде manager'ов `drain`, чтобы Raft не делил CPU с тяжёлой нагрузкой.

**Кворум Swarm** — большинство manager'ов. 1 manager → переживут 0 отказов; 3 → 1; 5 → 2. Потеря кворума: уже запущенные задачи живут, **управлять** swarm нельзя. Для 3 зон раскладка **1-1-1**, для пяти — **2-2-1**.

**Raft (Swarm)** — протокол согласия manager'ов. Запись подтверждает большинство. Больше manager'ов = хуже write состояния (больше round-trip Raft). Масштаб нагрузки — worker'ы, не «9 manager'ов».

**`--advertise-addr`** — адрес, который manager сообщает другим. У manager — **статический IP**. Если после ребута все manager'ы сменят IP, swarm зависает.

**`--force-new-cluster`** — аварийное восстановление кворума (`docker swarm init --force-new-cluster`). Это авария, не штатный failover.

**Overlay-сеть (Swarm)** — сеть контейнеров **между хостами** (VXLAN, UDP **4789** по умолчанию). Без swarm overlay для multi-host не поднять. Вендор: порт не на периметр; VXLAN без аутентификации.

**VXLAN** — инкапсуляция L2 в UDP. **MTU** — максимальный размер пакета; overlay его уменьшает.

**Порты Swarm (между нодами, не в интернет)** — TCP **2377** (управление / Raft); TCP и UDP **7946** (gossip / discovery overlay); UDP **4789** (VXLAN); IP protocol **50** (ESP), если overlay с `--opt encrypted`.

**ESP** — протокол IPsec для encrypted overlay. Штраф производительности надо мерить.

**gossip** — обмен состоянием нод overlay. Не Raft-журнал.

**Ingress routing mesh** — опубликованный порт сервиса слушается **на каждой** ноде swarm; трафик перекладывается на живую задачу. Это балансировка Docker, не HAProxy. Для тяжёлого трафика смотрят publish mode `host` + внешний балансировщик.

**bridge / host / none** — сети одного хоста. `bridge` — виртуальный свитч (`docker0`). `host` — контейнер в сети хоста (изоляция сети снята). `none` — без сети.

**user-defined bridge** — именованная сеть Compose: DNS между контейнерами по имени сервиса.

**`icc: false`** — контейнеры на default bridge не ходят друг к другу без явной сети. Для Compose всё равно создаётся user-defined сеть.

**BuildKit** — сборщик образов (с Engine 23.0 — по умолчанию). В **24.0.9** известные CVE BuildKit не закрыты.

**containerd** — runtime нижнего уровня. В статическом бандле 24.0.9 указан **v1.7.13**; в пакетной установке часто отдельный пакет — смотреть `docker info`.

**containerd image store** — в 24.0 **experimental**: хранить образы через containerd snapshotter вместо overlay2. В прод 24.0 не брать. (В Engine 29 на чистой установке стало дефолтом — другая линия.)

**runc** — низкоуровневый runtime, который реально создаёт контейнер. 24.0.9: **1.1.12**.

**CRI / dockershim / cri-dockerd** — Kubernetes говорит с runtime по CRI. Docker Engine CRI **не** реализует. dockershim убрали в Kubernetes **1.24**. Внешний адаптер — **cri-dockerd** (не часть Engine 24). Два демона (kubelet → cri-dockerd → dockerd) = лишний слой.

**Rootless mode** — `dockerd` от непривилегированного пользователя. Меньше ущерба при взломе демона, больше ограничений (порты <1024, часть сети, cgroup). Не «включил и забыл».

**userns-remap** — root внутри контейнера = обычный UID на хосте. Не включено по умолчанию. Ломает часть volume/privileged-сценариев. На builder'ах часто не включают из-за кэша/прав на артефакты.

**seccomp / AppArmor / SELinux** — профили ядра: какие системные вызовы и файлы можно. Docker по умолчанию даёт seccomp-профиль; AppArmor/SELinux — если дистрибутив их включил. `unconfined` / `--privileged` это снимает.

**`--privileged`** — почти все ограничения контейнера сняты. Для интеграционного контура — только если без этого физически нельзя, с объяснением ИБ.

**`no-new-privileges`** — запрет повышения привилегий через setuid.

**capabilities** — отдельные права Linux (NET_ADMIN и т.д.). В проде drop лишнего.

**read-only root FS** — корневая ФС контейнера только для чтения; запись — в volume.

**USER** — пользователь внутри образа. Не root: иначе в Kubernetes PSA `restricted` сломается.

**Content Trust / DCT** — подписи образов (Notary). Можно заставить демон принимать только подписанное. Это не замена сканера уязвимостей и не ГОСТ.

**Compose (v2 plugin)** — файл `compose.yaml`: несколько контейнеров на **одном** хосте (или на одном swarm stack). Это не оркестратор на 3 ЦОДа. В пакетах 24.0.x плагин обновляли отдельно (например 24.0.7 → Compose **v2.21.0**). Версию сверять `docker compose version`.

**Docker Desktop** — другой продукт (VM на Windows/Mac + UI). Это **не** Docker Engine 24 на сервере ЦОДа.

**docker-ce vs docker.io** — пакеты Docker Inc. vs пакет дистрибутива. Для воспроизводимой 24.0.9 ориентир — пакеты/бинарники Docker Inc. того времени.

**Static tarball** — распаковка бинарников в `/usr/bin`. Вендор: не прод (нет автообновлений зависимостей).

**RPO / RTO** — сколько данных готовы потерять / как быстро восстановиться. У Engine «данные» — `/var/lib/docker` и volumes этого хоста.

**HA** — у одного `dockerd` её нет. Появляется только при Swarm и кворуме manager'ов. Прод-HA приложений — в `Kubernetes.md`.

**N+1 хостов** — отказоустойчивость сборки: очередь CI подхватывает другой builder. Упал один демон — не падает Kafka и не падает интеграционное API.

**Реестр образов (Harbor / Quay / registry:2)** — хранилище OCI. Без реестра ноды и CI не из чего собирать прод в закрытом контуре. Docker Hub с builder'а в контуре гособмена — канал утечки и подмены.

**Сканер CVE (Trivy, Grype, Scout)** — отдельное ПО. Демон образы запускает, не аудирует.

**Vault / Swarm secrets** — HashiCorp Vault — отдельный документ. Swarm secrets / Docker secrets — только для swarm-сервисов, это не Vault.

**ГОСТ TLS / СКЗИ** — не заявлено. Штатный TLS демона — OpenSSL/Go TLS, не криптография КИИ.

**SLA** — официального 24/7 и патчей на 24.0 в 2026 нет.

**DinD (Docker-in-Docker)** — демон внутри контейнера/пода. Сокет хоста в CI-контейнере — типичный путь побега. DinD — изолированная VM/pod с жёсткой политикой, не сокет хоста.

**`json-file` (логи)** — драйвер логов. По умолчанию **нет** max-size; без ротации стенд убивает диск. Пример теста: `max-size` **10m**, `max-file` **3**.

**`userland-proxy`** — по умолчанию **true**: отдельный процесс на опубликованный порт. На Linux часто ставят `false`, полагаясь на iptables. Менять только поняв firewall (nft/iptables) этого хоста.

**iptables / nft** — правила фильтрации, которые пишет Docker. Конфликт с «чужим» firewall. На Kubernetes-ноде — одна из причин не ставить Engine рядом с kubelet.

**noisy neighbor** — один контейнер без лимитов (`memory`, `cpus`) съедает машину. Это не HA, это защита соседей.

**prune** — удаление неиспользуемых образов/слоёв. Слепой `docker system prune -a` по cron снесёт кэш сборки.

**Бэкап Swarm** — остановить Docker на **одном** manager, скопировать `/var/lib/docker/swarm` (включая ключи шифрования Raft). Hot-backup вендор считает менее предсказуемым. Auto-lock: unlock-ключ обязателен для restore, хранить не рядом с бэкапом на том же диске.

**HEALTHCHECK** — инструкция образа: процесс сам сообщает, жив ли он.

**Вариант C** — целевой: Engine только на CI/builder и служебных хостах, не на worker'ах Kubernetes. В каждом ЦОДе независимые `dockerd`, общее состояние — реестр.

**Вариант D** — Swarm как оркестратор прода на 3 ЦОДа. Конфликт с Kubernetes. Пока RTT неизвестен, stretch-Swarm нельзя честно обещать.

**Вариант E** — Engine + cri-dockerd как CRI Kubernetes. Для 1.36 штатный путь — containerd.

**Вариант F** — Swarm и kubelet на одних машинах. Не рекомендуется; официальной прод-схемы нет.

**Mirantis Container Runtime / podman** — другие продукты. Целевой бинарь файла — Docker Engine 24.0.9 CE.

**NTP** — синхронизация времени (TLS, логи, Swarm Raft).

**152-ФЗ / КИИ** — требования ИБ. Часто ответ на 24.0.9 — «нет, нет патчей».

**inode** — учётные записи файлов на ФС. Переполнение inode `/var/lib/docker` = все контейнеры хоста.

Источники формулировок: глоссарий и тело `Docker 24.md`. Новых порогов RTT и размеров диска здесь нет.
