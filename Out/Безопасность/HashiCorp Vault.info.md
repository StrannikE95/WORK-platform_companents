# HashiCorp Vault 2.0.4 — термины и сокращения

Словарь к файлу `HashiCorp Vault.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в операционной системе: у неё есть память и открытые файлы. Vault — процесс `vault`: слушает сеть, держит ключи в RAM, пишет журнал хранилища на диск.

**Файл / каталог на диске** — то, что остаётся после рестарта процесса. У Vault это каталог встроенного хранилища (`storage "raft" { path }`; в Kubernetes — том `dataStorage`): журнал состояния и снимок. Журнал «кто какой путь спросил» кладут на другой том (`auditStorage`).

**HTTP** — протокол запросов по сети: метод (`GET`/`POST`/`PUT`), путь, заголовки, тело. Клиенты Vault ходят HTTP(S) на listener, обычно порт **8200** (`/v1/...`).

**TCP-порт** — номер, по которому другие процессы находят этот процесс в сети. У Vault: **8200** — API клиентов и вход узла в кластер (join); **8201** — копирование журнала между узлами и пересылка запросов на лидера.

**TLS** — шифрование байтов HTTP в сети. Без TLS на listener пароли, токены и тела секретов идут открытым текстом. В проде HashiCorp требует TLS на 8200; «протокол SSL» в чужих UI обычно тоже TLS.

**Секрет** — значение, которое нельзя класть в git и в открытый конфиг Kubernetes: пароль БД, ключ API, сертификат, токен. Vault хранит его и выдаёт по политике после login.

**mTLS** — TLS, где обе стороны показывают сертификат. Между узлами Vault на **8201** mTLS поднимается самим Vault после входа узла в кластер. Клиентский mTLS к 8200 — отдельная настройка.

**ЦОД** — отдельная площадка с серверами (своё питание, своя сеть). «Три ЦОДа» — три такие площадки, не три папки в одном шкафу.

**RTT** — время туда-обратно по сети между двумя машинами. Для встроенного хранилища Vault (копия журнала между узлами) HashiCorp задаёт порог между зонами **меньше 8 мс**. Выше — выборы лидера и запись журнала страдают. Вашего замера в исходном файле нет.

**SoT (source of truth)** — место, откуда система считает текущее состояние правдой. Для секретов и ключей в этом файле это Vault. Для карточек клиентов — нет: терабайты персоналки в хранилище ключ-значение не кладут.

**Под (Pod)** — минимальная единица запуска в Kubernetes: контейнеры живут и умирают вместе. IP пода меняется. Рестарт пода Vault без auto-unseal оставляет процесс **sealed**.

**ConfigMap** — объект Kubernetes: несекретный текст конфига в etcd. Пароли и PIN HSM туда не кладут.

**Kubernetes Secret** — объект API: байты в etcd, обычно base64. Base64 — не шифр. VSO кладёт сюда копию из Vault.

**etcd** — хранилище объектов API Kubernetes. Encryption-at-rest etcd — шифрование этих байт на диске API-сервера. Без него Secret читается как есть у того, кто имеет RBAC.

**Helm / чарт** — шаблон манифестов. Официальный путь: **hashicorp/vault 0.34.1** (app **2.0.4**). Чарты **не** делают `init`, unseal, бэкап и апгрейд за вас. Дефолт чарта — **standalone + file** (один сервер, не Raft): в доке HashiCorp это Security Warning, не прод.

**Image tag `latest`** — ярлык, который завтра укажет на другой патч. В проде пинят `2.0.4` (лучше digest).

**PVC** — заявка Kubernetes «дай том». Для Raft нужен диск **на узел** (RWO), не общая NFS/RWX-шара как `path` Raft. Recreate пода должен найти **свой** том.

**NFS** — сетевая файловая система. Как единственный диск Raft HashiCorp не допускает: латентность и обрыв сети ломают запись лога.

**NetworkPolicy** — правила Kubernetes, кто в кластере может открыть TCP на 8200/8201. Это не ACL-политика Vault.

**CSI** — плагин Kubernetes, который создаёт диск для пода. В чарте сервера Vault **CSI Secrets Store provider** (секреты как volume) по умолчанию **выключен** — это другой CSI, не диск Raft.

**HCL** — язык конфига сервера Vault: блоки `listener`, `storage "raft"`, опционально `seal`.

**Инстанс Vault** — один или несколько процессов `vault` с общим Raft-состоянием (кластер) либо одиночный file-backend. CLI `vault` — тот же бинарник: `init`, unseal, policy, snapshot.

**UI** — веб-консоль. Включается отдельно, для API не обязательна. В интернет не выставляют.

**Плагин** — модуль движка или auth: часть встроена в процесс `vault`, часть — внешний процесс.

**Secrets engine (движок секретов)** — модуль внутри Vault по пути API (`secret/`, `transit/`, …). Типы в тексте: **KV**, **database**, **pki**, **transit**.

**KV** — движок «ключ → значение»: запись и чтение секрета по пути (`vault kv`, HTTP `secret/data/...`). Не озеро данных и не SoT клиентских карточек.

**Database engine** — движок: Vault сам создаёт в Postgres (и др.) короткоживущего пользователя и отдаёт пароль клиенту. По истечении lease учётка отзывается.

**PKI (движок)** — выпускает сертификаты по запросу API. Не путать с корпоративным CA, которым подписывают listener 8200.

**CA** — удостоверяющий центр: подписывает сертификаты. Для listener TLS в проде нужен свой CA.

**Transit** — «шифрование как сервис»: приложение шлёт plaintext HTTP-ом, получает ciphertext. Данные живут у приложения (озеро, БД); ключ — в Vault. Тем же движком делают **Transit auto-unseal** другого кластера Vault.

**Plaintext / ciphertext** — открытые байты / байты после encrypt. Transit не хранит plaintext озера.

**Auth method** — как клиент доказывает, кто он, до получения токена. Без auth процесс с адресом 8200 — никто. В тексте: Kubernetes (JWT пода), **AppRole**, OIDC/LDAP для людей, userpass.

**JWT** — токен (три base64-сегмента), который под Kubernetes auth проверяет Vault через TokenReview. Берётся из ServiceAccount пода.

**ServiceAccount** — учётка пода в Kubernetes. К ней привязывают роль Vault (policies).

**AppRole** — auth для машин не из Kubernetes: пара `role_id` + `secret_id`. Батчи, внешние воркеры.

**OIDC / LDAP / userpass** — вход людей: IdP по OpenID Connect, каталог LDAP, или логин/пароль в самом Vault. User lockout для userpass/approle/ldap по умолчанию включён.

**Policy (ACL)** — текст в Vault: «этому токену можно `read` по пути `secret/data/app/*`, и больше ничего». Не NetworkPolicy. Широкие `*` — дыра. Least privilege — минимальные пути и глаголы.

**Token** — короткоживущий пропуск после login: его шлют в заголовке к API. Root token после `init` умеет всё; после настройки auth его **отзывают** (`revoke`). Держать root в проде «на всякий случай» — дыра.

**Lease** — срок жизни динамического секрета или токена. Vault умеет отозвать до истечения. TTL токенов и даты в PKI завязаны на часы машины.

**TTL** — сколько секунд/часов живёт token или lease. Короткие TTL — норма прода.

**NTP** — синхронизация часов. Сильный skew ломает TTL, PKI и failover.

**Seal / unseal (печать)** — после старта Vault **запечатан**: файлы на диске есть, мастер-ключа в памяти нет, API почти не обслуживает. Unseal — расшифровать мастер-ключ и начать работу. На Kubernetes reschedule пода без auto-unseal = снова sealed.

**`init`** — однократная инициализация пустого хранилища: создаёт ключи, выдаёт доли/recovery и root token. Делают **один раз** на первом поде.

**Root key (мастер-ключ)** — ключ, которым Vault расшифровывает остальное в памяти. В Shamir его режут на доли; при auto-unseal его оборачивает KMS, HSM или Transit другого Vault.

**Shamir** — ручной unseal: при `init` получают N долей, чтобы открыть — любые K из них (часто 5 долей, порог 3). Каждую долю после рестарта **каждого** пода вводят снова. Все доли у одного человека = один человек открывает весь контур (нет split-knowledge).

**Split-knowledge** — доли Shamir/recovery у разных людей, не в одном git и не в одном чате.

**Auto-unseal** — unseal без ввода долей людьми: Cloud KMS, HSM (PKCS#11) или Transit другого Vault. На Kubernetes HashiCorp рекомендует auto-unseal: поды переезжают часто.

**KMS** — облачный сервис ключей (AWS/GCP/Azure). Креды к KMS не пишут plaintext в HCL: instance profile / env. Доступен и Community, и Enterprise.

**HSM / PKCS#11** — аппаратный модуль ключей. Auto-unseal через PKCS#11 — **только Enterprise**. PIN не в git и не в ConfigMap.

**Recovery keys** — при auto-unseal вместо «unseal-долей» выдают ключи для `generate-root` и чрезвычайных операций, не для каждого рестарта. Хранят так же серьёзно, как Shamir.

**`generate-root`** — процедура выпустить новый root token, когда старый отозван; для auto-unseal нужны recovery keys.

**Integrated Storage / Raft** — встроенное хранилище: состояние кластера пишется в лог на диск и копируется между узлами по протоколу Raft (TCP **8201**). Отдельный Consul для хранения **не нужен**. Пишет **один** лидер; лишние узлы запись не ускоряют.

**BoltDB** — файл БД, в котором лежит Raft-состояние. Раздувает RSS процесса; из-за этого с Integrated Storage рекомендуют `disable_mlock = true`.

**RSS** — сколько RAM процесс занимает с точки зрения ОС.

**Consul storage** — старый внешний бэкенд HA: ещё один кластер Consul. Для нового кластера HashiCorp ведёт на Integrated Storage. Third-party storage в матрице редакций: Community да, Enterprise нет.

**Кворум (quorum)** — большинство голосов voter в Raft. Для 3 узлов = 2, для 5 = 3. Нет кворума → **нет записи** (новые секреты, login, смена политик). Чётное число узлов как целевой размер не используют.

**Voter** — узел с голосом в кворуме. Нечётное число: прод-ориентир HashiCorp — **5** (failure tolerance 2 узла). 3 допустимо (tolerance 1).

**Non-voter** — узел без голоса, пока не догнал лог (Autopilot так вводит новичка).

**Active / standby** — в кластере **один** active (лидер Raft): принимает запись. Остальные — standby. В Community standby **пересылает** почти все запросы лидеру.

**Request forwarding** — standby принял HTTP клиента → отправил лидеру на **8201** → вернул ответ. Клиенту всё равно, на какой узел попал, если forwarding жив.

**Performance standby** — **только Enterprise:** standby сам обслуживает чтения (KV get, transit encrypt/decrypt); запись всё равно у лидера.

**Performance replication (PR)** — **только Enterprise:** второй кластер в другом ЦОДе отдаёт чтения локально; запись, меняющая общее состояние, уходит на primary. Токены и lease PR **не** копирует.

**Disaster Recovery (DR) replication** — **только Enterprise:** тёплый кластер-копия. Клиентов не обслуживает, пока его не повысят. Это провал целого кластера/региона, не падение одного пода.

**Stretch-кластер** — один Raft, узлы физически в нескольких ЦОДах, **один** кворум. Раскладка 5 voter **2-2-1** переживает потерю **одного** ЦОДа; 3-1-1 при потере ЦОДа с тремя голосами теряет кворум. Два ЦОДа из трёх при 3 или 5 voter обычно убивают кворум. Stretch ≠ PR/DR.

**Autopilot** — механизм Raft: новый узел сначала non-voter, догоняет лог, потом получает голос. В чарте для стабилизации новых voter включён. **Dead server cleanup** (вычищать мёртвые узлы из peer set) по умолчанию **выключен** — включают отдельно после `init`.

**`retry_join`** — в конфиге/чарте: узел сам стучится к уже живым, чтобы войти в Raft.

**Snapshot** — снимок Raft-состояния на диск/в файл. Community: вручную `vault operator raft snapshot save` / `restore`. Автоснимки по расписанию — **Enterprise**. Снимок хранят **вне** дисков кластера (object storage / другой ЦОД), иначе падение площадки забирает и данные, и бэкап.

**Object storage** — хранилище объектов (S3-совместимое): ключ + байты, не диск пода.

**Audit device** — журнал «кто какой путь спросил и что ответили». Чувствительные поля **хешируются**. Если Vault **не может записать** ни на одно включённое устройство — **отказывается обслуживать запрос**. По умолчанию после `init` audit **выключен**. Нужны **два** устройства (file на отдельном томе + syslog/socket в сборщик). Диск audit 100% = API может встать.

**SIEM** — система, куда складывают security-события и где по ним дежурят. Audit Vault туда отдают вторым device; сам Vault SIEM не является.

**`/v1/sys/health`** — HTTP health для балансировщика. Коды различают sealed / standby / active. «TCP 8200 открыт» — не health. Standby может отвечать 429/472 в зависимости от query (`standbyok`): либо LB шлёт только на active, либо на всех и работает forwarding.

**Балансировщик / Ingress** — принимает клиентский TCP/TLS и выбирает под. HashiCorp для прода: TLS **end-to-end** (passthrough / TCP LB), не терминировать TLS на прокси и дальше plaintext до Vault.

**mlock / `disable_mlock`** — `mlock` запрещает выгружать память процесса в swap. С Integrated Storage рекомендуют **`disable_mlock = true`**: иначе BoltDB раздувает RSS и ловит OOM. Тогда swap на ноде **выключен или зашифрован**. Helm сам ставит `disable_mlock = true`, если не переопределить. Capability `IPC_LOCK` на дефолтный образ не вешают: на бинарнике её нет, admission может отвергнуть под.

**Swap** — выгрузка страниц RAM на диск. На пуле нод Vault проверяют, что выключен.

**OOM** — процесс убит, потому что кончилась память cgroup/машины.

**cgroup** — лимит памяти/CPU, который Kubernetes ставит на контейнер.

**Vault Agent Injector** — Admission webhook: по аннотации в под вставляют sidecar Agent, секреты появляются как файлы в volume. Приложение может не вызывать Vault API. Если webhook мёртв — новые поды с аннотациями не создаются. В проде **≥ 2** реплики Injector (`injector.replicas`).

**Admission webhook** — API Kubernetes вызывает его при создании пода; ответ может мутировать манифест (добавить контейнер).

**Sidecar** — второй контейнер в том же поде.

**Vault Secrets Operator (VSO)** — **отдельный** Helm-чарт. Синхронизирует пути Vault в обычные Kubernetes Secret. Секрет оказывается в etcd: без encryption-at-rest и жёсткого RBAC обходят Vault через API Kubernetes.

**Namespace (Vault)** — логический «мини-Vault» внутри одного кластера (свои политики и движки). **Только Enterprise.** Не namespace Kubernetes.

**Community / Enterprise** — две редакции. Community — self-hosted без PR, DR, HSM PKCS#11, namespaces, автоснимков, performance standby. Enterprise — коммерческая лицензия, другие образы (`vault-enterprise`, тег линии `2.0.4-ent`). Юридические ограничения BSL Community в файле не разбираются.

**HA (high availability)** — пережить отказ машины/процесса без ручного подъёма с нуля. Для Vault Community: нечётное число voter ≥ 3, auto-unseal, снимки вне кластера. Конкретные цифры времени не обещаны. Добавление узлов **не** ускоряет запись.

**Failover** — смена active при падении лидера: выборы Raft, короткий разрыв записи. Клиенты должны ретраить 5xx с backoff — это код приложения, не values Helm.

**RPO / RTO** — сколько секретов/ключей готовы потерять при аварии / за сколько поднять Vault. Это не RPO озера данных. Community без DR: потеря кластера/города = snapshot + restore.

**SPOF** — единственная точка, падение которой останавливает функцию. ЦОД с единственным кластером Vault без DR — SPOF для всех секретов.

**Anti-affinity** — правило планировщика: не класть два пода Vault на одну ноду. Чартовый anti-affinity требует отдельную ноду на каждый под: 5 серверов → минимум 5 нод в пуле.

**`topology.kubernetes.io/zone`** — метка зоны/ЦОДа на ноде. Для stretch 2-2-1 её используют, чтобы голоса не собрались в одном зале.

**Node pool** — выделенные ноды под Vault (лучше dedicated; HashiCorp: по возможности отдельный Kubernetes).

**IOPS** — операций ввода-вывода в секунду у диска. Raft упирается в диск лидера и RTT до кворума. Магнитные диски HashiCorp прямо отвергает. Burstable типы VM (t2/t3) в reference architecture запрещены.

**StatefulSet** — контроллер Kubernetes: стабильные имена подов и PVC. Серверы Vault ставят так, не Deployment с общим диском.

**CronJob** — периодическая задача в Kubernetes. Community не даёт автоснимки: нужен свой Job/`vault operator raft snapshot save` с правами snapshot.

**RBAC** — кто в Kubernetes может читать Secret, exec, править чарт. Не ACL Vault.

**PKI listener** — сертификат на 8200. TLS 1.3 по возможности; HSTS через custom response headers.

**User lockout** — после N неверных логинов учётка auth method блокируется. Порог сверяют с ИБ.

**Resource quotas (Vault)** — лимиты lease/rate внутри Vault (часть — Enterprise). Защита от своих же клиентов, не замена ёмкости диска/CPU.

**Режим `dev` (`vault server -dev`)** — память, всё unsealed, root на экране. В документ прода не входит.

**`vault kv` / `vault status`** — CLI: чтение KV и состояние seal/leader.

**Unseal-кластер** — маленький отдельный Vault, чей Transit открывает прод-кластер. Shamir переезжает туда; его тоже надо уметь открывать.

Источники формулировок: глоссарий и тело `HashiCorp Vault.md`. Новых порогов RTT и размеров диска здесь нет.
