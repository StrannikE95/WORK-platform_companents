# SafeLine WAF 9.4.0 — термины и сокращения

Словарь к файлу `SafeLine WAF.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в ОС. Один инстанс SafeLine — несколько контейнеров на **одной** Linux-машине (файл Docker Compose), не несколько копий одного Deployment в Kubernetes.

**Файл / каталог на диске** — `SAFELINE_DIR` (часто `/data/safeline`): конфиг, PostgreSQL этого узла, логи атак. Бэкап официально: `docker compose down` + `cp -r` каталога. Апгрейд **необратимо** мигрирует данные. Сетевой диск (NFS) как data dir вендор не описывает.

**HTTP / HTTPS** — запрос: метод, путь, заголовки, тело. SafeLine смотрит **содержимое** этого запроса (не «порт открыт»). Входной прокси слушает 80/443 хоста (или listen-порты сайтов в консоли). Консоль управления — отдельный HTTPS, дефолт **9443**.

**TCP-порт** — номер сокета. Служебные, в FAQ **не меняются**: **65508** health check балансировщика, **65443** custom page. **9443** консоль — меняется (`MGT_PORT` → внутри контейнера 1443). Процесс детекции принимает трафик от входного прокси на **:8000**. PostgreSQL внутри стека — 5432, с хоста не публикуют.

**TLS** — шифрование HTTP. На сайтах сертификаты в консоли «SSL Cert» (в UI слово SSL = TLS). Консоль 9443 на самоподписанном сертификате для людей по FQDN в проде недостаточна. Кастомные cipher — возможность Pro (changelog 6.9.0). ГОСТ TLS / СКЗИ в продукт не входят.

**Секрет** — пароль админки, `POSTGRES_PASSWORD` в `.env`, ключ лицензии Pro. Не в git. Стартовый пароль консоли узнают `docker exec safeline-mgt resetadmin` и сразу меняют.

**ЦОД** — отдельная площадка. На каждый живой ЦОД — минимум один полный инстанс. Общий Postgres WAF на три ЦОДа продукт **не** поддерживает.

**RTT** — время туда-обратно. На проверку HTTP-запроса почти не влияет (проверка на той же машине). Влияет на копирование конфига с узла, где правят правила, на остальные, на открытие консоли и на то, можно ли один балансировщик на три ЦОДа. Порога в миллисекундах у SafeLine нет.

**Firewall (обычный)** — фильтр по IP/порту. Не читает тело HTTP. WAF — следующий слой: смотрит SQL-инъекцию, XSS, бота в запросе.

**WAF (Web Application Firewall)** — обратный прокси, который пропускает или режет HTTP(S) до приложения. Не защищает Kafka, Postgres, gRPC Camunda. Не стоит на исходящих SOAP/REST-клиентах интеграционного API к ведомствам.

**Reverse proxy (обратный прокси)** — клиент стучится в SafeLine; если запрос прошёл проверку, SafeLine открывает свой HTTP к **upstream**. Так устроен продукт.

**Upstream / origin** — реальный адрес приложения за WAF (Ingress, Integration API, портал). В проде origin принимает HTTP **только** с IP узлов WAF (NetworkPolicy/firewall), иначе WAF обходят. Upstream лучше локальный (Ingress **этого** ЦОДа), не HTTP через город на чужой ЦОД.

**Ingress** — вход HTTP в Kubernetes. SafeLine — **не** Ingress-контроллер и не замена NetworkPolicy внутри кластера. Если повесить WAF **за** Ingress без XFF/PROXY Protocol, в логах будет IP Ingress.

**Tengine** — форк Nginx (Alibaba). Контейнер `safeline-tengine` принимает 80/443. В публичном `compose.yaml`: **`network_mode: host`** — стек сети **хоста**, не Docker bridge: порты машины слушает сам Tengine. На той же VM нельзя держать другой процесс, который тоже хочет 80/443.

**Host network** — режим Docker: контейнер = сетевой стек хоста. Расширяет поверхность: дыра в Tengine = дыра в портах машины.

**Детектор (detector)** — процесс семантического анализа: атака или нет. Контейнер `safeline-detector`. Tengine шлёт сюда на `:8000`. В Pro есть «Detection Engine Performance Configuration» — режимы под CPU машины.

**Семантический анализ** — решение по структуре запроса (инъекция, обход пути), не только по чёрному списку подстрок. Заявленное ядро SafeLine.

**SQL-инъекция / XSS** — в теле или query подставляют SQL или HTML/JS. Детектор это классифицирует; WAF может залогировать или отдать deny.

**MGT / консоль** — контейнер `safeline-mgt`: веб-админка и API управления, обычно `https://<ip>:9443`. Ходит в Postgres по URI с **`sslmode=disable`**. В интернет не публикуют: это админка щита, не сайт. Сброс пароля: `docker exec safeline-mgt resetadmin` — узнать стартовый, потом сменить. С 9.3.10 есть роль **read-only**.

**`safeline-pg`** — PostgreSQL этого узла (в changelog 9.3.11 бандл **15.2 → 15.18**; берут compose **того** релиза). Хранит конфиг, логи, статистику **этого** инстанса. Не кластер с репликами на три ЦОДа. 5432 с хоста не торчит.

**`sslmode=disable`** — клиент mgt не шифрует сессию к Postgres. Приемлемо, пока 5432 не слушает мир.

**`safeline-luigi`** — обработка логов. Контейнер `mario` с 6.10.2 **удалён**, роль переехала сюда.

**`safeline-fvm`** — служебный контейнер в compose; отдельного описания роли в публичных docs нет.

**`safeline-chaos`** — челленджи и динамическая защита (капча и связанная логика).

**Application (сайт в консоли)** — правило: какой домен/порт слушаем → какой upstream. Не микросервис в Kubernetes и не Deployment.

**Config Auto Sync** — функция **Pro** с 7.0.0: один узел **master**, остальные **slave**; сайты и правила копируются master→slave. Это **не** общий кластер с одной БД. В 9.4.0 отдельно добавили синхронизацию **forwarding rules** (набор historically был неполным). Синхронизация конфига ≠ репликация логов атак.

**Master / slave** — master: единственное место, где правят правила. Slave принимает копию и обычно **не** даёт менять конфиг локально. HTTP-трафик могут принимать **все** узлы. Падение master само по себе не обязано ронять трафик на уже синхронизированных slave. Штатной процедуры «выбрать нового master», если умер ЦОД master, в английской документации **нет**.

**Personal / Lite / Pro** — редакции. Personal — бывшая Community, бесплатная; на **ARM не поддерживается**. Lite — платная «домашняя». **Pro** — платная: HA-синхронизация, syslog атак, режимы производительности детектора, часть cipher. Каждый узел фермы — своя лицензия Pro; один ключ на три машины в docs не обещан.

**License server** — облако вендора. Ключ Pro официально требует **постоянную** связь контейнера mgt с `safeline.stream.safepoint.cloud:50052`. Смена IP узла — сервер лицензий сам рвёт сессию. При обрыве вендор пишет, что прокси/детекция/paid features **пока** живут — это не бесконечный offline и не air-gap. В Install Guide offline-схемы нет.

**QPS** — HTTP-запросов в секунду к WAF. Единица железа в FAQ (не объём Kafka/БД). Нагрузки в исходном контексте нет: таблица FAQ — справка, не гарантия.

**CC / rate limiting** — лимит частоты запросов с IP/ключа (флуд, брутфорс пароля).

**Anti-Bot / Challenge** — капча, слайдер, проверка «клиент — браузер». На URL машинных интеграций (колбэки ведомств, health) ломает клиентов. Allowlist служебных IP — **до** жёсткого challenge.

**Dynamic Protection** — шифрование HTML/JS на лету, чтобы готовые бот-скрипты не нашли селекторы. На JSON API почти наверняка ломает клиентов; включать только на человеческих HTML-страницах.

**X-Forwarded-For (XFF)** — заголовок со цепочкой IP. Если перед WAF есть LB/CDN, без настройки WAF видит IP балансировщика. SafeLine сам кладёт источник в XFF к upstream. На приложении нельзя `set_real_ip_from 0.0.0.0/0`: доверять XFF только от IP WAF.

**PROXY Protocol** — бинарный префикс от балансировщика с реальным IP (не HTTP-заголовок). SafeLine умеет читать (линейка 8.x). Нужен, когда заголовкам нельзя верить. В консоли: `Get Attack IP From`.

**Sticky session** — LB всегда шлёт одного клиента на тот же узел. Может понадобиться для challenge/auth; в docs нет «всегда sticky» — проверяют.

**Docker Compose** — официальный runtime: Linux, Docker ≥ 20.10.14, Compose v2 ≥ 2.0.0. macOS/Windows не поддерживаются. Архитектура x86_64 или arm64; ARM только с Pro. CPU: флаг **SSSE3** (`lscpu | grep ssse3`). Минимум «контейнеры встали»: 1 CPU / 1 ГБ RAM / 5 ГБ — не прод. ZooKeeper, отдельный Redis, внешний Postgres, Kafka **не** требуются.

**`.env`** — переменные: `IMAGE_TAG=9.4.0`, `IMAGE_PREFIX=chaitin`, `REGION=-g` (международная линейка), `POSTGRES_PASSWORD`, `SUBNET_PREFIX`, `MGT_PORT`. Не в git. Китайский инсталлятор `waf-ce.chaitin.cn` ходит в другое облако — не смешивать.

**`IMAGE_TAG=latest`** — ЦОДы сами разъедутся по патчам. Прод: pinned **9.4.0**, одинаковый patch на всех узлах (sync и лицензии). Образы из своего registry, лучше digest. Не `curl | bash` с сайта вендора в обход зеркала.

**`manager.sh`** — официальный инсталлятор (`curl` с docs). В закрытом контуре нужны зеркало образов и ответ вендора по лицензии.

**Helm community (`yaencn/safeline-lts-helmchart`)** — не Install Guide. README: у Deployment **только 1 replica**; несколько replica «ломают WAF неизвестным образом». LTS вендор не сопровождает с **9.1.0-LTS** (14 августа 2025). HPA (автоувеличение replica) для SafeLine не применяют.

**Балансировщик (LB)** — внешний L4/L7 перед фермой WAF: health check, снятие мёртвого бэкенда. SafeLine **сам** failover трафика не делает. Health: живой HTTP или порт **65508**. Апгрейд рестартует сервис и кратко рвёт трафик: снять узел с LB → обновить → вернуть. Катить все ЦОДы сразу = простой периметра.

**DNS failover / Anycast** — смена площадки на уровне DNS или одного IP на несколько ЦОДов. Это не функция SafeLine; без LB/DNS три узла — три острова.

**Observe / log vs deny** — сначала писать срабатывания, потом включать block на боевых интеграциях. 5xx «от SafeLine» и 5xx «от origin» в Pro различают.

**Websocket** — долгое HTTP-upgrade соединение. Влияет на ёмкость и на sticky; в контексте нагрузки цифр нет.

**HTTP/2 vs 1.1** — версия протокола на тех же путях; на тесте проверяют тем же, что в бою.

**Clean Data** — политика в консоли: удалять старые логи из Postgres узла. Иначе диск кончится независимо от озера данных.

**Syslog (Pro)** — отправка логов атак на внешний приёмник. Централизация: syslog в SIEM, не общий диск на 3 ЦОДа.

**SIEM** — хранение и разбор security-событий. Personal в FAQ предлагает fluentd, читающий таблицу Postgres — для прода костыль, показывает что логи **в БД узла**. Attack Alert (Pro) — не замена SIEM.

**NTP / TOTP** — синхронизация часов. У Personal для TOTP админки время критично.

**RPO / RTO** — сколько готовы потерять / как быстро восстановиться. Для WAF «данные» — **конфиг правил** и **логи атак**, не клиентская база. Slave со старым конфигом после обрыва sync продолжает пускать трафик по **старой** политике.

**HA** — несколько **независимых** полных инстансов + Config Auto Sync + внешний LB. Не «три пода в одном Deployment». Не кворум одной БД. Переживание 1 ЦОДа **по трафику**, если LB жив и конфиг уже на slave.

**SPOF** — падение master = нельзя менять правила (пока нет процедуры повышения slave). Падение городского LB = нет входа, даже если WAF живы. Один Compose на всю систему отказ площадки не переживает.

**NetworkPolicy** — в Kubernetes origin принимает HTTP только с IP WAF. Между ЦОДами sync и админка — по внутренней сети, не публичный адрес.

**Opt in to User Experience Program** — телеметрия вендора (Chaitin, `safepoint.cloud`). Решение ИБ, не «галочка в compose».

**Air-gap** — нет исходящего интернета. Образы с Docker Hub и license `:50052` тогда не сходятся с Install Guide.

**SSSE3** — набор инструкций CPU; без флага контейнеры детектора не тот профиль железа.

Источники формулировок: глоссарий и тело `SafeLine WAF.md`. Новых порогов RTT и размеров диска здесь нет.
