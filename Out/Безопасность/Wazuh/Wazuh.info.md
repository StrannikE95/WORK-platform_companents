# Wazuh 4.14.7 — термины и сокращения

Словарь к файлу `Wazuh.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа в ОС: память и открытые файлы. Центральные роли Wazuh — отдельные процессы: анализ событий (manager), поиск документов (indexer), веб-UI (dashboard), отправка JSON с диска manager в indexer, агент на хосте.

**Файл / каталог на диске** — то, что остаётся после рестарта. У manager это `/var/ossec` (ключи агентов, правила, XML-конфиг `ossec.conf`). У indexer — данные индексов на томе Kubernetes. Без постоянного диска рестарт теряет состояние.

**HTTP** — запросы с методом, путём, телом. REST API manager слушает **55000/TCP**. Indexer REST — **9200/TCP**. Dashboard — веб-UI (в манифесте контейнер **5601**, снаружи часто **443**).

**TCP-порт** — номер сокета процесса. Контракт Wazuh по умолчанию: **1514** события агентов; **1515** первичная регистрация агента; **1516** синхронизация узлов анализа; **55000** API; indexer **9200** и **9300–9400** между нодами; приём syslog **514** UDP/TCP (по умолчанию **выключен**). UDP 1514 по умолчанию выключен.

**TLS** — шифрование HTTP/байтов в сети. Отправка алертов manager→indexer и dashboard→API — TLS + логин/пароль. Канал агент↔server по умолчанию — симметричное **AES** (блок 128, ключ 256 бит), не TLS; Blowfish — опция. Самоподписанный сертификат из `generate_certs.sh` — для теста; в проде свой CA.

**Секрет** — пароль, ключ кластера, учётка indexer/API. В публичном overlay Kubernetes v4.14.7 лежат известные строки (`password`, `SecretPassword`, 32-символьный cluster key) — в проде их меняют до первого агента. Не класть в git.

**ЦОД** — отдельная площадка с серверами. Потеря ЦОДа с единственным управляющим узлом анализа останавливает регистрацию агентов и API управления; автовыбора второго такого узла нет.

**RTT** — время туда-обратно по сети. У Wazuh **нет** порога в миллисекундах. Растягивание кластера indexer на несколько ЦОДов бьёт по состоянию кластера на **9300**; узлы анализа синхронизируются на **1516**. Без замера растяжка на три площадки не считается решением.

**Алерт** — запись «сработало правило»: JSON у manager, затем документ в индексе. Не блокировка HTTP и не kill процесса (это Active Response, отдельно).

**SIEM** — система, куда складывают security-события, ищут по ним и дежурят. В Wazuh это связка **server + indexer + dashboard**. Три независимых установки = три SIEM (три индекса, три правды для дежурной смены).

**SOC** — люди и процедура, которые разбирают алерты. Dashboard без дежурства — поисковик, не безопасность.

**XDR** — рамка вендора: не только логи, ещё слежение за файлами, проверка конфига хоста, уязвимости, реакция на хосте. Не замена фильтра HTTP на входе, сетевых правил кластера и съёма обращений в ядро.

**Wazuh agent** — процесс на наблюдаемой машине или в поде. Читает логи, FIM, SCA, инвентарь; шлёт события на server. Образы: `wazuh/wazuh-agent:4.14.7`. Агент в контейнере **без** доступа к хосту (`/var/log`, `/proc`, hostPath) хост не мониторит. Официальный Docker-агент годится как syslog-коллектор, не как host IDS. Имя агента на Kubernetes = `spec.nodeName`, иначе ноды сливаются в одного агента.

**DaemonSet** — контроллер Kubernetes: по одному поду на ноду. Так ставят агента на кластер. Без **tolerations** на taint Kafka/Camunda/control-plane самые важные ноды слепые.

**Wazuh server (manager)** — процесс анализа: декодирует события, применяет правила, управляет агентами. Образ `wazuh/wazuh-manager:4.14.7`. Кластер: **один master + N worker**. Это не голосование за лидера: второй master штатно не выбирается. Кворум и шарды — у indexer, не здесь.

**Master (server cluster)** — единственный управляющий узел: регистрация агентов (`authd`), эталон правил/ключей, API. В `<nodes>` списка master'ов официально **один** элемент; остальные игнорируются. **Второй master штатно нельзя.** Падение master: enrollment и синхронизация на worker встают; анализ событий — роль worker, SLA «N часов без master» вендор не публикует.

**Worker (server cluster)** — узел, который принимает события агентов и анализирует. Worker **сам** инициирует связь с master (порт 1516). Масштаб анализа = число worker + балансировщик. `ossec.conf` на worker **не** подтягивается с master автоматически: копируют руками или GitOps. Синхронизируются ключи агентов, кастомные rules/decoders, CDB, SCA, группы — не весь `ossec.conf`.

**`ossec.conf`** — главный XML-конфиг manager/агента: кластер, порты, модули, FIM-пути.

**Enrollment / `authd`** — первичная регистрация: агент получает уникальный ключ. Слушает **1515**, живёт на **master**. Пароль в overlay Kubernetes v4.14.7 — известная строка `password` в `/var/ossec/etc/authd.pass`. Дефолт эталонного `ossec.conf`: `<use_password>no</use_password>`. В проде длинный пароль или проверка сертификата агента (`ssl_agent_ca`). 1515 в интернет не торчат.

**Agent connection** — постоянный канал уже зарегистрированного агента. По умолчанию **TCP 1514**. Без LB агент знает один IP: падение этого IP = слепой агент при живых worker.

**Cluster key** — общий секрет **ровно 32 символа**: им шифруется master↔worker по **1516**. Корневой секрет кластера. В публичном манифесте v4.14.7 лежит известная строка. Сегмент 1516 — только узлы кластера.

**Wazuh indexer** — поисковый процесс поставки Wazuh (`wazuh/wazuh-indexer:4.14.7`). Код на базе OpenSearch: хранит и ищет алерты, REST **9200**, транспорт нод **9300–9400**. Это **свой** кластер индексов `wazuh-alerts-*`, не server-кластер и **не** платформенный **OpenSearch 3.8.0** (поиск/Camunda). Процесс в образе manager шлёт JSON на **9200** этого стека; шарды с OpenSearch 3.8 не делят, манифесты и лимиты другие.

**OpenSearch 3.8** — отдельный продукт платформы (`opensearchproject/opensearch:3.8.0`). Подключать отправку алертов manager туда или считать indexer «тем же» кластером нельзя.

**Cluster-manager (indexer)** — узел indexer, который ведёт состояние кластера (кто какие шарды держит). Выбирается голосованием среди *eligible* узлов. Нечётное число eligible. Потеря кворума (например 2 из 3 площадок, по одному eligible на ЦОД) — кластер не выбирает manager.

**Кворум indexer** — большинство eligible cluster-manager. На трёх нодах по одной на ЦОД потеря двух площадок снимает кворум. Это модель OpenSearch-кластера indexer, не server master/worker.

**Shard / replica** — индекс режут на **primary shards**; копии — **replicas**. Число primary задаётся **при создании** индекса; потом только re-index. Без replica падение узла = дырка в индексе. Дефолт шаблона вендора: *three primary shards and no replicas*. Для HA — **хотя бы 1 replica**. Пример в доке: 0 replica → при падении узла неполный индекс; 1 replica → полный; 2 replica → живут даже 2 упавших узла ценой диска.

**Индекс `wazuh-alerts-*` / `wazuh-alerts-4.x-*`** — шаблон/паттерн документов алертов в indexer. Проверка стенда: событие → документ в этом индексе → видно в dashboard.

**Re-index** — создать индекс заново с другим числом primary и перелить документы. Иначе схему шардов живого индекса не меняют.

**Yellow / red cluster** — `_cluster/health` indexer. Yellow: не все replica на месте, поиск ещё идёт. Red: не хватает primary — часть данных недоступна. Forced zone awareness при нехватке диска может оставить yellow, пока мёртвая зона не встала.

**Zone awareness** — настройка indexer: `node.attr.zone` + `cluster.routing.allocation.awareness.attributes: zone`, чтобы replica жила в **другой** зоне, чем primary. Forced awareness — только если понимаете yellow при отказе зоны. При трёх зонах вендор: добавлять data-ноды сбалансировано (по ноде на зону).

**Filebeat** — процесс на каждом Wazuh server (в образе manager): читает JSON-алерты с диска и по TLS отдаёт в indexer **9200**. Без Filebeat алерты есть в файлах manager, dashboard их не увидит. Если 9200 недоступен — анализ на server идёт, поиск в UI отстаёт.

**Wazuh dashboard** — веб-UI (`wazuh/wazuh-dashboard:4.14.7`). Ходит в indexer (поиск) и в API master (агенты, конфиг). Официально **stateless** (Deployment). `WAZUH_API_URL` в гайде указывает на `wazuh-manager-master-0`. Смена пароля `wazuh-wui` ломает связь UI, пока не обновят конфиг dashboard. В интернет LoadBalancer не выставляют.

**All-in-one** — server + indexer + dashboard на **одной** машине (`wazuh-install.sh -a`). Лаборатория / до ~100 агентов, не прод на 3 ЦОДа.

**FIM (File Integrity Monitoring)** — агент смотрит inode/хеш: файл создали, изменили, удалили, кто и когда. На data-dir Kafka/Java даёт лавину событий. Может захватить ПДн из содержимого/пути — это политика, не «включить всё».

**SCA** — проверка конфига хоста по CIS-бенчмарку (файлы, пакеты, sysctl). Не детект атаки в момент T, а оценка «нода уехала от эталона».

**CIS** — набор эталонных настроек ОС. SCA сравнивает факт с этим эталоном.

**Active Response** — агент по правилу сам блокирует IP, убивает процесс, удаляет файл. Без процесса ИБ ломает интеграции. В исходном файле по умолчанию **выкл**.

**Decoder / rule** — разбор сырого лога в поля и условие «это алерт». Кастом кладут на master; на worker они синхронизируются (в отличие от всего `ossec.conf`).

**CDB** — списки (IP, ключи) для правил на server. Синхронизируются в кластере server.

**ISM** — политики жизни индексов indexer: через N дней сжать/удалить. Без этого диск растёт сам. Пример вендора retention алертов **90 дней**. Не путать с ILM Elasticsearch и с политиками платформенного OpenSearch 3.8.

**Archives** — писать в indexer **все** события, не только алерты. Включать только при отдельной ёмкости; иначе APS и диск взрываются.

**APS** — alerts per second, ориентир вендора для сметы диска, не ваш замер. Таблица «3.7 ГБ/сервер за 90 дней» — не Kafka с auditd.

**`events_dropped` / `discarded_count`** — счётчики `wazuh-analysisd.state` и `wazuh-remoted.state`. Должны быть **0**. Иначе не хватает CPU worker или ещё worker. Жёсткий CPU throttle в cgroup даёт те же дропы.

**analysisd / remoted** — процессы manager: разбор событий и приём с агентов.

**Load balancer** — TCP-прокси перед **1514** (и обычно **1515**). Агент знает один VIP, не список подов. Рекомендация вендора — LB; иначе новый worker требует правки всех агентов. Алгоритм в гайде HAProxy: **leastconn**.

**HAProxy helper** — опция **на master**: двигает бэкенды в конфиге HAProxy, когда worker появляются/пропадают. Сам HAProxy — **отдельное** ПО.

**Failover-список `<server>`** — в `ossec.conf` агента несколько адресов worker без LB. Хуже, чем VIP: выкат worker = правка флота.

**CTI** — публичный сервис угроз Wazuh (уязвимости/CVE). Модуль **Vulnerability Detection** без исходящего доступа к CTI в гайде не работает как написано.

**CVE** — идентификатор опубликованной дыры в ПО. VD подтягивает данные через CTI, не «сканер из воздуха».

**PVC / RWO** — том Kubernetes, который монтируется только одним подом. Manager и indexer — **StatefulSet + PVC**, не Deployment. Shared NFS «один том на три indexer» в манифестах нет.

**CSI** — плагин, который создаёт PersistentVolume. Без динамических PVC overlay `wazuh-kubernetes` не о том. Для EKS 1.23+ вендор отдельно требует IAM-роль EBS CSI.

**`vm.max_map_count`** — sysctl: лимит mmap у ядра. Indexer требует **≥ 262144**, иначе процесс падает. В K8s это privileged initContainer `sysctl`; после ребута ноды значение должно остаться.

**mmap** — отображение файла/памяти в адресное пространство процесса; OpenSearch-based indexer создаёт их много.

**JVM heap (`Xms`/`Xmx`)** — куча Java-процесса indexer. Правило вендора: половина RAM узла, **Xms = Xmx**. Пример 8 ГБ RAM → 4g. Overlay EKS: heap **1g** и limit 2 Gi — стенд, не ёмкость. `bootstrap.memory_lock` в Linux-гайде включают; в официальном K8s overlay он **false**.

**Kustomize / overlay** — сборка манифестов (`kubectl apply -k`, `envs/eks/` или `envs/local-env/`). Репозиторий `wazuh/wazuh-kubernetes`, тег **`v4.14.7`**, не `main`. Отдельного Helm-оператора у вендора в этом гайде нет. `local-env`: 1 indexer, 1 worker. Полный overlay: indexer 3 / master 1 / worker 2.

**StatefulSet** — стабильные имена и диски. Rolling update indexer — по одному поду; без replica шардов выкат = деградация поиска.

**Deployment** — статeless-реплики. Для dashboard можно `replicas ≥ 2`; для manager/indexer — потеря идентичности и диска.

**PDB (PodDisruptionBudget)** — сколько подов можно снять сразу при drain ноды. Для 3 indexer имеет смысл не убивать сразу 2 из 3.

**Anti-affinity / topology spread** — не класть все replica indexer в один ЦОД. Минимум двух worker-нод K8s часто нужен, иначе поды не разъедутся.

**NetworkPolicy** — кто в кластере открывает 1514/1515/1516/55000/9200/9300. 9200, 9300, 1516, 55000 не с мира; 1514/1515 только от агентов/LB.

**PKI / self-signed** — скрипт `generate_certs.sh` делает самоподписанные сертификаты. API вендор советует своим доверенным сертификатом. First-login warning про untrusted CA в проде не норма.

**Overlay-секреты v4.14.7** — публичные дефолты, которые меняют до первого агента в проде: `wazuh-authd-pass` = `password`; `indexer-cred` = `admin` / `SecretPassword`; `dashboard-cred` = `kibanaserver` / `kibanaserver`; `wazuh-api-cred` = `wazuh-wui` / `MyS3cr37P450r.*-`; `wazuh-cluster-key` = 32 символа из git.

**RBAC API** — роли в API manager. Режим *white* (deny by default) включают только когда роли описаны, иначе сломаете эксплуатацию. Не все с правами администратора.

**SSO / IdP** — вход людей через корпоративный каталог. В 4.14 это отдельная настройка dashboard/indexer, не галочка `apply -k`.

**Syslog** — текстовый поток логов по 514. Агент может не стоять: сетевая коробка шлёт syslog на server (коллектор по умолчанию выключен).

**Flow control** — на агенте очередь, пока 1514 мёртв. Бесконечный буфер вендор не обещает.

**HIDS** — агент на хосте (файлы, процессы, логи). Falco смотрит syscall ядра; Wazuh — логи/FIM/SCA. Два агента на одной ноде — двойной overhead; нужна матрица, кто за что.

**auditd** — аудит ядра Linux (свои логи). Широкий auditd на брокере Kafka взрывает APS Wazuh.

**cmdline** — аргументы процесса в алерте. Могут содержать ПДн и секреты; срок хранения и маскирование — решение ИБ (152-ФЗ/КИИ), не «JSON как есть».

**ПДн / 152-ФЗ / КИИ / ГОСТ** — требования к персональным данным, значимым объектам, криптографии. Штатный AES/TLS Wazuh — не СКЗИ по ГОСТ, если ИБ это выдвинет.

**GitOps** — выкат rules/decoders только через git на master, не `vi` на поде.

**Image tag `latest`** — не пинить. Все четыре роли **4.14.7** (лучше digest) из своего registry. Смешивать 4.13 indexer с 4.14 manager «на глаз» нельзя. После установки **выключают** репозиторий пакетов Wazuh: случайный `yum update` разъезжает версии.

**GPL / Apache 2.0** — лицензии центральных компонентов по quickstart. Облачного license-server с постоянным TCP к вендору нет.

**Falcosidekick** — маршрутизатор алертов Falco. В него можно целить отдельно; в дистрибутив Wazuh **не входит**.

**WAF / NetworkPolicy / Falco** — другие слои: HTTP на входе, TCP в кластере, syscall на ноде. Wazuh их не заменяет и атаки сам не останавливает (кроме явно включённого Active Response).

**HA (приём событий vs управление)** — несколько worker + LB (или failover-список). HA управления = живой единственный master + runbook, когда его ЦОД мёртв. Автоfailover master нет: поднимают тот же StatefulSet с PVC.

**SPOF** — единственная точка отказа. Master — SPOF enrollment/API. Один indexer без replica — SPOF данных. Dashboard replicas: 1 — SPOF просмотра, не детекта.

**RPO / RTO** — сколько алертов готовы потерять / как быстро поднять SIEM. Бэкап: PVC indexer **и** `/var/ossec` master (ключи агентов). Потеря ключей = пере-enrollment флота.

**Интеграционное API / Kafka / Camunda** — источники логов и поверхность FIM, не часть Wazuh. Без агента (или syslog) SIEM слепой на этих хостах.

Источники формулировок: глоссарий и тело `Wazuh.md`. Новых порогов RTT и размеров диска здесь нет.
