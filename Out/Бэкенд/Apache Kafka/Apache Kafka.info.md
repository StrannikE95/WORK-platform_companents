# Apache Kafka 4.3.1 — термины и сокращения

Словарь к файлу `Apache Kafka.md`. Список линейный, не таблица. Сверху — слова, без которых не читаются остальные. Аналогий нет: только что это делает в коде и на диске.

---

**Процесс** — запущенная программа. В Kafka 4.x это брокер и/или контроллер (`process.roles`). Combined mode: один процесс сразу обе роли.

**Файл / каталог на диске** — сегменты лога топиков (`log.dirs` у брокера) и metadata log у контроллера. Kafka рассчитана на локальный POSIX-диск и page cache. **Не NFS / не сетевой NAS как `log.dirs`.**

**TCP-порт / listener** — сетевой вход брокера (порт + протокол). Обычно разные входы: для клиентов, для брокеров между собой, для контроллеров. Клиент ходит **напрямую** на брокера-лидера партиции; балансировщик «как у HTTP» перед всеми брокерами ломает модель.

**ЦОД** — независимая площадка. Три зала в одном здании с общим UPS — не три ЦОДа.

**RTT** — время туда-обратно. При `acks=all` и реплике в другом ЦОДе латентность записи не может быть ниже времени репликации на эту копию. Порога RTT в документации Apache нет.

**TLS / SSL** — шифрование канала. В конфигурации Kafka исторически пишут `SSL`, имеется в виду TLS. При TLS путь zero-copy `sendfile` для отдачи клиенту работает иначе: брокер должен шифровать байты. Hostname verification с 2.0 включён по умолчанию; `ssl.endpoint.identification.algorithm` не обнулять.

**HA** — пережить отказ брокера/ЦОДа за счёт копий партиций и кворума контроллеров. Долговечность записи — это не «fsync на диск», а репликация на другие брокеры.

**RPO** — сколько уже подтверждённых данных готовы потерять. **RTO** — за сколько восстановиться. Stretch при корректных RF/min.ISR и живой сети: RPO≈0 для уже подтверждённых `acks=all` записей при падении одного ЦОДа. Это не юридический 24/7. Два ЦОДа сразу при трёх площадках кворум из 3 или 5 контроллеров, как правило, не переживает.

**SoT** — правда сущности. Kafka — лог событий, не источник истины клиентских данных. Из лога неудобно делать выборку «дай клиента по ИНН».

**Под (Pod)** — единица Kubernetes. Kafka — stateful.

**Stateful / KafkaNodePool** — отдельные пулы Strimzi: `controller` и `broker`. Не один Deployment без диска.

**PVC / CSI / local PV** — том под лог. NVMe/SSD, отдельный StorageClass. Объём = (входящий поток × retention × RF / число брокеров) × запас; формула пустая, пока нет потока и retention.

**NFS** — сетевая ФС. Как единственный диск лога не используют.

**cgroup / лимит памяти** — лимит **выше** кучи JVM, чтобы остался page cache. Если лимит = куча, Linux нечем кэшировать лог.

**NetworkPolicy** — клиенты только на CLIENT-порт; контроллерный порт не публиковать через LoadBalancer. Listener контроллеров — отдельный.

**Anti-affinity / topology zone** — зона Kubernetes → `broker.rack`. Брокеры на dedicated nodes (taint/toleration): не соседствовать с batch-джобами, которые выбивают page cache.

**PDB (PodDisruptionBudget)** — чтобы kubelet не снял сразу два брокера одной зоны.

**Helm** — не основной путь в файле. Практичный путь на K8s: **Strimzi**.

**PKI / CA / SAN** — сертификаты с SAN=DNS на имя брокера, которое видит клиент. Формат PKCS12 (дефолт современных JDK; JKS устарел). Ротация до истечения.

**CVE / патч JDK** — Apache рекомендует свежий LTS и свежий патч JDK из соображений уязвимостей.

**ГОСТ / СКЗИ / 152-ФЗ** — vanilla Apache Kafka ГОСТ не закрывает. Меняют PKI, at-rest, аудит, контур КИИ.

**LoadBalancer** — не «все брокеры как HTTP». `advertised.listeners` должны резолвиться у клиента (внутри кластера одно имя, снаружи другое — разные listener'ы).

**Брокер (broker)** — процесс Kafka, который принимает сообщения, хранит их на диске и отдаёт потребителям.

**Контроллер (controller)** — отдельная роль в Kafka 4.x: хранит метаданные кластера (список топиков, кто лидер партиции, кто жив) и принимает решения. Работает по протоколу Raft. Диск контроллера — отдельный быстрый том под metadata log, не общая куча с `log.dirs` брокера. Для типичного кластера Apache пишет порядка **5 ГБ RAM и 5 ГБ диска** под metadata log — оценка проекта, не замер вашего кластера.

**Raft** — протокол согласия большинства. Контроллеры выбирают лидера метаданных этим протоколом.

**KRaft** — режим, в котором метаданные живут внутри Kafka, а не в ZooKeeper. С Kafka 4.0 ZooKeeper удалён. 4.3.1 — только KRaft. Миграция со старого ZooKeeper-кластера только через bridge-релиз **3.9**.

**Кворум (quorum)** — большинство голосов. Для 3 контроллеров большинство = 2. Если живых контроллеров меньше большинства, кластер не выбирает лидера метаданных и перестаёт принимать изменения (создание топиков, выборы лидеров партиций). Правило Apache: чтобы пережить N одновременных отказов контроллеров, нужно **2N+1** штук.

**Топик (topic)** — именованный поток сообщений (например `client.updated`). Это лог на диске, не таблица БД и не SoT.

**Партиция (partition)** — кусок топика. Параллелизм Kafka = число партиций. Один потребитель в классической consumer group читает одну партицию. Единица масштаба — партиция, не «ещё один Kafka». Слишком мало — потолок throughput и параллельных консьюмеров; слишком много — давление на контроллер, дольше восстановление, больше файлов, выше хвосты латентности.

**Реплика (replica)** — копия партиции на другом брокере. Нужна, чтобы при падении брокера данные не пропали.

**RF / replication.factor** — сколько копий у каждой партиции. RF=3 значит данные лежат на трёх брокерах. Дефолт прода: `default.replication.factor=3`. Concurrent rolling по одному брокеру в каждом ЦОДе при RF=3/min.ISR=2 может просадить ISR; в документации Confluent для 3 region приводят RF≥4 — для vanilla Apache это дисциплина выката, не отдельный параметр.

**Лидер (leader)** — та реплика, в которую пишут продюсеры. Остальные — followers, копируют данные с лидера.

**ISR (in-sync replicas)** — реплики, которые не отстали. Только они считаются достаточно свежими.

**min.insync.replicas (min.ISR)** — минимум живых ISR, без которого запись с `acks=all` отклоняется (`NOT_ENOUGH_REPLICAS`). Ручка «лучше отказать в записи, чем записать в одну копию». Прод: **2**. Если поставить 3 при RF=3, падение одного ЦОДа остановит запись.

**acks=all** — продюсер ждёт, пока запись подтвердят все текущие ISR (и при этом ISR не меньше min.ISR). Базовая настройка долговечности.

**unclean.leader.election.enable** — если `true`, лидером можно выбрать отставшую реплику ценой потери уже подтверждённых сообщений. Прод: `false` (значение по умолчанию).

**Rack awareness / `broker.rack`** — раскладка реплик по стойкам/ЦОДам. Без параметра Kafka имеет право положить две-три реплики в один ЦОД.

**Продюсер / консьюмер** — кто пишет / кто читает. Микросервисы, Camunda-воркеры, интеграционный API.

**Consumer group** — группа читателей одного топика: Kafka делит партиции между ними. Если воркеров больше, чем партиций — лишние будут простаивать. Каждая группа читает поток независимо (аудит, озеро, процессный движок) без повторной записи продюсером.

**Share group (очереди Kafka)** — другая модель чтения (KIP-932, production-ready с 4.2): несколько консьюмеров делят одну партицию позаписно. Включать точечно: `kafka-features.sh` / `share.version=1`. Для порядка внутри ключа обычно остаются классические consumer groups.

**Offset** — номер сообщения в партиции («я прочитал до сюда»). Внутренний топик offsets: в проде `offsets.topic.replication.factor=3`, иначе падение одного брокера ломает consumer groups.

**SASL** — протокол аутентификации. Механизмы: SCRAM, Kerberos (GSSAPI), OAUTHBEARER, PLAIN.

**SASL_SSL** — и аутентификация, и шифрование. Типичный прод-протокол для клиентов.

**SASL_PLAINTEXT / SASL/PLAIN без TLS** — пароль открытым текстом в сети. В проде недопустимо.

**SCRAM-SHA-512** — логин/пароль в метаданных Kafka. Официальная документация требует TLS для SCRAM: без него возможен перехват обмена и, при компрометации контроллеров, impersonation. Пароли задаются через admin API, не plaintext в `server.properties` на всех нодах.

**GSSAPI / Kerberos** — аутентификация доменным билетом, если в контуре уже есть Kerberos.

**OAUTHBEARER** — токен IdP (Keycloak и т.п.). В 4.x есть; в 4.3 ужесточены allowed URL для JWKS. Это жизненный цикл токенов, не «добавить строчку».

**ACL** — список «кому что можно»: читать топик, писать, создавать, администрировать. Отдельный principal на каждый сервис (`User:camunda`, …), least privilege. Не давать разработчикам `ALL` на кластер в проде.

**Authorizer / StandardAuthorizer** — модуль, который ACL проверяет. В KRaft — `StandardAuthorizer`, ACL хранятся в метаданных кластера. Ставить на брокерах и контроллерах. Поведение по умолчанию: нет ACL на ресурс → доступ только super.users. Не включать `allow.everyone.if.no.acl.found=true` в проде.

**super.users** — служебные учётки операторов и брокеров, не приложения.

**bootstrap.servers** — список 2–3 брокеров, с которых клиент узнаёт весь кластер. Это точка входа, не «все брокеры мира».

**Page cache** — кэш диска в оперативной памяти ядра Linux. Kafka кладёт сообщения на диск, а читает горячий хвост лога из этого кэша. Поэтому брокеру нужна свободная RAM **не в куче JVM**.

**Куча JVM (`-Xmx`)** — куча нужна под метаданные, сетевые буферы, индексы. Официальный пример Apache для нагруженного кластера LinkedIn: **6 ГБ** (`-Xmx6g -Xms6g`) и G1GC. Раздуть кучу до 32 ГБ — отнять память у page cache.

**Strimzi** — оператор Kubernetes (CNCF) для Kafka. Strimzi **1.2.0** официально поддерживает Kafka 4.3.1. Drain Cleaner / cordon (в 1.2.0 для Kafka 4.3+ — cordoning при scale-down): без этого Kubernetes убьёт под с лидерами партиций. User Operator заводит пользователей декларативно.

**Stretch-кластер** — один логический кластер Kafka, брокеры и контроллеры физически в нескольких ЦОДах. Нужна прямая L3-связность. Если K8s в ЦОДах изолированы без pod-to-pod — stretch не взлетит: три отдельных Kafka + MM2.

**MirrorMaker 2 (MM2)** — копирует топики между разными кластерами. МежЦОДовая доставка асинхронная: RPO > 0, дубли, offsets не те же, именование `source.topic`. MM2 сам должен быть отказоустойчивым.

**Combined mode** — один процесс и брокер, и контроллер (`process.roles=broker,controller`). Удобно для теста. Не для прода: документация KRaft «not recommended in critical deployment environments» — контроллер нельзя катить отдельно, он делит GC и диск с нагрузкой клиентов.

**Isolated mode** — `process.roles=controller` **или** `broker`, никогда оба в проде. Минимум прода при трёх площадках: 3 контроллера по одному в ЦОД; 5 (например 2+2+1) — спокойнее rolling upgrade. Минимум брокеров для RF=3: не меньше одного в каждом ЦОДе, итого ≥ 3; дальше 3, 6, 9, … равномерно.

**Динамический кворум (KRaft v1, с 4.1)** — `controller.quorum.bootstrap.servers`, добавление/удаление утилитой `kafka-metadata-quorum.sh`. Для greenfield 4.3.1 сразу форматировать как dynamic, не тащить статический `controller.quorum.voters`. `kafka-storage.sh format --standalone` на тесте; в проде пустые диски автоформатировать нельзя: пустой диск большинства контроллеров может выбрать лидера без уже закоммиченных метаданных.

**`cluster.id` / `node.id`** — идентификатор кластера и ноды. Диски форматируют `kafka-storage.sh` с этим id.

**Kafka Connect** — коннекторы «Kafka ↔ внешние системы», отдельные процессы. Java минимум 17.

**Kafka Streams** — библиотека потоковой обработки внутри JVM-приложения, не отдельный сервер. Клиенты и Streams допускают Java 11. Брокеры: официально Java 17, 21 и 25; Apache рекомендует свежий LTS (на момент доки 4.3 — Java 25).

**Утилиты** — `kafka-storage.sh`, `kafka-topics.sh`, `kafka-acls.sh`, `kafka-metadata-quorum.sh`, `kafka-reassign-partitions.sh`, `kafka-features.sh`.

**Schema Registry (Confluent / Apicurio)** — реестр схем Avro/JSON Schema/Protobuf. Не часть дистрибутива Kafka. Без схем event-модель превращается в несовместимый JSON.

**UI (AKHQ, Kafdrop, Conduktor)** — не часть дистрибутива.

**Cruise Control** — автоперекладка партиций при добавлении брокеров (отдельный проект; в образах Strimzi есть). Иначе после scale-out данные остаются на старых брокерах. Ручной путь: `kafka-reassign-partitions.sh`.

**At-rest encryption** — в open-source Kafka нет встроенного шифрования топиков на диске. LUKS / шифрование томов Kubernetes / hardware.

**Retention / compaction** — сколько лог хранить по времени/размеру или сжимать по ключу. Без политики хранения кластер упрётся в диск.

**Tiered storage** — вынос старых сегментов в object storage (S3-совместимое). В 4.x есть, отдельный контур. Не включать «на всякий случай» без политики хранения.

**JBOD / несколько `log.dirs`** — несколько локальных дисков у брокера допустимы. RAID «для надёжности» часто вреден: надёжность уже в репликации, RAID-rebuild убивает латентность.

**`auto.create.topics.enable`** — автосоздание топика при первой записи. На тесте можно; в прод — `false`, иначе сервисы плодят топики без RF/ACL.

**`transaction.state.log.replication.factor` / `min.isr`** — внутренний топик транзакций: в проде 3 и 2, согласовано с пользовательскими топиками.

**Идемпотентный продюсер** — в современных клиентах по умолчанию включён. Вместе с `acks=all` и ключом партиции — контракт клиента.

**Ключ сообщения (partition key)** — от него зависит, в какую партицию попадёт запись, порядок внутри ключа и «горячие» партиции.

**Under-replicated partitions / ISR < RF** — сигналы мониторинга вместе с request latency, disk, page cache / miss-чтение, лагом консьюмеров, здоровьем кворума.

**Quota** — квоты, чтобы один зависший консьюмер не забил диск и сеть.

**mTLS** — взаимные сертификаты. Сложнее в выдаче, сильнее привязывает identity к PKI.

**PLAINTEXT** — без TLS. Только изолированная сеть стенда.

**Confluent Platform / форк** — другое поведение, лицензия, обвязка. Файл про Apache Kafka 4.3.1.

**Greenfield** — новый кластер, не миграция с ZooKeeper.

**Overlay / jitter** — сеть подов. Если между ЦОДами хуже VM — брокеры иногда лучше на hostNetwork или вне K8s. Решение по замерам.

**Vault / Kubernetes Secrets** — пароли SCRAM и keystore не в Git и не в открытом ConfigMap.

**QPS / MB/s** — нагрузка неизвестна: в файле нет числа брокеров «хватит для прода» и размера диска. Есть минимум для отказоустойчивости.

Источники формулировок: глоссарий и тело `Apache Kafka.md`. Новых порогов RTT и размеров диска здесь нет. Ориентиры 5 ГБ контроллера и куча 6 ГБ — из документации Apache, не смета вашего кластера.
