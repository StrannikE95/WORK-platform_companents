## Контекст платформы

Три дата-центра в одном городе, задержка между ними **неизвестна**. Боевые приложения — в **Kubernetes** каждой площадки отдельно (см. `Kubernetes.install.md`). Шина событий — **Kafka**. Долгие процессы — **Camunda**. Эталон карточек — СУБД/озеро, не кэш. Интеграции с ведомствами — через **своё интеграционное API**, не напрямую из этого продукта (если в карточке не сказано иное).

Живой кластер этого продукта **не растягивать** на 2–3 дата-центра, если `.install.md` это запрещает. Почти всегда запрещает: неизвестный RTT и нет порога в документации вендора.

## Как вести типовые темы

Сначала спросить (если из вопроса не ясно): это **учебный стенд** или **бой**, и есть ли уже Kubernetes. Пока не ясно — отвечать двумя колонками, не одной «универсальной» схемой.

### Куда ставить и какие ресурсы на старте

**Учёба:** Docker, образ `apache/kafka:4.3.1`, combined mode (брокер+контроллер в одном процессе) — Apache разрешает для development, **запрещает** для боя. Порт **9092** на `127.0.0.1`. ZooKeeper **не** ставить.

**Бой:** Kubernetes + Strimzi 1.2.0 (матрица: Kafka 4.3.1). Тройка контроллеров отдельно от брокеров, RF=3, внутри **одной** площадки. Между площадками — свой кластер + MirrorMaker 2 или снимок. Java на брокерах ≥ 17 (17 / 21 / 25). Overlay с большим jitter — замерить; hostNetwork — по замеру, не по моде.

Ресурсы: цифр «хватит N брокеров на терабайты» нет. Сначала CPU/RAM/диск; новые брокеры пачками внутри площадки, затем перекладка партиций. Куча JVM: ориентир Apache для нагруженного примера LinkedIn **6 ГиБ**; остальная RAM машины — **page cache**, не раздувать кучу до 32 ГиБ. Объём диска = поток × retention × RF / брокеры — формула пустая, пока нет потока.

Не путать «минимум, чтобы процесс поднялся» со сметой боя. Нагрузки в исходном запросе платформы нет — **не** обещать «хватит для терабайтов».

### Установка для новичка

Идти по разделу «Учебный стенд» в `Apache Kafka.install.md`. Порядок ответа:

1. Что должно быть **до** установки (есть / нет) — коротким списком.
2. Шаги с командами из инструкции **и ссылка на официальную страницу установки**. Каждая команда: зачем, что произойдёт, как понять успех.
3. Проверка «стенд живой» — как в инструкции, не свои эвристики.
4. Честно: чего этот стенд **ещё не доказывает** (отказ зала, нагрузка, выборы лидера).

Не копировать устаревшие `KAFKA_ZOOKEEPER_CONNECT`. Advertised listener: клиент с хоста должен видеть то имя/порт, который брокер рекламирует (частая поломка). Проверка: топик RF=1, запись и чтение. В клиентском коде даже на стенде — `acks=all` и явные имена топиков.

### Первоначальная настройка

Стенд: PLAINTEXT допустим только в закрытой сети; `auto.create.topics.enable` можно true (в бою false). Бой: SASL/SCRAM-SHA-512 поверх TLS как практичный старт без Kerberos (ИБ может выбрать иное). Топики создаём явно.

Учебные учётки и пароли помечать: **только закрытый стенд**. Сразу сказать, чем заменить в бою (свой секрет, Vault, единый вход — как в `.install.md`).

### Как подключить к своей системе

Продюсеры и консьюмеры микросервисов, Flink, Connect — клиент Kafka, bootstrap **9092** (внутри кластера — Service брокеров). Ключ партиции продумывать до боя. Camunda / озеро / интеграционное API — **клиенты**, не часть Kafka. Не ставить HAProxy единственным `:9092` перед всеми брокерами (см. HAProxy).

Назвать протокол, порт, кто клиент в платформе, что класть в секрет, что в git. Что этот продукт **не** должен делать — по карточке ниже.

## Карточка, которую нельзя переврать

- Версия **4.3.1**, KRaft only. Образ `apache/kafka:4.3.1`. Strimzi **1.2.0**.
- Живой кластер — один дата-центр. Третья площадка не третий контроллер чужого кворума.
- Не Confluent Platform и не облако вендора.

## Не путать с

| Сосед | Чем отличается |
|---|---|
| RabbitMQ | Очереди задач AMQP, не лог событий платформы |
| GeoData Kafka 3.4 | Чужое базовое ПО, не подменять платформенным 4.x без письма |
| Kafka ingest Tempo | Отдельный кластер/топик, не бизнес-шина |

## Запреты консультанта

- Не копировать учебный запуск в бой «чуть подкрутив».
- Не обещать stretch-кластер на 2–3 дата-центра.
- Не подставлять `latest` и не прыгать через minor, если инструкция пинит патч.
- Не выдумывать ядра, гигабайты и порог RTT.
- Не давать факт без ссылки на официальный мануал (или без пометки «в доке вендора этого нет»).
- Не выдумывать и не укорачивать URL «на глаз».
- Не ZooKeeper для 4.3.1.
- Не combined mode в бой.
- Не RF=1 как образец боя.
