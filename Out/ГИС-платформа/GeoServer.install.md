# GeoServer 2.24.4 — установка и конфигурирование

Связанный документ (зачем система, из каких программ состоит, порты, железо): `GeoServer.md`.

Этот файл — **как поставить и настроить**. Настройки с учебной машины в бой не копируйте.

## Что вы ставите

GeoServer — сервер карт и объектов по протоколам OGC. Ставите **классический** WAR/Docker OSGeo версии **2.24.4** (18 июня 2024). Это **не** платформа GeoData и **не** GeoServer Cloud (другой дистрибутив, свой Helm).

Образ: `docker.osgeo.org/geoserver` — пин **`2.24.4`**, не тег **`2.24.x`** (в руководстве 2.24 это nightly, *не для боя*). Если тега 2.24.4 в реестре нет — свой образ из **WAR 2.24.4** на Tomcat 9. Документация линии: https://docs-archive.geoserver.org/2.24.x/en/user/

Официального оператора Kubernetes под WAR 2.24 нет.

**Прочитать до установки.** Линия **2.24.x** закончила жизнь в **августе 2024**. На дату этого файла — два года без официальных патчей. 2.24.4 закрывал в том числе удалённый запуск кода (CVE-2024-36401). Всё, что нашли после июня 2024, проект в 2.24.x **не чинит**. Считать 2.24.4 готовым к бою с гособменом без отдельного решения ИБ **нельзя**. Поддерживаемая линия на август 2026 — другой документ.

Один каталог данных, размазанный сетевой папкой на несколько дата-центров, здесь **не собираем**: блокировки файлов и задержка сети дают битый XML, не устойчивость. Живые ноды — в одной площадке. Вторая — копия каталога и переключение PostGIS.

---

## О чём эта инструкция молча договорилась

1. **Активный GeoServer в одном дата-центре** (JVM + каталог + доступ к PostGIS). Другие залы — клиенты на 443 и восстановление. Общий диск каталога на несколько городов — риск порчи списка слоёв.
2. Классический WAR/Docker, не Cloud и не Enterprise.
3. Учебный стенд — закрытая сеть. Java 11 — опорный runtime линии 2.24; Java 17 в доке 2.24 — экспериментально.
4. Цифр запросов в секунду нет — нет цифры кучи. Хранилище — PostGIS; запись через WFS в бою выкл.
5. Два дата-центра: актив в первом, запас каталога и PostGIS во втором. Три — то же плюс ещё одна копия. Третий зал **не** третий писатель каталога.
6. Экспериментальные модули «кластер каталога» в бою не считаем официальной устойчивостью (нет патчей после конца жизни 2.24).
7. Лицензия GPL.

---

## Учебный стенд: одна площадка, без нагрузки

**Зачем:** слой из PostGIS, стиль, картинка карты и объекты. **Не зачем:** отказ дата-центра и ёмкость тайлов.

### Что должно быть до установки

- Docker **или** однонодовый Kubernetes.
- Порт 8080 свободен на этой машине.
- Сеть стенда не торчит в интернет.

### Установка (Docker — основной путь для учёбы)

Проверить наличие тега в реестре, затем:

```bash
docker pull docker.osgeo.org/geoserver:2.24.4
docker run -d --name geoserver-dev \
  -p 127.0.0.1:8080:8080 \
  -v geoserver-data:/opt/geoserver_data \
  docker.osgeo.org/geoserver:2.24.4
```

Привязка к `127.0.0.1` обязательна. Интерфейс: `http://127.0.0.1:8080/geoserver`. Заводские **`admin` / `geoserver`** — сменить сразу. Пустой каталог образ может заполнить **учебными слоями**; в бой их уносят.

Глава Docker руководства 2.24 показывает `2.24.x` — **не** копировать в бой и лучше не на препрод.

Расширения — zip **той же** 2.24.4. На стенде имеет смысл стабильный модуль лимитов запросов, не экспериментальный JAR с nightly.

На Kubernetes для учёбы: Deployment **1** реплика, диск только этому поду. **Не** три реплики с этого YAML в бой.

### Какие настройки на тесте упрощаем

| Параметр | На тесте | Зачем так |
|---|---|---|
| Число нод | 1 | Не учимся переживать выкат |
| Каталог | один том | Не учим блокировки сетевой папки |
| Кэш тайлов | локальный | Нет тысяч клиентов |
| Пароль | не `geoserver`, сеть закрыта | Заводской пароль в доке открытым текстом |
| Экспериментальный кластер | не ставить | Иначе шина сообщений вместо карты |
| Запись через WFS | выкл, если не цель стенда | Привычка записи через GeoServer |

Чего **не** упрощаем: слой живёт в **хранилище**, не «в GeoServer»; публичный базовый URL, если уже есть вход; плагин = версия сервера; nightly ≠ 2.24.4.

### Как понять, что стенд живой

1. Capabilities и GetMap отвечают. В статусе — **2.24.4**.
2. Убрали PostGIS — карта пустая при живом контейнере.
3. Порт 8080 не с корпоративной сети без фильтра: линейка без патчей, удалённый запуск кода в прошлом уже был.

### Что хорошо и что плохо в такой схеме

| Хорошо | Плохо |
|---|---|
| Быстрый путь Docker | Нет модели отказа, нет общего кэша |
| Дешёво показывает стиль на вашей геометрии | Успех на одном поде ≠ общий диск через город |
| | Даже стенд не светить наружу: линейка без патчей |

Перед боем полезен **препрод**: 2.24.4, внешний каталог, лимиты запросов, PostGIS, вход с TLS, две реплики с выбранной схемой каталога — всё **в одном** дата-центре.

## Бой: один живой дата-центр, второй — запас каталога и PostGIS

**Зачем:** пережить отказ **пода внутри площадки** (вторая JVM за входом, если каталог решён). Отказ **дата-центра с активным GeoServer** = нет карты, пока не восстановите каталог и не переключите PostGIS. Устойчивость PostGIS — в `PostgreSQL.install.md`, не в этом файле.

### Почему каталог не растягиваем на несколько дата-центров

В ядре **нет** кворума. «Кластер» в production-документации — несколько узлов за прокси и **одна** правда списка слоёв. Общий каталог на сетевой папке между городами: задержка блокировок XML, два писателя = порча. Экспериментальная шина не возит **данные слоёв**. Три реплики на диске «только одному поду» не стартуют.

### Как расставить машины

**В активном дата-центре:**

- Не меньше **двух** JVM за входом, на разных нодах **этого** зала.
- Схема каталога **без** шаринга через город:
  - **предпочтительно:** каталог выкатывается пайплайном, ноды только читают; админка и REST записи — с прыжкового хоста на **один** писатель;
  - либо общий диск **только внутри зала** после замера блокировок и скорости;
  - два пода + **один** диск «только одному» не бывает.
- PostGIS: учётка только чтение. WFS без транзакций.
- Кэш тайлов: общее хранилище **в зале** или стабильное расширение в объектку; свой каталог на каждом поде = мигание картинки.
- Каталог данных снаружи приложения (`/opt/geoserver_data` в Docker 2.24).
- Публичный базовый URL = ваш HTTPS.
- Лимиты запросов на **каждой** ноде (они считают **инстанс**, не кластер).
- Образ/WAR **2.24.4**.
- Админку на читателях часто выключают; `/web` не в интернет.

**Между площадками:**

| Сколько площадок | Что где | Если умер активный дата-центр |
|---|---|---|
| **Две** | Первая: живые ноды + каталог + доступ к PostGIS. Вторая: клиенты ходят на 443 первой; холодная копия каталога + копия PostGIS | Нет карты, пока восстановление и переключение. Время замерить |
| **Три** | Третья как вторая | То же; не три писателя каталога |

GeoServer Cloud / чужой Helm — **другой** дистрибутив, не этот экземпляр 2.24.4.

### Что должно быть до боевой установки

- Письменное решение ИБ: остаёмся на линейке с закончившейся жизнью.
- Замер задержки: под → PostGIS, под → диск каталога — **внутри** активного зала.
- Бэкап: каталог данных + файлы прав + PostGIS. Тайлы можно пересчитать; список слоёв — нет.
- Сертификаты на входе. Cookie сессии: флаг Secure.
- Расширения только стабильные той же 2.24.4.

### Порядок установки в активном дата-центре

1. Собрать/пролить **2.24.4** + модуль лимитов запросов (и расширение тайлов в объектку, если нужно).
2. Вынести каталог. Сменить `admin` и пароль хранилища ключей (переменные образа 2.28 вслепую не копировать — проверить на теге 2.24.4).
3. Снять учебные слои.
4. Вход TLS, публичный базовый URL, белый список CSRF (не выключать защиту).
5. Белый список разбора XML; режим «без ограничений» **выкл**.
6. CORS — явный адрес вашего UI, не «любой сайт» из примеров Tomcat.
7. Страница статуса: не светить переменные окружения (в 2.24.4 чинили утечку).
8. Журнал — профиль боя, не подробный учебный.
9. Проверка готовности: не только «Tomcat принял 8080», а GetMap известного слоя **успешен**.

Второй под: понять, **когда** он видит смену стиля (рестарт / перечитка / никогда). Пока не поняли — это не кластер, это две копии.

### Правила конфигурации боя

| Слой | Правило |
|---|---|
| Сеть | 8080 не в интернет; админка и REST из внутренней сети |
| JDBC | пароли не в git и не в Capabilities |
| HSTS | на входе (в GeoServer по умолчанию выкл) |
| JVM | `-Xms` и `-Xmx` явно и равны по смыслу; лимит пода **выше** кучи |
| Лимиты запросов | на каждой ноде; пример «на 4 ядра» — старт, не смета |
| Политика сбоя подов | не снимать все поды зоны сразу |

Не включать два экспериментальных механизма синка каталога сразу. Шину с рассылкой «всем в сети» в Kubernetes обычно не заводят.

### Как расти, когда появятся цифры нагрузки

1. Картинки карты → ноды **и** лимиты (ориентир модуля: ~2× ядер параллельных GetMap **на инстанс**).
2. Подложка → предрасчёт тайлов, не гигантская куча.
3. Объекты → лимит числа и индексы PostGIS; вектору лишняя память почти не помогает.
4. Растр → куча + пирамиды, не сотни мелких файлов без обзоров.

### Проверки, без которых это ещё не бой

1. В статусе **2.24.4**, не nightly. Пароль не `geoserver`. Учебных слоёв нет.
2. В Capabilities URL внешние, не внутренний адрес.
3. Выключили под: карта жива. Запись через WFS отказ. Запись в эталон через JDBC не проходит.
4. Восстановили каталог + PostGIS на стенде.
5. Учение «активный дата-центр выключен»: карты нет, пока запас. Учение «PostGIS мёртв»: пустая карта при живых подах — ожидаемо.
6. ИБ зафиксировала риск линейки без патчей.

### Что хорошо и что плохо в схеме «актив в одном дата-центре + запас»

| Хорошо | Плохо |
|---|---|
| Каталог не шарится через город | Падение этого зала = нет карты у всех |
| Меньше экспериментальных модулей | Время восстановления = каталог + хранилище, минуты надо замерить |
| Чтение масштабируется подами внутри зала | Дыры после 2.24.4 апстрим не закроет |
| Тайлы в объектку — стабильное расширение | Лимиты считают ноду; слепой автомасштаб = нехватка памяти |

**Не готово к бою**, если: тег nightly; пароль `geoserver`; учебные слои; один под как «бой»; три реплики на диске «только одному»; общий каталог через город; запись через WFS «на всякий случай»; CORS любой сайт; CSRF выкл; XML без ограничений; карта назначена эталоном; линейка 2.24 в аттестованном контуре **без** фиксации конца жизни; путаница с GeoData.
