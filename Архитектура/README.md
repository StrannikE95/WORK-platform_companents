# Архитектура развёртывания — как работаем

Цель: до разработки зафиксировать **способ развёртывания** так, чтобы Dev воспроизводил ошибки Prod (тот же механизм и та же роль-модель, меньше ёмкость).

Это не карта «поставьте все продукты прямо сейчас». Слои идут **сверху вниз**. Нижний слой не заполняем, пока верхний не закрыт.

## Порядок слоёв

| # | Папка | Вопрос слоя | Когда закрыт |
|---|---|---|---|
| 1 | Модель сред | Сколько контуров, сколько ЦОДов, как изолированы | Есть список сред и роль каждого ЦОДа |
| 2 | Платформа | Общий «пол» контура: K8s, вход, диски, DNS, секреты, накат | Есть кластеры, пулы, три требования Task_6 |
| 3 | Политика размещения | Куда кладём каждый продукт из `sample/` | У каждой строки статус не `РЕШИТЬ` |
| 4 | Эталонные топологии | 4–6 классов (stateless, кворум, остров…), не 36 уникальных схем | Классы согласованы, в них разложены продукты |
| 5 | Каталог инстансов | Сколько копий и что шарим | Таблица инстансов без дыр «сколько?» |
| 6 | Способ наката | Чем ставим (оператор / Helm / пакеты / вендор) | Механизм совпадает с политикой и паритетом Dev=Prod |
| 7 | IaC | Как это окажется в Git | Репозитории и overlays, ещё не код |

Выход Task_6 (`sample2/` с Prod/Dev-инструкциями на продукт) — **после** слоёв 1–6. Сейчас не делаем.

## Легенда статусов в файлах

| Метка | Значение | Что делать вам |
|---|---|---|
| **ЗАФИКСИРОВАНО** | Взято из `Контекст/Tasks/Task_6.txt` или из `sample/` | Менять только если меняете постановку |
| **ПРЕДЛОЖЕНО** | Черновик. Рядом явно написано **допущение** | Подтвердить, поправить или вычеркнуть |
| **РЕШИТЬ** | Без вашего ответа слой нельзя честно закрыть | Вписать ответ в поле `Ответ:` |

Термины в скобках при первом появлении — для чтения без словарного запаса архитектора.

## Источники (важно)

- Состав ПО — **только** `sample/`.
- `Архитектура/5. Каталог инстансов/IT-landscape.md` и `.xlsx` — прошлый артефакт общей картины. **Не копировать** оттуда решения «молча»: в постановке сказано, что там могут быть незамеченные допущения.
- Карточки `Out/**/*.md` и `*.consultant.md` пригодятся позже, когда дойдём до продукта. Сейчас не опора.

## Допущения этого предзаполнения

1. Рамка ЦОДов — из Task_6 (Dev = 1 ЦОД, Prod = 2 ЦОД + 1 ЦОД под бэкапы), а не из `Common.txt` (там «3 ЦОДа» без роли бэкапа).
2. Сеть в деталях (VLAN, IP-план) не описываем. Три платформенных требования Task_6 (вход, диски, DNS) — да.
3. Нагрузка не замерена — не включаем «все фичи масштабирования вендора».
4. Кастомные микросервисы и интеграционный API на 30+ ведомств в `sample/` **нет**. В каталоге они как логический контур, не как продукт.
