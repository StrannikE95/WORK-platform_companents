|---|---|
| StorageClass `local-ssd`: RWO, локальный SSD, CSI, для stateful-операторов | **ЗАФИКСИРОВАНО** |
| StorageClass `shared-fs`: RWX, только по списку исключений | **ЗАФИКСИРОВАНО** |

## 2.4. DNS и переключение A→B

| Требование | Статус |
|---|---|
| Внутри кластера — CoreDNS / `cluster.local` | **ЗАФИКСИРОВАНО** |
| Снаружи — зона `oreon.moskva.ru` | **ЗАФИКСИРОВАНО** |
| Клиенты — FQDN, не Pod IP | **ЗАФИКСИРОВАНО** |
| Advertised listeners Kafka — внешние FQDN, не Pod IP | **ЗАФИКСИРОВАНО** (смысл Task_6) |

**Advertised listeners** — адреса, которые брокер сам отдаёт клиенту после первого контакта.

| Решение | Статус | Содержание |
|---|---|---|
| Шаблон имён | **ПРЕДЛОЖЕНО** | Dev: `<сервис>.dev.oreon.moskva.ru` → VIP Dev. Prod (то, что видят клиенты): `<сервис>.oreon.moskva.ru` → **сейчас** VIP ЦОД-A. При уходе на B **то же имя** перенацеливают на VIP ЦОД-B. Иначе клиентам менять конфиг — это уже окно. **Допущение.** |
| Имена VIP площадок (чтобы дежурный знал куда щёлкать) | **ПРЕДЛОЖЕНО** | Служебные имена вроде `edge-a.oreon.moskva.ru` и `edge-b.oreon.moskva.ru` на VIP A и B; клиентские `<сервис>.oreon.moskva.ru` на них переключают. **Допущение.** |
| Кто ведёт зону | **РЕШИТЬ** | AD / PowerDNS / BIND / «команда ЦОДа, зона есть». Без этого слой 6 не знает, куда класть записи. |

**Слабое место.** TTL клиентских имён должен быть коротким, иначе «минуты» при смерти A превратятся в «TTL ещё не истёк». Число TTL здесь не ставим (сеть вне рамок), но требование к дежурному переключению без этого не выполняется.
