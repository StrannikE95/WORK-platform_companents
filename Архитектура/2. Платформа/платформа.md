## 2.1. Kubernetes-кластеры

| Решение | Статус |
|---|---|
| Kubernetes **1.36.4**, kubeadm, containerd | **ЗАФИКСИРОВАНО** |
| Кластеры: 1 Dev, 1 ЦОД-A, 1 ЦОД-B | **ЗАФИКСИРОВАНО** |
| Control plane **×3** на каждом (Dev — 3 маленьких) | **ЗАФИКСИРОВАНО** |
| ControlPlaneEndpoint :6443 — VIP HAProxy **этого** ЦОДа | **ЗАФИКСИРОВАНО** (Task_6) |
| GeoData — отдельный кластер Kubernetes **1.24**, не платформенный 1.36 | **ЗАФИКСИРОВАНО** |
| Имя CNI — на реализации. CNI **обязан** исполнять NetworkPolicy. Строгий default-deny **не** в день 1 | **ЗАФИКСИРОВАНО** |
| HTTP-роутер **внутри** кластера: **Gateway API**. Имя контроллера — на реализации. Без контроллера объекты не используем | **ЗАФИКСИРОВАНО** |

Gateway API выбирает Service по Host/path. Поды выбирает Service. Это не API Gateway/BFF.

Как HAProxy (или «балансировщик ЦОДа») дотягивается до контроллера Gateway API — см. уточнения: ответ «K8s LoadBalancer» с этим не сведён.

## 2.2. Вход — зафиксировано частично

| Решение | Статус |
|---|---|
| Пара HAProxy **3.4.3** + Keepalived на хосте, две Linux-VM, пакеты/бинарник, не Compose | **ЗАФИКСИРОВАНО** |
| VIP: :6443 TCP к API **и** HTTP(S) | **ЗАФИКСИРОВАНО** (Task_6) |
| Kafka :9092 через этот HAProxy не публикуем | **ЗАФИКСИРОВАНО** |
| SafeLine не делит 80/443 с HAProxy на той же VM | **ЗАФИКСИРОВАНО** |

Цепочка, записанная пользователем (прикладной HTTP), **ещё не сведена** с HAProxy и Gateway API:

```text
GSLB / Global Traffic Manager
  → Anti-DDoS
  → WAF
  → балансировщик ЦОДа
  → K8s LoadBalancer
  → APISIX
  → Portal / BFF
  → доменные сервисы
```

В `sample/` нет GSLB, Anti-DDoS, APISIX. Есть Spring Cloud Gateway.

Keepalived — зависимость без файла в `sample/`, в каталог (слой 5).

1. **«Балансировщик ЦОДа» = наша пара HAProxy + Keepalived?**

   (а) Service типа `LoadBalancer` в кластере (нужен MetalLB или аналог — второй VIP рядом с HAProxy);  
   (б) так назван вход **Gateway API** (балансировщик ЦОДа бьёт в NodePort/порт контроллера) — отдельного LoadBalancer нет;  
   (в) своё.

3. **APISIX и Gateway API** — это  
   (а) APISIX **и есть** контроллер Gateway API (один продукт);  
   (б) Gateway API (контроллер выберем) **и отдельно** APISIX как API Gateway;  
   (в) APISIX вместо Gateway API (тогда «Да, Gateway API» отменяем).

4. **APISIX vs Spring Cloud Gateway** из `sample/`: замена / два шлюза с разными ролями / SCG не ставим?

5. **GSLB и переключение A→B:** GSLB сам уводит трафик с A на B, а запись AD/`edge-a` — запасной ручной контур? Или GSLB только «глобально», а A/B внутри города по-прежнему щёлкает дежурный в AD?

7. **Ubuntu 22.04 LTS или 24.04 LTS** на нодах K8s и HAProxy (одна на Dev/A/B). GeoData всё равно 22.04 на острове.
