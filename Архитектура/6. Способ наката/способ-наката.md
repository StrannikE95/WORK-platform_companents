# 6. Способ наката

**Зачем слой.** Способ наката — *чем* ставим и *откуда* берётся желаемое состояние. Паритет Dev/Prod ломается здесь: Prod = оператор, Dev = «docker compose up» из `sample/`.

**Как закрыть.** После слоёв 3 и 5: у каждой строки каталога должен быть механизм, **одинаковый** в Dev и Prod (другие values: меньше CPU/диск).

Сейчас — правила и вопросы. Не пишем команды установки.

---

## 6.1. Правила

| Правило | Статус |
|---|---|
| Dev и Prod — один механизм (оператор / Helm / пакеты / вендорский installer) | **ЗАФИКСИРОВАНО** |
| Compose не является боевым механизмом, кроме явного исключения вендора | **ЗАФИКСИРОВАНО** |
| Quickstart из `sample/` — учебный стенд, не переносится в Prod и не становится «Dev» | **ЗАФИКСИРОВАНО** духом постановки |
| Для Kubernetes желаемое состояние — в Git | **ПРЕДЛОЖЕНО** | Если подтвердите Argo CD в слое 2. **GitOps** — кластер сам подтягивает описание из Git, а не человек делает `kubectl apply` с ноутбука. **Допущение.** |

---

## 6.2. Четыре допустимых механизма

| Код | Что это | Когда |
|---|---|---|
| `operator` | Custom Resource (свой объект API: `Kafka`, `Cluster`, …) | слой 3 = K8s + есть официальный оператор |
| `helm` | чарт, без оператора | вендор даёт Helm, оператора нет |
| `systemd` | пакеты на VM | слой 3 = VM-пакеты или запасной путь Task_6 |
| `vendor` | инсталлятор/репозиторий вендора | остров |

`compose` — только строки, помеченные исключением (кандидат: SafeLine).

`kubectl apply` манифестов с диска человека — не механизм контура: нет паритета и аудита.

## 6.3. Вопросы платформенного наката

| Вопрос | Статус | Черновик |
|---|---|---|
| GitOps-контроллер | **ПРЕДЛОЖЕНО** Argo CD | Нужен Git, куда класть overlays `prod` / `dev`. |
| Кто имеет право merge в Git контура | **РЕШИТЬ** | Иначе GitOps = «кто угодно меняет Prod». |
| Секреты в Git | **ПРЕДЛОЖЕНО** | В Git — ссылки/шаблоны, значения — Vault (если Vault подтвердите). Не пароли в values.yaml. **Допущение.** |

## 6.4. Матрица механизмов (заполнять после слоя 3)

Не заполняйте «Strimzi» везде заранее. Строка появляется, когда runtime в политике выбран.

| Инстанс из каталога | Механизм | Артефакт (чарт/CR/playbook/вендор) | Overlay Dev vs Prod | Статус |
|---|---|---|---|---|
| Kubernetes (сам кластер) | kubeadm | | те же шаги, меньше машины | из sample |
| HAProxy + Keepalived | **ПРЕДЛОЖЕНО** `systemd` | конфиг в Git | меньше `maxconn`/CPU | слой 3 |
| SafeLine | **ПРЕДЛОЖЕНО** `compose` как исключение | релиз вендора | меньше VM | слой 3 |
| GeoData / Luxms | `vendor` | | тот же installer | слой 3 |
| Остальные | | | | ждать слой 3 |

Kafka: если слой 3 подтвердит K8s — механизм из sample это **Strimzi 1.2.0**, не docker-compose из quickstart. Flink: Operator **1.15.0**. Vault: Helm HA Raft. Это **кандидаты из sample**, не закрытый каталог.

## 6.5. Критично для паритета

- Смена механизма при нехватке RAM на Dev («давайте на Dev одной VM») **запрещена** постановкой. Режут values, не класс.
- Обновление: тот же канал (тот же оператор/пакет), иначе ошибка «на проде при накате по-другому» снова не ловится.
- Версии пинить (не `latest`) — уже принято в `sample/`; в контуре то же.
