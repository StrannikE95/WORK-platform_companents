**Зачем слой.** Одна таблица: продукт из `sample/` → куда кладём в Prod и Dev. Это замена «36 независимых картинок». Пока строка в статусе **РЕШИТЬ**, эталонную схему продукта не рисуем.

**Как закрыть.** Пройти таблицу. Сначала подтвердить правила, потом строки. Класс топологии (колонка) — из слоя 4; пока можно писать черновик класса.

Источник строк — `sample/`. Решения из `IT-landscape.md` сюда не переносить.

## 3.1. Правила (уже в постановке)

| Правило | Статус |
|---|---|
| Есть официальный оператор под наш K8s **и** данные не требуют сырых дисков → Kubernetes | **ЗАФИКСИРОВАНО** |
| Вендорский стек / остров (свой инсталлятор, свои версии K8s/Kafka/БД) → как велит вендор, отдельные VM/кластер | **ЗАФИКСИРОВАНО** |
| Много локальных дисков / объектное хранилище (кольца) → VM или физический сервер | **ЗАФИКСИРОВАНО** |
| Запасной боевой путь: пакеты на Linux-VM (systemd), не Docker Compose | **ЗАФИКСИРОВАНО** |
| Compose — учебный стенд и **явные** исключения вендора, не «запасной прод» | **ЗАФИКСИРОВАНО** |
| Dev = тот же механизм, меньше ёмкость | **ЗАФИКСИРОВАНО** |

**Оператор** — программа в Kubernetes, которая по описанию («хочу Kafka из 3 брокеров») сама держит поды, диски и обновления. Пример в `sample/Apache Kafka.md`: для Kubernetes указан **Strimzi 1.2.0**.

## 3.2. Как читать статусы строк

- **ЗАФИКСИРОВАНО** — прямо следует из Task_6 или однозначной фразы `sample/`.
- **ПРЕДЛОЖЕНО** — правило + sample указывают направление; вы подтверждаете.
- **РЕШИТЬ** — sample описывает quickstart, а бой можно сделать несколькими способами. Не угадываем.

Колонка «Dev» везде подразумевает **тот же механизм**. Не дублируем, если нечем отличить кроме размера.
