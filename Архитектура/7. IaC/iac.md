# 7. IaC

**Зачем слой.** IaC (Infrastructure as Code) — описание инфраструктуры и приложений **файлами в Git**, а не кликами в UI. Это и есть долгоживущий «способ развёртывания». Схемы mermaid — вид сверху, они устаревают; Git — источник правды.

**Как закрыть.** Когда слои 1–6 согласованы: репозитории, ветки/overlays, что автоматизируем **первым**. Код Terraform/Helm в этом слое **сейчас не пишем**.

## 7.2. Overlay Dev / Prod — смысл

**Overlay** — тонкий слой отличий: `resources.requests`, размер PVC, число реплик **там, где не кворум**.  

Не overlay: «в Dev другая картинка установки». Это нарушение паритета.

Для кворума в overlay **не** ставить `replicas: 2`.

## 7.3. Чего не делать сейчас

- Не создавать репозиторий и не писать Terraform «чтобы было».
- Не генерировать 36 Helm values до таблицы размещения.
- Не считать, что файл в `sample/` — IaC. Это конспект стенда.

Когда дойдёте сюда по-настоящему, в этой папке появятся: соглашение об именах каталогов, пример overlay на **одном** продукте (учебный), и только потом массовое наполнение.
